# 文件监测列表

入口：采集插件 → NTFS 文件变更日志 / 指定文件与可选运行时 → 详细 → 文件监测列表。两处编辑同一份列表，保存在当前历史数据库，默认空。每行一个本机文件完整路径，最多 100 个；允许尚不存在的文件，不支持目录递归、UNC、通配符和备用数据流路径。

空列表不读取 USN 卷日志、不采集文件元数据，也不保存 Security 文件访问/权限审计和 Sysmon 明确的文件事件。其他系统、软件、进程事件按各自插件正常采集；这些事件可能包含相关软件文件路径，不能将它们等同于文件监测记录。

文件元数据采集忽略旧 collector-options.json 的 file_roots，按列表逐项读取属性、时间、Owner/DACL、ADS 元数据及可选哈希。旧配置中的便携软件、进程模块和可选运行时功能仍独立工作。文件缺失返回明确的不存在观察，读取失败报告缺口，目录不会被扫描。

USN 仅处理列表涉及的固定 NTFS 卷，按当前父目录文件 ID 和精确文件名匹配，保存命中的记录。增加、移除或清空列表会更新范围版本，下一轮建立新的 USN 起点，不把旧的整卷游标当成当前列表覆盖。新列表首次读取之前的变化不作完整追溯承诺。重命名出列表停止跟踪新路径；父目录移动、路径不可读和日志覆盖可能形成缺口。不会保存文件正文。

保存后旧范围尚未提交的批次会被拒收；已保存历史不删除。列表编辑不会启用已停用插件，也不会改变采集周期。可分别手动触发 USN 和指定文件元数据插件。

验证包括空列表、旧 file_roots 不再生效、精确文件隔离、同名异目录排除、缺失文件、目录拒绝、ACL/哈希、列表版本与清空、Security/Sysmon 文件事件过滤，以及非文件事件保留。
