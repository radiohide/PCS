# 采集完整性专项审计（2026-09-11）

> 后续要求已调整：本文的“敏感值隐去/正文排除/截断”属于第一版审计过程，现已改为**原值加密保存、默认 ******、系统配置可显示明文**。完整事件 XML 与长字段原值亦保留。最新生效策略与剩余硬边界见 [敏感字段与完整原始证据](sensitive-display.md)。以下统计仍是第一轮验证，不能当作新加密版本的性能指标。

## 结论

**仍不能称为“所有系统信息完整采集”。** 66 个逻辑采集器的逐项实现/未实现边界见 [覆盖验收表](collector-coverage.md)。本次检查覆盖 11 个快照任务、事件日志、USN；UI 目录有 133 项说明（并非 133 个独立进程）。不能把 `snapshot.complete=true` 理解为“该领域所有活动均已采到”，它只确认此次已声明范围的对象枚举完成。

本次修复主动丢弃的证据、3 个实际漏采缺陷，并增加固定解释和字段缺口展示。没有启用系统审计、改变注册表/服务配置、安装 Hyper-V、读取密码库、保存剪贴板/文档/私钥内容，也没有扩大用户指定的目录范围。

## 主动丢弃信息：改动与边界

| 来源 | 之前的问题 | 本次处理 | 仍未完成/不能保证 |
|---|---|---|---|
| 23 个事件通道、EVTX | 不读正文；仅白名单 EventData，忽略匿名字段和 UserData | 首次读取自动 FormatDescription；保存 System、未知/匿名/重复 EventData 和 UserData 叶字段；缺失/失败/脱敏/截断状态 | 旧库记录不会被虚构补全；消息资源不存在时仍无法获取正文；未解析所有 XML 扩展结构 |
| 事件批次 | 添加正文可能撑破 1 MiB | 按 UTF-8 编码大小分批，未装入批次的记录不推进断点；单字段/正文限制显式记录 | 不承诺无限长度；单条超过硬限制仍保留断点并报缺口 |
| 领域注册表配置 | 白名单外一律摘要 | 指定键内保留值、类型，敏感字段脱敏；标出深度外子键数量 | 不扫描整个注册表，不绕过访问控制，不跟踪实时操作 |
| CIM 领域采集 | Fields 只留下选定属性 | 除用于展示的重点字段，保留来源 CIM 属性和嵌套结构，经脱敏 | 非 CIM 接口仍按各自字段清单；嵌套深度上限 8 |
| 服务、进程、Run/RunOnce | 命令缺失或只有摘要 | 保存命令/命令行，过滤常见秘密参数；进程未返回命令行时说明原因 | 参数中的所有未知秘密格式不能由模式过滤保证识别；短进程、令牌权限仍未完整覆盖 |
| 计划任务 | 参数摘要、触发器/条件字段不全 | 保存 Actions、Triggers、Settings、Principal 的 CIM 属性，以及运行结果 | 不保证任务执行事件通道已经启用；无权限任务不可读 |
| WMI 持久启动项 | 查询和命令只有摘要 | 保存查询、消费器命令、绑定及来源属性 | ScriptText 正文仍排除；不执行收集到的脚本 |
| Shell/COM | 命令和二进制登记值只有摘要 | 保存脱敏命令；二进制配置用可恢复 Base64 表示 | 不代表扩展已加载；签名信任未验证；仍有有限扫描深度 |
| 桌面/开始菜单快捷方式 | 参数摘要；目录链接使整个来源失败 | 保存参数、说明、窗口样式；目录链接作为边界对象记录，不进入目标 | 启动文件夹独立来源仍以文件元数据为主；目录链接目标不在当前范围 |
| 本机软件登记 | 只有 5 个字符串字段 | 枚举键内全部值并保存类型、字符串/多字符串/整数/二进制，敏感值明确隐去；读取失败输出缺口 | 其他用户和便携软件需各自范围；带秘密标记的整个文本可能被保护性隐去 |
| Chrome/Edge 扩展 | 只有部分 manifest 字段，无登记状态 | 增加说明、主机/可选权限，以及 Preferences/Secure Preferences 中扩展 state、disable_reasons、登记路径 | 登记代码不保证实时激活；不保存整个浏览器偏好文件、访问历史或令牌 |
| 指定文件范围 | 未生成哈希时原因不明 | 明确关闭、非文件、重解析点、超限、已采集等状态；配置显示 Docker/Mihomo 是否启用 | SACL、内容版本、签名信任与实时事件仍有边界 |

## 修复的实际漏采缺陷

1. 更新历史同一更新、时间和操作可能重复，原 ID 冲突让整个来源失败。现在追加结果代码和同一身份的出现序号，不丢弃重复条目。本机复测保存 884 条。
2. Windows PowerShell 5.1 的 JSON 数组枚举差异，使通道能力检查产生一个数组身份。修复后得到 23 个独立通道结果。
3. 开始菜单的目录链接不再导致整个快捷方式来源失败。复测得到 293 个条目（含明确标记的链接边界对象，不是 293 个实际快捷方式）。

Application 首批 128 条真实记录：5 条返回原始说明，123 条 FormatDescription 未返回正文，整批正常输出（182,204 字节）。这是一个历史样本，不是全通道正文可用率。不能为了“完整率”替没有消息资源的事件编造说明。

本机软件全登记值实测：64 位视图 171 项 / 299,978 字节；32 位视图 398 项 / 707,208 字节，均未超过 1 MiB。基础采集服务、任务、账户、组、卷、网卡/IP、硬件和 Shell/登录启动来源返回快照，无 Gap。真实事件连续两个批次各 128 条，序号递增到 2，交集为 0。

## 固定解释

`evidence-rules-2` 在界面按来源领域、事件级别、证据字段和采集状态生成固定解释，独立于原始证据。通用解释不臆测厂商 ID 的含义；例如 incredibuild/88 只能确认它报告了什么级别、有哪些正文/字段，不能把 88 通用映射成许可证错误。旧记录明确显示“当时未保存”，不会被新规则假装补全。

详情显示来源原始说明、采集边界、脱敏/截断/未解析信息；USN 常见原因位翻译为操作类型。密码、令牌、私钥字段和脚本正文按策略排除。模式脱敏不是完整 DLP，原始命令/路径仍属于本机敏感运行数据；不要将历史数据库上传到 GitHub。
