# 采集缺口按状态变化入库

`Gap` 的请求编号只负责消息重放校验，不再决定是否生成时间线记录。持久化 `coverage_state` 按来源和原始原因保存当前缺口、首次发现、最近检查时间和累计观察次数。

- 新的缺口原因：生成一次 `coverage.gap`。
- 同一原因持续存在：更新检查时间和次数，不新增时间线记录。
- 同一来源一次采集调用的全部消息成功入库、且没有该来源的 Gap：生成一次 `coverage.recovered` 并关闭该来源现存缺口。
- 恢复后再次出现：重新生成缺口记录。
- 来源可以同时存在多个缺口原因；一个成功分片不能清除同次调用中其他分片的失败。

恢复表示来源现在能够成功采集，不表示过去缺失的信息已补齐。`coverage.log_reset` 等有独立事件身份的真实断点事件继续保留，不按此规则吞并。

去重状态独立于可滚动删除的历史记录，重启后保持。升级前已经写入的重复历史不做批量删除；首次启用状态表时会建立一次当前缺口状态。底层请求回执仍保留，用于检测相同请求编号被篡改或冲突重放。最近采集结果依然报告当前缺口，时间线的去重不会把采集健康状态改成成功。
