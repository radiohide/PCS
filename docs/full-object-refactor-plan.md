## 1. 全量重构的定义

将 PCScope 的数据组织、查询和界面统一为：

**对象类别 → 对象类型 → 对象实例 → 属性和状态 / 发生的动作 / 证据和来源 / 采集状态。**

范围覆盖所有现有采集项和事件来源，每一项都必须有明确去向。开发期间允许按模块和类型分批完成；正式默认界面一次切换到新模型，不长期混用“来源对象”和“真实对象”两套列表。

“全量”指现有功能和来源的完整迁移，不表示一次新增 Windows 所有可能对象的采集能力。模型目录中的类型若没有现有来源，明确标记“尚未接入来源”，不以空列表冒充已采集完成。

完成后的产品应能回答：这个对象是什么、最近观察状态如何、发生过什么、每个结论有什么证据、哪些信息没有采到。

## 3. 当前结构的主要调整

| 当前结构 | 目标结构 |
| --- | --- |
| 采集项兼任对象类型 | 对象类型和来源采集项独立，用映射连接 |
| `(source,scope,id)` 标识对象 | PCScope 实例 ID + 有时间范围的来源身份映射 |
| 事件 object_id 常是通道/提供者/事件 ID | 保留源标识，另解析真实目标对象或标记未归属 |
| 来源 JSON 最新快照 | 逐字段观察事实、来源引用与可重建最新投影 |
| 原始事件兼任动作 | 来源证据与对象动作分开，允许多证据支撑同一动作 |
| 插件健康与对象列表分散 | 对象详情汇总其各来源的配置、可用性、新鲜度和历史覆盖 |
| UI 专属目录被后端用于分类 | 中立模型目录统一生成前后端声明 |
| seq 作为时间线分页顺序 | 明确发生/观察/入库时间，稳定游标支持所选顺序 |

读取接口、原始证据获取、加密、进程隔离等已有可靠代码可以复用。需要重构的是它们周围的契约与数据流，不要求为了“全量”而替换每一行代码。

              ↓

              ↓

## 5. 数据契约设计任务

在实施存储和界面前，先冻结以下最小契约，后续扩展使用显式版本。

| 实体 | 核心信息 |
| --- | --- |
| TypeDefinition | 类别、类型 ID、关键字段、身份策略、生命周期策略、支持动作 |
| ObjectInstance | 内部 ID、机器与安装作用域、类型、原生身份、实例代际、身份状态 |
| SourceDefinition | 插件、采集项、接口/渠道、权限、范围与能力 |
| Evidence | 来源记录身份、源时间、观察时间、入库时间、原始材料定位、解析版本 |
| Observation | 对象、采集范围、字段值、读取完整性、证据引用 |
| FieldFact | 字段 ID、类型和值、值状态、有效时间/观察时间、推导方式 |
| ObjectAction | 动作类型、目标对象、结果、前后值、时间精度、来源提供的执行身份 |
| CoverageState | 配置、最近读取结果、新鲜度、历史覆盖，按来源与范围记录 |
| ProjectionState | 规则版本、游标、水位、错误、待处理数量与完成状态 |

必须统一的规则：

1. `source` 与采集分片不能成为跨来源对象身份的组成部分；用户、注册表视图等有业务意义的作用域由类型决定。
2. 首次观察不是创建；本次未发现不是确认删除；PID 相同不是同一进程。
3. 配置变动、运行状态变化、明确操作和执行结果分开。
4. 时间支持精确发生时间、变化区间、仅观察时间；不使用虚构精度。
5. 明确缺失、不可读、不适用、冲突、脱敏和证据已清理的差别。
6. 一个字段或动作可以有多份证据；无法确定同次动作时不合并。
7. 来源原始材料不随解释规则升级改写。
8. 无法解析目标对象的日志仍保留并可检索，不制造虚假实例。

当前协议 v1 的 Event/Item 有严格字段校验。先由兼容适配器接收旧输出；确需新增信息时制定 v2 和能力协商，不能无协商给旧消息增加字段。旧插件在过渡期可运行，但其能力限制必须明确显示。

## 6. 全量来源映射工作

### 6.1 映射清单

为每个现有采集项生成一条或多条映射声明，至少记录：

- 来源与采集项 ID、输出结构版本。
- 对象类别、类型或非对象用途。
- 身份字段及作用域、缺失时的处理。
- 配置字段、运行状态字段及时间依据。
- 支持的动作、结果和证据定位。
- 读取完整性、权限和过滤范围。
- 固定样例、验收状态及未支持原因。

目录自动核对映射覆盖，新增采集项没有处理声明时检查失败。映射结论可以是对象观察、动作证据、采集状态、运行采样或明确未归属，不能一律包装成对象。

### 6.2 十二类交付矩阵

| 类别 | 核心工作 | 必须验证的边界 |
| --- | --- | --- |
| 账户与身份 | SID、组、权限、配置文件归一 | 改名、同名不同 SID、用户与机器范围 |
| 软件与组件 | 各类安装登记与组件身份 | 同名多版本、不同用户、32/64 位登记、卸载与重装 |
| 运行实例 | 进程、模块加载、会话实例 | PID/会话标识复用、创建时间缺失、短生命周期 |
| 自动执行入口 | 服务、任务、启动登记、WMI 订阅 | 完整路径、状态与配置区别、删除重建、多来源 |
| 系统扩展与关联 | COM、Shell、文件关联和浏览器扩展 | 注册表视图、用户覆盖、注册存在不代表实际加载 |
| 文件与访问控制 | 名单内文件、目录、ACL、ADS | 改名、路径复用、身份受限、名单变化不等于删除 |
| 策略与配置 | 有范围的配置对象和字段 | 策略来源不同、未设置与关闭不同、嵌套字段差异 |
| 网络与远程访问 | 地址、规则、连接、共享等类型拆分 | 动态端点复用、接口身份、配置与瞬时连接区别 |
| 安全与信任 | 证书登记、防护、排除项、密钥证据 | 存储区差异、密钥日志不等于完整清单、敏感显示 |
| 硬件与驱动 | 设备、驱动、磁盘与卷身份 | 盘符变化、设备重新接入、驱动服务与普通服务区分 |
| 虚拟环境 | 虚拟机、WSL、容器及配置 | 引擎不可用、名称复用、运行状态与定义对象区别 |
| 桌面与应用集成 | 打印、输入法、快捷方式、编辑器扩展和同步 | 用户范围、临时作业、登记与实际使用区别 |

所有类别在统一验收前完成现有来源映射，不以一个计划任务样例通过代替全量完成。计划任务可以作为开发中的贯通样例，但不作为缩小交付范围的理由。

## 7. 存储重构

### 7.1 新旧职责

旧 records/snapshots 先继续作为来源证据和历史输入。新增对象实例、来源绑定、字段事实、动作、证据引用、覆盖状态与当前投影；不原地改写旧 source/scope/id 的含义。

逐步拆分 storage/lib.rs 中入库、对象投影、检索和容量维护职责。新对象查询不再运行按 source 字符串推断类别的 CASE。

### 7.2 事务与恢复

- 原始批次持久化与待投影工作登记同事务提交；断点只在来源批次可靠保存后推进。
- 投影异步、小批次、幂等执行；失败隔离到批次或适配器，原始采集继续。
- 数据库 schema 版本、来源结构版本、解析规则版本分别管理。
- 当前投影可按规则版本重建；重建不生成真实系统动作。
- 原始证据已清理时，保留事实是否还能重建必须明确标识，不假装可无限重放。

### 7.3 容量控制

新表、索引、队列、WAL 和当前投影均纳入已有容量预算。避免复制大段 XML，避免对每次不变观察永久追加所有字段版本。

清理采用明确依赖顺序：历史动作与事实版本、证据引用状态、原始证据、无保留价值的历史实例。当前状态保留必要的来源和观察摘要；详细证据被清理时可见标记。

不能因证据引用存在就永久锁住所有旧数据。最小当前状态超出预算时报告容量不足，不静默删除必要状态。无限模式不执行自动历史删除。

## 8. 前端全页面重构

| 页面 | 新行为 |
| --- | --- |
| 系统总览 | 对象类别/类型数量、近期动作、来源覆盖摘要；对象数与证据数分开 |
| 系统对象 | 类别→类型→实例筛选，作用域、存在状态、身份状态、采集状态可筛选 |
| 对象详情 | 当前行展开；关键属性与状态、动作历史、证据和来源、采集状态 |
| 时间线 | 按真实对象与动作展示；来源/插件作为独立筛选；未归属证据和采集活动明确标识 |
| 状态对比 | 对相同实例的观察版本比较；不同来源缺字段不解释成删除；生命周期不同不默认直接比较 |
| 采集插件 | 保留所有开关、周期和手动触发；增加“提供哪些对象、字段和动作证据”的映射说明 |
| 采集健康 | 统一来源范围、读取能力、补采与对象投影进度；采集失败和解析失败分开 |
| 系统配置 | 保留现有四页签；模型迁移状态按需链接，不把内部技术参数铺满设置页 |

显示名称、类型、动作 ID 和筛选选项由统一目录提供。通用兜底必须显示来源材料、未解析原因和可用字段，不退回只有“其他事件”且无内容。

原始数据入口区分“归一对象数据”和“来源原始证据”；复制遵守敏感显示设置。对象详情不一次加载全部历史或全部 XML。

## 10. 历史迁移与整体切换

> **〔2026-09-12 修订：本节 10.1 已作废；10.2、10.3 保留。〕** 用户决定不迁移旧数据，旧库留在原地、永不投影。10.1 的前提（保留当前可运行版本、把旧历史迁入新模型）随之消失。10.2 的切换门槛与 10.3 的回退方案**与迁移无关**：切换门槛保护的是「用户配置逐项对账」和「切换期缺口准确记录」，回退方案里「不得假设旧二进制能够打开新 schema」是回退边界而非迁移要求——两者在迁移作废后依然成立并须继续遵守。见 §19。

### 10.1 开发和验证期

> **〔2026-09-12：本小节已作废，原文保留供对照。〕**

保留当前可运行版本。通过功能标记选择新投影和新查询，默认界面在正式切换前保持稳定。新旧对照比较的是证据覆盖和状态事实，不要求对象数量相同，因为新模型会合并多来源重复项。

迁移使用有界批次和持久化游标。记录迁移起始水位，之后新采集数据继续入库并登记待处理工作，最终追平。

保留策略可能在迁移期间删除旧证据：协调正在读取的短批次，已被清理的待处理记录明确登记并推进。禁止为迁移无限固定所有历史。

### 10.2 切换门槛

所有类型适配与页面验收通过后，先记录最终水位并追平，再切换默认查询和前端。切换期间展示准确进度；若必须短暂协调写事务，不停止来源读取而不记录缺口。

用户的插件开关、周期、文件名单、权限模式、隐私、保留策略必须逐项对账一致。不能借重构恢复默认值。

### 10.3 回退方案

> **〔2026-09-12：本小节不随迁移作废，继续有效。〕** 下一段「不得假设旧二进制能够打开新 schema」在迁移作废后**更加**关键：新构建首次打开旧库即原地升级到 v8，此后旧二进制拒绝该库（实测 stderr 为 `Error: database version is newer than this application`，退出码 1）。这条单向门已实测复现，见 S32 记录。

优先回退读路径并暂停新投影，旧来源记录继续接收。不得假设旧二进制能够打开新 schema，应明确可兼容版本。

需要数据库备份时使用一致性备份接口，预检空间和备份保留规则；不能运行中只复制主 DB 文件而漏掉 WAL。

不能简单恢复旧备份覆盖上线后的新证据。若使用备份恢复，需保留并核对切换后新增来源材料，制定重放方案；无法无损恢复时明确报告边界。

## 11. 关键风险与处理

| 风险 | 处理要求 |
| --- | --- |
| 名称相同导致对象误合并 | 类型身份键、作用域和生命周期规则；信息不足保持暂定 |
| 删除重建被视为同一实例 | 保留来源绑定时间范围与实例代际，不仅按路径匹配 |
| 采集分片改变制造新对象 | 分离采集范围和身份范围 |
| 时间接近被视为同次动作 | 只有明确规则支持才归并，保留证据和阶段 |
| 原始材料或敏感信息重复膨胀 | 引用证据、统一加密与显示处理，不在摘要复制秘密 |
| 回补旧数据覆盖新状态 | 事实时间及字段来源规则，不以入库顺序决定最新 |
| 投影拖慢采集或查询 | 有界队列、短事务、只读查询隔离、按需详情 |
| 停用项目被当成对象消失 | 继承现有停用保护，逐来源覆盖而非空快照 |
| 证据清理留下悬空结论 | 最小来源摘要、保留状态标记、引用清理规则 |
| 新模型全量迁移遗漏少见来源 | 自动映射清单覆盖检查与逐类型固定样例 |

**前置：** S04。

**实施内容：** 接收现有 v1 消息；为源事件和快照项建立稳定证据定位；原始入库、去重和投影任务登记在同一事务中完成；保留源记录身份、时间、加密材料与读取问题。

**交付：** 兼容适配器、证据查询基础接口、事务验证。

**验收：** 重放相同批次不重复产生证据和任务；事务失败不推进断点；旧插件无需立即更新即可运行；XML 等大内容不复制到每个字段；日志重置后记录 ID 复用不碰撞；敏感数据不因新入口绕过保护。

**前置：** S04、S05。

**实施内容：** 按类型规则生成或解析实例；来源绑定带有效范围；支持已确认、暂定和歧义状态；记录首次/最后观察、未发现、确认删除/结束及新实例代际。

**交付：** 身份模块、生命周期状态机、边界样例。

**验收：** 同一实例多个来源可归一；同名不同作用域不合并；PID 复用、任务删除重建、用户改名按规则处理；缺少创建时间时不虚构；不完整快照和名单变化不能确认删除；重复处理不新增实例。

### S07：实现事实、动作和当前投影

**前置：** S05、S06。

**实施内容：** 保存字段值与证据引用；按来源能力和事实时间选择当前值；保留冲突；生成配置差异、状态变化及明确动作；实现多证据引用、阶段区分和规则版本重建。

**交付：** 投影引擎、动作生成规则、字段选择策略。

**验收：** 旧日志晚到不回退新状态；快照变化显示时间区间；未变化观察不重复生成变化动作；开始和结束不误去重；同时间不同结果不被静默覆盖；规则重建不制造真实系统动作；同一证据处理两次结果一致。

### S08：实现覆盖状态与预算清理

**前置：** S05–S07。

**实施内容：** 汇总来源开关、最近读取结果、新鲜度、历史覆盖；区别采集失败和解析失败；将全部新表、队列、索引接入容量预算；定义证据清理后状态及引用处理。

**交付：** 覆盖查询、容量维护、清理一致性检查。

**验收：** 单项停用保留旧字段值和真实观察时间；恢复不声称补齐缺失历史；相同来源异常不逐对象重复写入；清理后无无法解释的悬空引用；无限模式不自动删除；必要当前状态超额时明确报错；投影队列积压不无限占盘。

## 15. 全类型适配步骤

### 15.1 每类共同交付与验收

S09–S20 都依赖 S03、S05–S08。每步必须完成对应类别在 S01 清单中的全部来源，不只是下面列出的代表类型。

**共同实施：** 核查真实输出结构 → 实现身份映射 → 映射配置/状态字段 → 解析可确认动作 → 绑定证据与覆盖 → 提供类型摘要与解释声明。

**共同交付：** 来源适配器、目录映射、至少一份每种实际输出结构的样例、缺字段/歧义样例、该类别覆盖报告。

**共同验收：** 来源逐项映射无遗漏；身份和时间符合契约；每个关键字段和动作能定位证据；未知不填猜测值；重复回放结果一致；源数据和加密材料不改写。以下各步再增加专项检查。

### S09：账户与身份

**内容：** 用户、组、成员登记、权限分配和用户配置文件按 SID 与作用域归一；成员变化展示为登记变化或组属性动作。

**专项验收：** 用户改名不新建实例；同名不同 SID 分开；机器级组不会因采集运行账户变化重复生成；拒绝读取某组成员不表示清空成员；来源未提供建立时间则为空。

### S10：软件与组件

**内容：** 软件登记、AppX、预配包、运行时、可选组件、更新与便携登记分别建类型，保留各自原生标识与范围；部署记录作为动作证据处理。

**专项验收：** 同名多版本和不同用户登记不误合并；更新历史不冒充当前安装清单；部署开始不意味着安装成功；路径文件登记不自动证明程序已经安装；卸载重装缺少证据时标记生命周期不确定。

### S11：运行实例

**内容：** 进程、模块加载实例、登录与终端会话标准化；CPU/内存作为运行状态采样；用创建时间、启动作用域等区分复用标识。

**专项验收：** 同 PID 不同创建时间为不同实例；只有 PID 的旧日志保持暂定/未归属；模块身份包含加载上下文，不能只按 DLL 名归一；采样间隔内消失的短进程不宣称已完整观察；会话 ID 复用不串联历史。

### S12：自动执行入口

**内容：** 服务、任务、启动登记、登录初始化项、WMI 永久订阅和 IFEO 等配置适配；统一任务基础配置、详情与可靠日志；服务配置和运行状态分别建字段。

**专项验收：** 同任务完整路径的多个来源归一；不同文件夹同名任务不合并；任务下次执行时间变化不生成“人工修改”；运行开始/结束保留阶段；源命令、运行账户可追溯；WMI 订阅的过滤器、消费者与绑定登记各自保留真实身份，不提前构建通用关系图谱。

### S13：系统扩展与关联

**内容：** Shell 扩展、COM、文件关联、命名空间与浏览器扩展按登记范围、视图和原生 ID 识别；关联文件信息作为有来源的字段。

**专项验收：** 同 CLSID 的用户/机器、32/64 位登记不被无条件合并；注册存在不解释为已经调用或加载；扩展文件不可读保留登记对象及读取问题；文件关联与其目标命令字段能追溯来源。

### S14：文件与访问控制

**内容：** 名单内文件/目录、ACL、ADS 及文件变化证据归一；优先使用可靠文件身份，只有路径时记录限制；区分删除、移出监控范围和读取失败。
