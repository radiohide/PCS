## 配置与命令

`dist/dev/collector-options.json` 中 file_roots、portable_roots、module_process_names 默认空列表，docker_metadata 和 hash_files 默认 false。构建打包保留已有配置。只支持显式本地路径；不跟随重解析点，扫描达到上限将整份来源标记失败并保留旧状态。配置变更建立独立 scope，旧范围不会被误判为删除。

EVTX：`pcscope-cli.exe import-evtx <database-path> <local.evtx>`。只导入选定文件的允许字段与摘要；原始 EVTX 不自动纳入历史容量。CLI 是开发工具，不能与正在运行的服务共用数据库写入。

技术依据：[LSA 权利枚举](https://learn.microsoft.com/en-us/windows/win32/secmgmt/managing-account-permissions)、[防火墙关联过滤器](https://learn.microsoft.com/en-us/powershell/module/netsecurity/get-netfirewallportfilter?view=windowsserver2025-ps)、[Windows 安全审计事件](https://www.microsoft.com/en-us/download/details.aspx?id=50034)。

## USN 与最新整体验证

原生 Rust USN 插件每个固定 NTFS 盘符每轮最多 8 批，每批最多读取 16 KiB 原始日志；记录卷 GUID、日志 ID、文件/父文件 ID、名称、原因位和来源时间。日志禁用或权限不足不尝试创建日志。未知记录版本/无效结构拒绝推进该批断点，丢失区间数量允许未知。当前不能将父文件 ID 还原为完整路径，也不覆盖无盘符卷、远程盘或非 NTFS 文件系统。排除自身 history.db/WAL/SHM 的卷序列号及文件 ID；其他文件不按同名误排除。已有残留旧文件 ID 可能仍被观察到。

USN 本机 C/D/E 三卷都返回 Access denied，属于权限失败，不是成功采到零条。V2/V3 中文名、坏记录、未知版本、断点覆盖/日志切换/回退的 3 项测试通过；存储 9 项测试通过，共 12 项 Rust 测试。整体 IPC/采集/缺口/重复实例/正常退出再测通过，数据库当前对象 15,597，保留记录 36,256，快照 2,640（数量随运行变化）。

Mihomo 适配器只访问显式启用的 http://127.0.0.1:<mihomo_port>；可从 PCSCOPE_MIHOMO_TOKEN 接收已有 API 凭据，凭据不写入历史。不会自动发现/导出订阅秘密。Docker/Mihomo 默认不开启。[Mihomo API](https://wiki.metacubex.one/en/api/)；[Docker 只读清单格式](https://docs.docker.com/reference/cli/docker/container/ls)。
