# PCScope 对象模型重构计划

日期：2026-09-11

状态：代码核查后的实施计划，尚未执行重构。

目标模型：[对象监控模型设计](object-model.md)。核查基于 `a2311a4` 的应用代码及随后新增的模型文档。本文不修改现有数据库或采集配置。

## 1. 结论

当前程序以“来源快照 + 来源事件”组织数据，目标模型以“对象类别 → 对象类型 → 对象实例”组织数据。主要工作是新增对象身份、事实与证据映射层，并将查询和展示切换到该层；不是仅给现有采集项改名称。

采用增量方案：**保留采集和原始记录 → 新增归一投影 → 计划任务试点 → 逐类扩展 → 切换默认展示**。

现有采集器、断点、单项开关、隐私保护和查询隔离继续使用。对象之间的关系图谱不纳入本次重构。

## 2. 代码核查与差距

### 2.1 分类与对象身份

| 核查项 | 当前实现与依据 | 与目标不符之处 | 处理方式 |
| --- | --- | --- | --- |
| 类别与类型 | `collection-catalog.json` 定义采集项；`collection.rs` 按 source、ID 包含词、事件规则分类 | 采集项兼任展示类型，缺少独立对象类型目录 | 新增中立目录，保留采集目录作为来源维度 |
| 系统对象主键 | `storage/src/lib.rs`：`objects` 主键为 `(source,scope,id)` | 同一实体来自不同来源时天然分开 | 新增全局对象实例 ID 与来源身份映射 |
| scope | `collect-domain.ps1` 包含 machine/user/schema/context/shard | 采集分片和协议版本混入作用域；不能直接作为业务身份 | 区分身份作用域与采集范围，分片不参与对象身份 |
| 事件对象标识 | 原生事件读取器 `Program.cs` 使用 `channel/provider/eventId` 作为 `object_id` | 这是事件类型标识，不能代表具体任务、进程或密钥 | 原值原样保留；新增解析后的目标对象引用 |
| 跨来源匹配 | `related.rs` 提供任务路径附近、PID 与创建时间附近的候选事件 | 候选检索不是统一对象身份，也不是同次动作确认 | 保留候选功能，禁止直接把时间邻近候选转换为已确认映射 |
| 安装与生命周期 | 当前对象表没有安装实例、incarnation、身份状态字段 | 无法通用表达重装、删除重建及标识复用 | 增加身份模型；旧数据缺失部分明确标记未知 |

机器级对象不应仅因换了运行用户就重复生成；用户级对象必须保留用户 SID。32/64 位视图对 COM 等类型可能具有身份意义，不能统一删除。具体作用域由类型适配器决定。

### 2.2 属性、状态与生命周期

| 核查项 | 当前实现与依据 | 差距 | 处理方式 |
| --- | --- | --- | --- |
| 字段结构 | `contracts::Item` 只有 `id` 和任意 JSON `data` | 无统一字段 ID、类型、来源引用和缺失原因 | 在归一层定义字段事实，不强迫旧插件立即修改输出 |
| 最近状态 | `objects.data` 保存每个来源最近快照；`object_times` 保存 changed_at/seen_at | 来源级最新值不是跨来源字段级最新值 | 建立字段候选事实和可重建当前投影 |
| 状态变化 | 对 JSON 等价性比较后生成 `object.changed` | 配置变化、运行状态变化需要进一步区分 | 类型定义字段性质与变化语义，原始差异保留 |
| 变化时间 | 快照事件 occurred_at 使用 observed_at，明细保留 before_observed_at | 已有变化区间基础，但没有统一时间精度契约 | 增加 exact/interval/observation 时间模型 |
| 对象消失 | 完整快照缺失时生成 `object.no_longer_observed`，从当前 objects/object_times 移除 | 用词已避免“确认删除”，但缺少可直接查询的历史实例生命周期 | 保留历史实例壳及状态，不能把不再发现直接转成删除 |
| 首次发现 | 已区分 baseline.observed 与 object.first_seen | 可复用，但还没有独立 first_observed_at/created_at 模型 | 保留首次观察语义，仅凭可靠来源填写创建时间 |

已有“不完整快照拒绝更新”和“关闭子项保留旧值及 seen_at”的行为是正确基础，必须保留。

### 2.3 动作与证据

| 核查项 | 当前实现与依据 | 差距 | 处理方式 |
| --- | --- | --- | --- |
| 原始日志 | `records.data` 保留 fields、system、正文、加密 XML 等 | 证据充足，但与动作、对象引用未独立建模 | 优先以现有记录为证据载体，避免复制大段原始内容 |
| 快照证据 | `snapshots` 保存批次，records 保存 before/after | 尚无统一证据定位接口与字段级引用 | 增加引用目录，定位批次及批次中的源对象 |
| 动作语义 | event-items、event-semantics、event-presentation 提供分类与解释 | 解释存在，但不是对象动作存储模型 | 提取稳定语义映射，复用前端模板，不把所有解释重写为 Rust |
| 去重 | event_ids、batch_heads、snapshot_receipts 等保证来源重放幂等 | 幂等不等于跨来源同次动作归并 | 保留已有去重；新增谨慎的证据归并规则 |
| 多份证据 | 单条记录展示及关联候选为主 | 一个对象字段或动作不能通用引用多份证据 | 增加事实/动作证据映射 |
| 冲突与晚到 | 未有通用字段冲突选择和解析版本投影 | 旧日志回补、来源冲突可能被简单处理为新值 | 投影按事实时间与类型规则选值，保留冲突 |

### 2.4 采集状态、查询与界面

| 核查项 | 当前实现与依据 | 差距 | 处理方式 |
| --- | --- | --- | --- |
| 覆盖状态 | coverage.rs 保存来源缺口转换；monitoring、插件配置提供权限与开关信息 | 信息分散，缺少对象相关的逐来源摘要 | 在现有状态之上按来源/范围汇总，不复制成大量对象缺口事件 |
| 单项控制 | item_controls.rs 持久化开关，过滤停用内容，推进规则已明确 | 控制的是采集项，不等于对象或字段 | 保留采集项控制语义，建立“该类型由哪些采集项支撑”的说明 |
| 对象查询 | search_objects 从旧 objects 表计算 item/category，按来源字符串推导部分类别 | 缺少 type_id、生命周期、身份状态和多来源过滤 | 新增对象查询接口和物化索引 |
| 时间线 | record_search 按记录 seq 分页，分类来自采集目录 | 不是对象动作时间线；seq 顺序也是入库顺序 | 新增动作查询，显式选择发生时间/观察时间，使用稳定复合游标 |
| 可读详情 | 当前行展开、人类说明/原始数据、复制、前后并排比较已经存在 | 缺少统一对象详情和四个信息分区 | 保留交互框架，替换数据输入和增加证据定位 |
| 保留策略 | retention_units 清理 records/snapshots，现有元数据另行维护 | 新表若不参与清理会导致悬空引用与持续膨胀 | 新模型第一次落库即接入保留预算和回收规则 |

## 3. 可以直接复用的能力

- Rust 服务、插件进程隔离、定时及已有事件采集调度。
- 协议 v1 的来源快照和事件批次，现有读取接口、日志渠道和权限检测。
- 原始证据加密、字段遮罩、剪贴板复制时遵循显示策略。
- 事件和批次幂等、断点恢复、完整快照校验。
- 采集缺口首次报告与恢复报告、单项开关与停用保留状态。
- 只读查询连接、WAL、查询超时/并发限制和已有窄索引思路。
- 事件动作解释、原始数据详情、差异高亮、同步阅读、自身活动识别。
- 黑白主题、直角控件、前端自动刷新/暂停、系统配置页签。

这些能力要做适配和回归验证，不应无理由推倒重写。

## 4. 目标架构与模块边界

```text
现有插件输出（协议 v1）
    ↓
现有校验、去重、原始入库、断点提交
    ↓ 同事务登记持久化投影工作
来源适配 → 对象身份解析 → 字段事实/动作及证据引用
    ↓
对象当前投影、对象检索索引、对象动作索引
    ↓
新的 IPC 查询 → 系统对象 / 时间线 / 证据详情
```

建议新增模块：

| 模块 | 责任 |
| --- | --- |
| 中立对象类型目录 | 类别、类型、字段、动作及来源映射声明；不放在 UI 专属目录中 |
| `object_identity` | 作用域规范化、身份解析、生命周期与歧义处理 |
| `object_adapters` | 按来源结构解释对象候选、字段、时间和动作 |
| `object_projection` | 幂等构建对象与当前事实；跟踪解析版本及进度 |
| `object_query` | 类型列表、对象列表、对象详情、对象动作、证据定位 |
| `object_retention` | 引用一致性、失效证据标记、对象历史回收与预算 |

模块名为建议，落地时按代码规模选择独立 crate 或 storage 子模块。避免继续把所有新增逻辑堆入 storage/lib.rs。

### 4.1 逻辑存储

新增实体建议包括 object_instances、source_object_bindings、evidence_refs、object_observations、object_facts、object_actions、fact_evidence、action_evidence、object_current、projection_jobs。

- source_object_bindings 需要保存适用时间或生命周期范围，同一个源标识可以先后绑定不同实例。
- evidence_refs 首先引用 records.seq 或 snapshot 的来源/范围/批次与项标识；不复制完整 XML 和快照到每条事实。
- 旧 source、scope、id 原样保留作为来源定位，不能原地改写成新对象身份。
- 当前投影与索引可重建；无法从清理后的证据重建的最小当前状态必须明确保留策略及来源摘要。
- 映射失败记录原因和规则版本，保留证据进入“未归属记录”，不能阻塞整个来源采集。

### 4.2 协议与查询兼容

第一轮不改插件协议版本。当前 Event/Item 使用 deny_unknown_fields，不能直接给所有插件输出增加新字段并期待旧后台接受。

优先后台解析现有 data；只有证据实际缺失时，再设计明确的协议版本或可兼容字段扩展。不得把采集范围分片当成完整实体身份。

新增独立 IPC 操作，保留 ObjectSearch/TimelineSearch 等旧操作至迁移验收后：

- 类型目录和覆盖状态。
- 实例列表及筛选。
- 实例详情与字段来源。
- 实例动作历史。
- 证据详情与保留状态。
- 投影构建状态。

## 5. 分阶段实施

### P0：映射清单与基线

交付：机器可读映射清单、类型目录草案、匿名化固定样例和性能基线。

逐项盘点现有采集目录，为每项标明：对象类型、配置/状态字段、动作证据、采集状态或暂不映射。一个采集项可映射多个类型。统计必须由目录生成，不能手工维护一个以后会失真的总数。

检查各来源身份字段和时间字段是否足够，标出“可确认”“暂定”“需补采字段”。特别核查任务完整路径、进程创建时间、用户 SID、文件身份及源 scope。

验收：每个现有采集项都有处理结论；未实现类型和未归属记录清单可见；记录现有列表和时间线查询延迟、库/WAL 大小及采集吞吐。

### P1：对象基础层与保留兼容

依赖 P0。交付：增量数据库迁移、身份接口、证据引用、投影队列及基础保留规则。

先添加新表，不删除或改名旧表。源入库与待投影登记同事务提交；投影在小批次中运行，每批持久化进度。失败可以重试，不回退采集断点。

投影幂等键必须包含来源证据身份与规则版本；不能只依赖请求时间。建立数据库 schema 版本与投影规则版本两个独立版本。

验收：中断重启不漏投影、不重复动作；证据被清理时返回明确状态；投影开关关闭后旧页面仍能正常查询。

### P2：计划任务端到端试点

依赖 P1。交付：第一个符合完整模型的对象类型。

输入包括 `pcscope.startup.tasks`、`pcscope.startup.task-details`、Security 中相关任务审计、TaskScheduler/Operational 中可定位任务的事件。实际字段映射以采集结构和样例核查为准，不假设每条日志都有完整路径或操作者。

处理：

1. 两个快照来源按明确的机器安装作用域和完整任务路径归一。
2. 配置和运行状态字段分组，保留逐字段来源与观察时间。
3. 运行日志与修改审计定位到任务实例；删除重建边界不确定则标注暂定。
4. 下次运行时间变化归为状态变化，不直接生成“用户修改任务”。
5. 多份证据支持同一动作需明确规则；开始和结束仍是不同阶段。

验收：一个任务多来源只显示一个已确认实例；可以看配置、状态、动作、证据和采集状态；缺失审计时显示变化区间，不伪造发起人或精确发生时间。

### P3：对象查询与前端切换

依赖 P2。交付：新对象列表、详情与对象动作时间线。

新增类别 → 类型 → 实例筛选。按归一实例计数，不按证据计数。来源、插件和采集项作为独立筛选保留。

当前行展开继续保留“易读说明 / 原始数据”；说明内分属性和状态、动作历史、证据和来源、采集状态。原始区明确区分归一对象 JSON 与原始来源证据。

发生时间排序使用稳定二级键和游标，时间未知或区间事件规定明确排序锚点并在 UI 标识，不能用 seq 冒充发生时间。页面分页固定查询边界或水位，避免回补期间反复跳页；新内容通过载入最新进入。

迁移期间新对象视图仅显示已支持类型，同时提供“原有来源视图”查看其他类型；不在同一列表混放归一实例和旧来源对象而不标识。

验收：任务全链路可用；暂停刷新、单项开关、隐私遮罩、复制、差异并排阅读及自身活动过滤不退化。

### P4：身份敏感类型与历史恢复

依赖 P2/P3。按用户 → 服务 → 进程 → 指定文件推进，不一次扩展所有类型。

必须覆盖账户改名、同名不同 SID、服务删除重建、PID 复用、文件改名与路径复用。缺少必要身份字段时保留暂定实例，不以猜测提高覆盖率。

当前快照可以先建可读对象，随后分批回放保留历史。回放较早证据不覆盖新状态；第一份保留记录不冒充对象真实创建。

验收：固定身份边界样例通过，实例生命周期无错误拼接；已清理历史明确标注无法恢复。

### P5：全目录扩展

依赖 P4。按照 P0 映射表逐批扩展其余类型：

1. 软件登记、AppX、启动登记、Shell/COM 扩展。
2. 网络配置、防火墙、端点与共享。
3. 证书、防护配置、策略与环境配置。
4. 设备、驱动、存储、虚拟环境与桌面集成。

只有事件证据而没有对象清单的类型可以支持“历史中发现的对象”，但不得计入“当前确认存在”的默认清单。比如密钥操作事件不自动产生一份完整的当前密钥清单。

验收：全部现有采集项都有明确归属或有理由的未归属状态；每种支持类型具有身份规则、关键字段、动作映射、证据入口和至少一个代表样例。

### P6：默认切换与收尾

依赖 P5。交付：新模型作为默认视图，迁移说明与回归报告。

先切读路径，旧来源存储仍作为兼容输入。旧对象展示分类逻辑在确认没有调用方后清理；原始来源 ID 和证据字段不删除。

验收：新旧记录覆盖对账完成、保留策略与故障恢复通过、查询性能达标，再移除过渡入口。通用对象关系图谱作为独立后续计划。

## 6. 历史迁移与回退

### 6.1 在线迁移流程

1. 预检数据库 schema、剩余空间、保留策略和待处理规模。
2. 新增表及版本元数据，保留旧表和读取接口。
3. 登记迁移水位；新入库数据持续进入投影工作队列。
4. 小批次回放保留记录及快照，保存游标；进程重启可续跑。
5. 历史水位完成后追上实时队列，再切换对应类型的默认读取。

历史读取任务与保留清理需要协调：用有界批次保护当前正在解析的证据；证据在待处理期间被保留策略清理时，记录“历史已清理”并推进，不永久阻塞。不得为回放无限保留原始历史而突破用户额度。

### 6.2 回退边界

界面可回退到旧来源视图，并暂停新投影；源采集和原始数据继续工作。新 schema 是否允许旧二进制打开必须核查，不能承诺任意旧版本直接兼容。

数据库备份应使用一致性备份接口，不能运行中只复制 history.db 忽略 WAL。备份位置、预算和清理方式在实施预检中明确；不自动创建无限期大副本。

重建投影不生成真实系统动作；解析规则升级记录为模型维护操作。

## 7. 存储预算与性能门槛

- 默认沿用 5 GB 滚动清理，用户选择无限增长时继续尊重该设置。
- 新索引、证据引用、当前投影、待投影队列和 WAL 全部计入预算。
- 不给每次未变化快照的每个字段永久追加大记录；复用版本、更新真实观察时间并保留必要的证据定位。
- 证据保留和投影裁剪同批维护引用状态，避免原始材料已清理但新表仍无限增长。
- 没有可删除历史、必要当前状态仍超额时给出明确容量不足状态；不静默破坏当前对象或声称仍满足额度。
- 列表 API 不返回完整 XML、大型 before/after 或所有证据，详情按需读取。
- 按 machine/type/scope/lifecycle、object/time、source/evidence 建窄索引；避免每页运行全库 JSON 分类。
- 保留只读查询隔离，投影批次必须有执行时间和数据量上限。

验收目标在本机固定数据副本上测量：相同筛选与页大小的列表/时间线 p95 不高于基线 20%，且目标小于 1 秒；对象摘要详情目标小于 1 秒。冷启动与重建单独记录，不用空库成绩代替真实历史规模。若未达到，先优化再切换默认视图。

## 8. 必须验证的场景

| 场景 | 预期 |
| --- | --- |
| 两个任务快照来源和运行日志命中同一路径 | 同一已确认实例，多份证据 |
| 同名任务位于不同文件夹 | 不合并 |
| 同一路径任务确认删除后重建 | 分为两个生命周期实例 |
| PID 相同、创建时间不同 | 不合并进程 |
| 来源只有名称或 PID | 暂定或未归属，不强行确认 |
| 旧日志晚于新快照入库 | 历史补充，最新状态不回退 |
| API 与日志状态不一致 | 按时间/能力处理；不能消解则展示冲突 |
| 未完整读取或单项停用 | 不产生对象删除，不刷新未读取字段时间 |
| 下次运行时间正常推进 | 状态变化，不声称人工修改 |
| 日志开始、失败、结束记录 | 保留阶段与结果，不误归并 |
| 投影中断、重复任务、规则升级 | 可恢复、幂等，不重复生成真实动作 |
| 历史清理与投影同时运行 | 无悬空引用、无无限等待、预算受控 |
| 明文显示关闭 | 摘要、证据详情和复制均遵循遮罩 |
| 前端暂停刷新 | 后台采集和投影继续，页面不自动跳动 |

## 9. 完成定义

重构完成不是“页面出现十二个分类”，而是：

1. 每个已支持实例具有明确身份规则和生命周期状态。
2. 多个来源可以为同一实例贡献字段和动作，而不生成无意义重复对象。
3. 每个关键结论能追溯证据与时间，无法确认的信息保持未知或暂定。
4. 对象状态与采集状态分开，未采到、未发现、确认删除可以区分。
5. 新增模型兼容历史保留、开关、隐私、刷新控制和既有性能要求。
6. 全目录映射清单公开标出支持程度，未归属证据仍可查看。

## 10. 建议第一批实际开发任务

第一批只完成 **P0 + P1 + P2 的计划任务闭环**：

- 产出类型与来源映射目录。
- 加入对象实例、证据引用和持久化投影队列。
- 统一两个任务配置来源及可确认的任务日志。
- 提供对象详情查询与试验入口。
- 验证重复任务、时间区间、权限缺口、停用采集和日志回补。

试点通过后再做全局界面切换和其余类型。这样可以先验证最核心的“一个实际对象、多份来源证据”，避免在身份规则尚未可靠时扩大迁移范围。
