# 原生状态采集第一批验收

日期：2026-10-14。原目标保持：全部不依赖历史日志的来源迁入编译后端；设备、网卡、服务、软件、模块、证书等当前状态直接读取，日志提供历史动作及原因。此次新增 19 项原生归属，当前全量为 59 已原生 / 72 待迁移 / 2 分组，整体目标尚未完成。

## 已进入正式代码路由的 19 项

- 基础单快照 8 项：系统版本、启动状态、服务、卷、网卡、设备、系统补丁、虚拟化平台能力。
- 系统分片 5 项：进程、用户配置文件、登录会话、机器身份、系统还原点。
- 存储分片 4 项：驱动服务、设备驱动绑定、固件、电池。
- 证书分片 2 项：当前用户和机器证书。

对应来源完整标识由 `plugins/platform-native/ownership.json` 维护，源代码位于 `State.cs`；新增基础来源沿用原单快照的范围字符串，其他来源沿用 16 分片。包装器对原生归属项禁用兼容脚本，原生失败不回退。

系统状态使用 Windows [MI QueryInstances 接口](https://learn.microsoft.com/en-us/dotnet/api/microsoft.management.infrastructure.cimsession.queryinstances?view=powershellsdk-7.4.0)直接查询原提供程序，证书直接调用 X509Store 只读接口。MI 依赖来自系统 GAC，编译检查缺失明确失败，隔离运行无需复制 PowerShell 或加载其引擎。

## 验证与修正

工作区构建的低完整性 exe 即使从普通终端启动，也会少读部分信息：当时只看到 279 个服务和约 39 个进程；设置普通应用完整性级别后，读取 281 个服务、330 个以上进程及真实补丁记录。这是实际读取范围差异，不应据此提交完整快照并确认缺席。新状态来源会读取自身 TokenIntegrityLevel，低于普通应用级别时输出失败并保留旧状态。应用打包仍需按既有 prepare-debug-runtime 流程设置运行文件标签。

初版普通 WMI 查询只有 3 张可见网卡，系统参考含 17 张。已保留 IncludeHidden 提供程序选项；所有 17 张网卡的身份和原六字段一致。提供程序语言明确使用既有英文基线，避免中文/英文设备厂商字符串变化被记录为配置修改。网卡状态、MAC、驱动版本和速率按既有系统类型定义处理。

只读字段比对已通过：213 个设备、17 张网卡、281 个服务、3 个卷、217 条驱动绑定、394 个驱动服务、1 个固件对象、1 个电池对象。服务 PID、运行状态和退出码是两次读取间可能变化的字段，不用跨时间相等证明其静态一致性。观察期间流服务代理由首次存在变成后续未枚举；再次运行系统两个查询接口和原生采集后结果一致，未通过白名单删掉这一对象来满足数量检查。

系统还原点在普通权限下仍拒绝访问，输出 gap，没有提交空快照。增强权限的相应范围验收仍开放；不能宣称已取得还原点结果。证书分别返回当前用户 44 条、机器 42 条，只采元数据，不导出私钥或执行信任评估。
