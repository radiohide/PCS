# 快照新增记录进入时间线（0.2.4）

2026-10-15：实际后台只读诊断发现，最近 200 条网络端点行动全为 `observed.no_longer_observed`；按端点类型查询 `observed.first_seen` 和日志 `network.connection_observed` 均为空。材料位于忽略目录 `target/network-appearance-diagnostic.json`，未复制原始设备资料到 Git。

原因是旧清单表已经保存 `object.first_seen` 差异，新对象模型只接入字段变化和完整快照缺席，新增差异没有进入行动队列。这是后台投影缺口，页面未过滤掉新增记录。当前后台未提供可显示的连接日志，不能靠另一个日志入口补救。

## 实现与边界

- 同一原始范围有过完整基线后，新列出的独立项目将原始差异与新增投影工作一起提交，随后通过已有对象绑定进入同一时间线。首轮基线不产生虚构的连接建立记录。
- 新增工作排在该轮对象观察之后。按来源、项目、范围、对象键和首次观察时间核对身份，忽略已知对象的附加登记角色；不猜测歧义身份，不另建重复对象。UDP 不完整身份仅在原始绑定唯一时使用。
- 时间使用前一次完整检查到本次检查的区间；缺少有效前次时间时仅使用采集时间。没有伪造准确的网络连接建立时间。
- 卡片显示“新增连接”“新增监听端口”“新增 UDP 端口”，其他端点状态显示“新增网络项”。分类依据此次新增时保存的小型类型摘要，后续状态变化不改写旧卡片；通用新增显示“新发现”。
- 同一证据重放、正常处理与历史恢复重复提交均去重。原始资料已清理或损坏时记录失败，继续处理其他工作，避免永久重试循环。
- 不新增 PowerShell 采集、不修改审计策略、不提高轮询频率。沿用原生枚举和已有串行投影器。此处覆盖独立快照项目的新增；嵌套成员列表的独立新增行动及同一身份再次出现的单独行动未在本次扩大实现。

## 旧资料恢复与运行

提供同账户后台接口 `repair_snapshot_appearance`，每次 1–256 条顺序检查、最多读取 2 MiB 原始材料，超过 1 MiB 的单条材料跳过。游标持久保存，采集写入忙时立即返回重试提示。它只为仍保留且能核对身份的 `object.first_seen` 原始差异补充派生时间线，不编辑原始记录、字段状态或首次基线；不在程序启动时自动扫描历史。

固定程序包仍为 `dist/dev`，debug 依赖与启动配置保留。正在运行的旧后台必须按原权限替换后，新逻辑和恢复接口才生效；更新或重新打开桌面界面本身不会替换增强后台。正式替换及历史恢复需要独立核对执行结果，不以编译成功代替。
