# N04 原生采集、权限与循环防护补充验收

日期：2026-10-12。基线为根目录 `pcscope`、schema 9；新开发包 `dist/native-safety`。本记录追加在 [采集完整性与性能评估](N04-collection-assessment.md) 之后，不改写旧包、旧测试或旧来源摘要。

## 权限方案与适用范围

授权给具体采集程序即可。Codex 的工具审批、沙箱可写目录、Windows 管理员 token 是不同的权限层。Codex Windows 的 elevated 沙箱模式需要管理员批准初始化，但命令仍以非管理员身份运行，因此不能替代 Windows UAC。[OpenAI Windows 沙箱说明](https://learn.chatgpt.com/docs/windows/windows-sandbox)

当前产品采用普通权限桌面 + 同一账户的增强后台。增强后台通过固定 EXE、固定参数的 `ShellExecuteExW` 请求 UAC，不再通过 PowerShell `Start-Process`；后台仍验证原账户 SID。当前方式在需要重新启动增强后台时可能再次请求 UAC，不是已经安装好的 Windows 服务。使用另一管理员账户会改变 HKCU、用户密钥及 DPAPI 范围，不能当作原用户采集的等价替代。[Microsoft UAC 与 WMI](https://learn.microsoft.com/en-us/windows/win32/wmisdk/user-account-control-and-wmi)

未来独立部署的目标是：在受保护安装目录部署机器侧服务/权限代理，安装时请求一次管理员授权；普通权限桌面经有访问控制的 IPC 调用固定采集能力，用户侧进程继续采集 HKCU、用户 DPAPI 和用户密钥。代理不接受任意 shell、脚本、EXE 路径或任意系统写入。此服务安装、最小权限划分和 IPC 加固仍待 N02/N06 实施，不能宣称已完成，也不能直接把全部采集换成 LocalSystem 后认定用户范围不变。

不存在仅凭管理员权限就保证完整采集的方案。尚未启用的审计、被覆盖/清空的日志、未安装组件、不支持的提供程序、受保护进程和未配置的监控范围都可能缺失。权限、环境和实现缺口分别记录；失败不提交完整空快照，也不推断对象已删除。开启审计属于额外系统写入，本轮只读授权没有执行该动作。

已验证环境仅为 Windows 10 企业版 LTSC 10.0.19044 x64、当前 Windows 用户、本地 NTFS、系统 .NET Framework 4.x、Windows PowerShell 5.1 兼容层、PS7 测试调度器。Windows 11、Server、ARM64、网络盘、其他文件系统及多用户服务尚无本轮实机验收。目录只观察明确指定目录的直接子项，不递归；文件只读元数据、ACL、ADS、文件身份及可选有上限的摘要，不保存内容版本。

## 本轮实施

| 项目 | 当前行为 |
| --- | --- |
| 事件日志 | 默认原生 Event Log 后端；仅显式配置 `powershell` 才使用兼容后端；原生失败不自动回退 |
| 新增原生来源 | 资源采样、LSA 权利、WTS 会话、CNG 元数据、日志覆盖、DISM 驱动包、.NET 注册表、范围配置、文件元数据、目录元数据，共 10 个 |
| 能力检测 | 原生审计与通道 API；默认只读；修复必须由产品设置显式启用，低权限拒绝修复 |
| 原生归属 | `plugins/platform-native/ownership.json` 指定正式归属；包装器禁止兼容层重复采集这些来源 |
| 兼容失败 | 按具体来源输出 gap；已经输出的原生证据仍可入库 |
| 运行约束 | 系统 DLL 搜索范围；PS5 不继承用户可写/PS7 模块路径及执行策略环境变量；不全局修改执行策略 |
| 快照 | 来源内全部分片先编码、验证唯一身份和协议长度，再输出；不提交部分完整快照 |

当前清单为 129 个直接来源：37 个正式原生来源、92 个 PowerShell 兼容来源；另外 2 个虚拟汇总组不计入直接来源。37 个包含 23 个日志通道、3 个 USN 来源、软件来源及本轮 10 个新来源。完整逐来源状态、现有 API 和观察范围在 [原生迁移清单](../../../model/native-migration.json)，由 `scripts/build-native-migration.cjs` 生成。

“能原生就原生”是所有来源的开发门槛。92 个 pending 是尚未完成的迁移工作，不代表 Windows API 必須依赖 PowerShell。迁移必须保留原始字段、身份、范围、分片、敏感值保护与缺口语义，并通过同环境对照后更新归属；不能仅把某个来源从清单或 UI 中删除来宣称全原生。Windows Update COM 原型在当前普通权限环境返回 Access denied，尚未正式接管；不能把文档允许普通用户调用误当成本机验收成功。

兼容脚本的签名/执行策略问题仍存在：新包实际应用领域混合路由取得 24 个原生 .NET 项，但 6 个兼容来源因脚本启动失败产生 gap。原生部分已可默认运行，全包部署仍需完成剩余原生迁移或受信任签名与策略验收。

## 避免循环风暴

调度只由时钟或明确手动操作驱动，读到日志、入库或刷新界面不会立即触发下一轮采集。自身活动标签是展示/关联元数据，不是唯一防风暴机制，也不删除原始证据。

| 约束 | 边界 |
| --- | --- |
| 并发与排队 | 状态、日志各一个执行通道；重复手动请求不排队；错过时钟 tick 不累计补跑 |
| 周期 | 状态最短 30 秒，日志最短 10 秒；默认状态 300 秒、日志 10 秒 |
| 手动冷却 | 状态 30 秒、日志 10 秒；能力检查 30 秒合并重复请求，返回实际 started 状态 |
| 日志拒绝/缺失 | 按通道 60、120、240、480、900 秒退避；保留缺口与真实尝试时间，健康通道仍能继续 |
| 任务失败 | 至少 30 秒，按配置周期指数退避，最大退避 1800 秒；用户配置的更长周期仍有效 |
| 每通道工作量 | 每轮最多 3 批；仅提交后推进断点；次要通道轮换，避免无界追赶 |
| 包装器时间 | 原生阶段至多 55 秒，兼容阶段至多 60 秒且共用 110 秒预算；外层服务 120 秒监督 |
| 文件范围 | 100 个显式文件/目录上限；拒绝后台数据目录及内部路径；不跟随目录重解析点递归；目录条目和摘要大小有上限 |

这避免 PowerShell 日志读取产生 PowerShell 日志、再触发立即读取的反馈链。原生调用本身仍可能产生 WMI、安全或文件访问审计；通过固定调度、工作量预算和真实进程身份关联控制，不能宣称原生调用完全不产生自身活动。退避保存在进程内，后台重启后可进行一次初始检测；持久化退避和长时间实际后台观测仍需验收。

## 只读 UAC 实测与缓存

本轮使用用户批准的专用只读验收 EXE，冻结 EXE/配置哈希，验证实际管理员 token 和同账户 SID，仅检测日志/审计、驱动仓库和 CNG 元数据并写工作区隔离目录；未启动正式后台、未打开正式数据库、未改变系统审计或日志设置。

| 指标 | 最终结果 |
| --- | --- |
| 管理员 token / 同账户 / repair | true / true / false；changes=0 |
| 日志实际可读 | 普通用户 19/23，管理员 21/23；剩余 Sysmon 和 Hyper-V 通道不存在 |
| 驱动包 | 原始 API 732 项，732 个唯一包身份，730 个唯一发布 INF 名称；完整输出 732 项、0 个驱动 gap |
| 审计 | 计划任务修改=false、进程创建=false、登录=true；保持原状 |
| CNG | 3 个明确提供程序/范围 gap；没有读取私钥材料 |

第一次 DISM 互操作因结构对齐错误退出。SDK 的 `dismapi.h` 明确使用 1 字节打包，已修正，并独立以 C 编译及 C# 两元素数组验证：x64 结构大小 100、provider 偏移 60、date 偏移 68。第二次读取成功后发现重复发布 INF 名称，完整快照被唯一性检查拒绝；改用“发布 INF + 原始驱动仓库 INF 路径摘要”作为包身份，再验收通过。原始接口的 15 个 SDK 字段保存在载荷中，不把驱动仓库存在解释成驱动已加载。

最终原始材料位于 `target/native-permission-assessment/06772b5977ac43bea514bb4dbbf7fd49/`，含 capabilities、driver-api-items、native-sources 和 complete。该目录含本机材料，保持忽略，不复制到交付文档或开发包。后续身份与适配问题可离线复现，无须再次触发 UAC。冻结验收 EXE 与最终开发包哈希分开记录；其后空通道、防自采集、DLL 搜索与组合时间预算的修改另经普通权限验证，不宣称最终包的全部字节已重新管理员实测。

离线定位的 CNG gap：Passport/machine 和 Smart Card/machine 返回 `0x80090009`，Smart Card/user 返回 `0x8010001D`。这些结果不能统一归因于管理员权限不足；尤其 `NTE_BAD_FLAGS` 要继续区分提供程序能力与调用兼容性。保留静默枚举，不为了消除 gap 取消静默、弹出 PIN 或读取私钥。[NCryptEnumKeys 参数与错误约定](https://learn.microsoft.com/en-us/windows/win32/api/ncrypt/nf-ncrypt-ncryptenumkeys)

## 完整性、性能与回归

- 缓存管理员材料与普通原生材料共 327 条报文入内存数据库，0 个投影失败；重复回放新增任务=0。不是正式后台运行验收。
- .NET 原生 24 个项目与此前 PS 诊断材料逐项比较 ID 和完整 data，完全一致。文件夹具确认只读 2 个直接子项，嵌套文件不递归；自身数据目录输出明确 gap。
- 原生程序缺失时只有原生失败 gap，不启动 PS；兼容脚本缺失或实际启动失败后原生 .NET 证据保留。
- 默认原生日志读取及同 epoch 的 batch_seq+1 续读通过，两批无重复事件 ID。此前固定 EVTX 的 3638 条全载荷对比与 3.57 倍耗时改善仍作为独立历史性能证据。
- 最终开发包单次普通权限包装器耗时：应用 283 ms、系统 569 ms、安全 196 ms、范围采集 133 ms、Application 首批 541 ms、续读 290 ms。不是全量 129 来源的总耗时、p95 或长期负载；普通权限驱动 110 ms 只是快速拒绝，不能当作成功驱动采集性能。
- Rust 工作区 362 项通过；最后调度反馈与组合预算修改后，相关 IPC/服务/包装器 13 项复测通过。22 个 Node 检查通过；无 Git 环境使用既有文件枚举 shim 验证所有权。独立桌面编译通过，仍有此前 MinGW 多 manifest 链接警告。
- 原有 14 条严格 Clippy 问题未在本轮声称解决。未完成最终 GUI UAC 切换/取消、权限代理安装、多用户、冷启动恢复、Windows 其他版本及长期防风暴实测。

开发包、测试指标和摘要参见 [机器验收指标](N04-native-safety-metrics.json) 与 [开发包 SHA256](N04-native-artifacts.sha256)。新包不覆盖 `dist/n04-source-gaps`；旧包 28 个文件摘要仍需保持一致。
