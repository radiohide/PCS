# 系统对象名称整改与验收

日期：2026-10-13。代码、字典和打包版本：模型 1.2.6，`dist/object-names`。

## 核对口径

以实际对象记录为分母，不把 `active` 记录数当作现在仍运行的程序数。首次完整后台查询 21,678 条，包含“名称尚未确认”10,745 条（49.57%），涉及 25 类对象；此外另有 14 条无名软件登记和 1 条被隐私过滤隐藏的名称。原始审计保存在 `target/current-object-name-audit.json` 和 `target/current-object-name-rows.json`。

按同一 instance_id 比较，不靠改掉“名称尚未确认”这句话宣称问题已解决。分别统计已有名称或用途、带来源限定的日志名称、带来源限定的旧程序名称和仍缺资料项。未知设备、受保护值、身份冲突、丢失的历史原文不猜测。

## 已实现

- 恢复采集到却没有映射的磁盘名、设备驱动名、防火墙显示名、进程名及登记路径。机型产品名称不再混入计算机名称。
- 网络连接显示协议和两端地址；磁盘分区、存储卷、路由、证书、应用组件和文件打开方式显示已知用途。双向符号不宣称连接发起方向。
- “文档、图片、视频”等桌面入口采用本机 Shell 实际返回的名称，按精确组件标识匹配，并补齐列表所需的组件字段。Active Setup 使用实际采集登记和 .NET 组件信息解释用途。
- 登录会话按 Windows 登录类型和开始时间显示。用户组成员通过同一机器、安装实例和范围内的 SID 关联已有账户名称；三项系统 SID 有固定解释，不按名字合并账户。
- 旧程序名称只从原有绑定的完整“进程编号＋启动时间”采集材料恢复，且核对机器范围和材料内同一组字段。编号重用、多代绑定、保护或丢失的材料不会被补成确定名称。不写回身份，也不判断当前运行状态。
- 日志记录的名称保留“程序活动记录／登录记录”等限定。历史误分类和原文不足单独说明。
- 原始路径、内部标识和全部属性继续放在详细信息中。本次没有新增采集循环，也没有新增 PowerShell 轮询或修改系统审计设置。

## 仍不能通过改名解决的资料问题

- 五个设备在 Windows 中缺少驱动，原生查询也没有可读名称；需对应驱动资料，不能虚构型号。
- 189 条旧程序记录、旧 DNS 和快捷方式记录存在多个对象混在同一身份下的情况，需要有界身份修复和历史重新投影；本轮明确显示冲突，不任选其中一个名字。
- 部分旧事件原文已不足、旧软件登记没有产品名称；保留原因，不视为已确认。另有可选功能名称被现有隐私关键词规则过滤，不能将其描述为来源未采集；隐私误匹配修正另行保留，未放宽现有保护规则。
