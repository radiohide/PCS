# 0.2.21 硬件全部历史查询修复

## 问题与修复

正式库“硬件＋全部时间”在约 6 秒后超时。硬件只有 97 条变化，但原查询强制沿全局时间索引寻找匹配项；需要扫描大量无关记录才能确认这一页已经结束。硬件对象列表可正常读取。

按类别、类型或具体对象筛选时，先通过已有对象／变化索引读取最多 10,001 个候选记录编号。候选不超过 10,000 条时，直接按编号读取匹配变化，再排序分页；超过阈值的密集分类继续使用时间索引。未筛选的查询不执行这一步探测。

所有原有筛选、展示版本、可见性规则、水位和游标条件保持有效。无需新索引、数据库迁移或重建展示数据。没有增加查询超时时间。
