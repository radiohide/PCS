# 时间线自动刷新阅读保护 · 0.2.24

## 行为

- 浏览历史时保留当前内容、滚动位置、已加载时间组和展开的详情。顶部按钮显示“有更新 · 载入最新”。
- 操作组内折叠、分类、全选、反选或全部折叠后，保留阅读状态，直到主动载入最新或改变查询条件。
- 在顶部且未操作组内显示、未展开详情、焦点不在记录内部时，继续自动刷新。状态栏和后台采集继续运行。
- 自动读取先准备完整时间组和 HTML，再替换页面；准备过程中如果开始阅读、切换页面、暂停刷新或修改筛选，放弃本次替换。
- 自动读取失败保留最后一次结果，按原有 15 秒节流重试。阅读期间不额外查询时间线。
- 手动“载入最新”和修改筛选仍会主动重载。此保护针对时间线自动更新，不改变其他页面的刷新行为。

## 实现

`app.js` 为页面刷新传递 `automatic`，页面可返回 `false` 表示本次未替换。协调器保留待刷新标记，且不会在页面或刷新代次已改变后写入旧结果。

自动刷新使用原有完整分组读取器，在离屏准备期间抑制逐批写入 DOM 和加载提示。成功应用后接续同一个读取器的游标和预取缓冲，避免重复拉取或遗漏后续组。原有读取上限、单路预取和过期响应取消继续生效；没有新增轮询器。

界面版本 0.2.24，正常目录 `dist/dev`，debug 目录保持不变。此次只替换桌面程序，现有 0.2.23 增强后台继续运行；未触发 UAC。路径配置和后台二进制哈希保持不变。

- `node scripts/check-auto-page.cjs`：通过。预加载、串行请求、隐藏视图、过期响应和失败重试。
- `node scripts/check-object-interactions.cjs`：49 个真实 Chrome 交互场景通过，无浏览器错误、无采集调用。新增覆盖：
  - 1,400 条虚拟化记录的中间阅读位置、行数、展开详情和时间线查询次数均保持不变。
  - 组内操作后，即使位于顶部也保留内容；手动加载最新清除提示。
  - 读取发出后开始滚动，返回结果不替换当前内容，并取消后续读取。
  - 回到顶部后自动更新，滚动位置仍为 0。
  - 后台读取失败保留旧页面，重试成功后继续滚动加载下两个完整组，无重复。
