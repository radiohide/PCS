# 桌面显示与权限连接修复

日期：2026-10-12。基准为根目录 `pcscope`；新包 `dist/desktop-display-fixed`，开发预览入口 `scripts/open-preview.ps1`。

| 已发现问题 | 修复后的行为 |
| --- | --- |
| 缺少显示名称时直接展示内部长标识 | 默认使用来源名称、文件短名称或中文类型；缺名明确提示，用短记录编号区分，完整名称与内部标识折叠 |
| 属性标签显示成 identity/configuration | 修正查询 label/kind 元组取值；界面按现有目录显示中文，兼容当前旧后台 |
| 列表遗漏已经采集的配置名称 | 摘要加入来源提供的名称、显示名称、说明等字段，不改变身份、结构或排序游标 |
| 失败的权限窗口挡住界面 | 可选择“稍后设置”或按 Esc 离开；失败可重试，保留实际权限状态 |
| 权限连接等待过久 | 有界等待，拒绝连接立即报告；不反复自动申请 UAC |
| 低权限开发程序无法连接管理员后台 | 复制完整包到普通临时应用目录后启动，原后台与记录保留，不修改 ACL 或工作区标签 |
| SQLite 临时目录不可访问 | 后台在线程启动前准备所选数据目录中的独立磁盘临时目录，验证可写及非重解析边界，不删除库或切换实例 |
| 后台未连接误报找不到文件 | 启动时仅尝试一次普通后台连接；失败保留手动恢复入口 |

名称规则覆盖对象列表、详情标题和对比选择框。模块文件使用短文件名，不把名称解释为未验证的功能用途；默认关键属性只显示少量易理解的信息，完整字段、路径及材料保留在详情中。

## 实际证据

只读抽查 200 条对象，display_name 均为空，旧界面因此显示内部别名。此样本按原始名称排序，不能推断全部对象均缺名。第一条软件安装项详情的显示名称确为 not_provided，使用缺名提示而非虚构名称。材料：`target/live-object-name-sample.json`、`target/live-unnamed-software-detail.json`。

相同原生诊断字节在工作区运行时完整性级别 4096、连接拒绝；复制到普通临时目录后级别 8192，CreateFile、异步注册与请求成功，读到 PID 13664、elevated=true。两次账户和端点一致，受限 SID 数量均为零。证据 `target/normal-preview-connection.log`。[Windows 完整性说明](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control)解释了映像标签和进程完整性级别的关系。

管道仍仅允许 SYSTEM 与当前账户，拒绝远程客户端，未添加其他主体或更改标签。低完整性测试程序生成低标签管道导致安全断言失败；保留同一严格断言和测试字节，在普通应用目录运行后 5 项 IPC 回归通过。自动审批曾拒绝删除标签测试，最终保留安全检查，没有绕过拒绝。

更新后的普通权限界面已打开，窗口标题 PCScope，进程响应；管理员后台和现有记录保留，未再请求 UAC。运行中的后台保留此前版本；新包的查询标签和摘要修复随下次后台更新生效，界面规则已兼容旧后台。
