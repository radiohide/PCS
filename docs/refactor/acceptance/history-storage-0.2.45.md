# 0.2.45 历史存储与手动删除

存储占用、分类明细和最早保留记录集中在“系统配置 → 历史存储”。采集健康不再重复显示。容量策略保存后刷新统计，自动刷新保留已展开的分类。

“删除全部历史数据”需打开确认框并勾选确认。范围为当前数据目录的采集记录、对象历史、派生结果和游标；保留采集周期、开关、文件/目录/进程监控名单、权限配置、隐私显示与容量策略。备份、导出文件和 Windows 日志不在删除范围内。

后台先持久化操作回执，再由同权限原生进程替换后台，等待原采集停止。新后台取得该实例连接的独占所有权后，创建仅包含配置的新库，关闭 SQLite 日志，再原子替换原库。失败时保留原历史并提供重试提示；不扫描或逐行删除大库，不执行 VACUUM。新库建立新历史标识和采集起点，系统日志从新起点继续记录。

回执与数据库中的操作标识支持崩溃后重试：已完成的操作不会再次清除新数据。请求必须带当前历史标识和明确确认字段。界面防止重复提交；断连或确认回复丢失时只查进度，不重发删除；旧操作回执不能确认另一轮删除。旧后台不支持时禁用入口并提示升级。

## 验证

- Rust：storage 261、service 39、ipc 6，共 306 项通过。
- 浏览器：历史存储删除流程、原存储刷新、设置独立加载均通过；真实路由 49 项交互通过。
- 删除交互覆盖取消、未勾选、重复点击、断连重连、丢失回复、失败恢复、旧回执、重新进入页面与离开后停止轮询。
- 存储测试覆盖配置保留、游标/观察缓存移除、文件空间释放、操作重放安全、旧历史标识拒绝、活动读连接阻止替换及随后重试成功。
- `scripts/check-history-reset.py` 创建全新 target 隔离实例，禁用采集，通过真实 IPC 完成后台替换和删除；配置逐值一致，旧标识不能再次删除。测试文件从 8,884,224 字节降至 864,256 字节，切换与清空耗时 0.766 秒。仅代表小测试库，不能推算生产大库耗时。
- release 工作区程序与 examples、桌面 debug 构建完成；正常入口仍为 dist/dev，桌面 debug 使用同组优化依赖。

开发验收未对用户生产历史执行删除。生产后台需更新到 0.2.45 后启用入口。
