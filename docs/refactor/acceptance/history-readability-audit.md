## 根因与本轮修复

| 根因 | 已实施的修复 | 仍需保留的边界 |
| --- | --- | --- |
| COM 根键说明、进程内服务器路径和独立服务器命令被写入同一实现字段；交错采集使说明与 DLL 路径反复比较 | 根说明写 `name`，`InprocServer32` 写 `server_path` 及文件元数据，`LocalServer32` 写 `local_server_command`；不同角色不再用空字段覆盖彼此 | 登记不是运行或加载证明；独立服务器命令不能直接当文件路径 |
| 同快照的多条 COM 登记使用同一个对象观察去重键，可能只投影首条 | 仅 Shell COM 快照增加按对象和原始项区分的幂等标记；保留原对象级证据引用 | 其他类型重放语义保持；不增加轮询、全盘扫描或模块枚举 |
| 新映射首次纠正旧事实可能被当成系统变化 | 精确限定旧规则到新规则、COM 实现三字段；通过原有时间和保护选择后，首次新有效观察建立比较基线，后续真实变化正常记录 | 不绕过晚到、冲突或遮罩规则；保留原始证据，不据此重写旧历史 |
| 旧 COM 对象没有名称，历史界面显示大量泛名 | 从精确来源绑定、范围、注册表视图和根键取得唯一已采说明；默认给出名称，原标识与依据折叠 | 这是已采登记说明，不冒充事发时名称；冲突、受保护值、超预算和身份不完整时拒绝补名 |
| 历史软件名称字典缺少身份状态上下文，已知名称未能使用 | 查询透传核实后的 `identity_status`；未核实事件清除关联对象可提供的名称信息 | 不通过旧错误关联恢复名称，也不让字典绕过隐私保护 |
| 生产进程快照字段与原参考适配入口不一致，路径、创建时间和会话信息未正确承接 | 生产入口统一使用适配器，承接 `path/start_time/session_id` 并兼容旧字段；PID 和完整创建时间共同区分实例 | 明确不可读或保护值不回退到另一字段；未批量重建旧进程对象，短命进程仍可能被快照遗漏 |
| 全局采集事件被要求关联一个系统对象 | 以“PCScope 采集监控”解释适用的全局事件；标题、阶段和影响分别表达 | 无需对象关联不等于能推断系统功能正常 |

COM 旧 `server_path` 动作为 **83,145/101,166（82.19%）**。已验证的代表材料在同一 CLSID 下交替出现组件说明与实现文件路径。读时质量标记按明确旧规则和混合角色绑定设置，时间线与比较显示“旧版采集记录需复核”，不再把它呈现为已证实的路径变化；原始前后值仍可展开。**该数量不表示逐条已证明虚假，也不能用于认定文件损坏或系统故障。**

实现依据：[COM 适配](../../../crates/contracts/src/adapters/shell.rs)、[投影与首次基线](../../../crates/storage/src/projection.rs)、[有界名称读取](../../../crates/storage/src/history_labels.rs)、[查询上下文](../../../crates/storage/src/query.rs)、[进程适配](../../../crates/contracts/src/adapters/runtime.rs)、[界面解释](../../../apps/desktop/ui/readable-events.js)。

## 字典覆盖与不能强认的内容

[完整字典复核](../../../target/history-audit-com-name-full-review-summary.json)审查 **130 组唯一 CLSID＋原说明、247 个有名称候选实例**，加入 125 条精确解释，覆盖 239 个实例。所有匹配同时要求已确认身份、精确 CLSID 和原说明；自定义名称或同名不同身份不被改写。

- 在 83,145 条旧 COM 路径动作中，80,385 条可使用直译名称（96.68%），2,760 条保留原说明；这个比例仅衡量名称解释，不等于变化可信率。
- 另一个全动作口径中，字典覆盖 80,424 条历史动作，不能与上一行重复相加。
- 5 组私有或用途不明确的原说明保留，例如 `CryptPKO Class`、`Execute Unknown`、`NvAppShExt Class`；不按缩写猜用途。另有 13 个实例没有可唯一采用的登记名称，它们在冻结历史中没有动作，不属于上述 808 条名称不足。
- 受保护、不可读、冲突、无可信关联的内容继续说明原因。已有名称、启动或结束事件，均不自动证明程序正常或操作成功。
- 登录 ID 可跨重启复用。没有事件所属启动周期的证据，就不能用当前机器启动周期补齐旧日志；原模型的 `verified` 关联不能据此当作跨启动周期已验收。

## 原始日志覆盖是另一条未完成链路

[原始事件覆盖汇总](../../../target/raw-history-coverage-summary.json)以同一历史水位统计 **78,244 条日志来源记录**；剔除 122 条采集健康通知后，真正 Windows 事件分母为 **78,122**。这些是保留记录数，不是跨日志代际去重的系统事件总数。

| 口径 | 结果 | 能说明什么 |
| --- | --- | --- |
| 旧事件标题字典不能解释 | 25,484/78,122，32.62% | 只按来源、提供程序和编号识别标题；未验证版本、字段、结果和状态投影 |
| 补齐 4907 后标题仍不能解释 | 16,757/78,122，21.4498% | 同一批分组只有 Security 4907 的 8,727 条标题得到解释；不增加模型动作投影或对象关联 |
| 冻结时间线涉及的原始事件记录 | 11,130/78,122，14.25% | 说明现有时间线与原始事件之间仍有较大覆盖差异 |
| 上述数量的聚合差额 | 66,992 | 不是逐条联查结果，不能直接称为丢失、解析失败或全部未投影 |
| 当前适配入口静态无动作路线 | 66,997/78,122，85.76% | 按分组元数据检查的候选路线缺口，不是逐条重放的实际失败数 |

旧字典已经能解释、但当前适配入口没有动作路线的分组加权共 41,522 条。下一步应优先补原始日志到可查询事件摘要的完整链路，再按明确字段补对象关联或状态更新；多数事件不必改变当前状态。不能仅改善已进入时间线的名称，就宣称所有已采日志已经可读。Security、组策略、System、应用部署等具体优先级见汇总文件。

[4907 定点复核](../../../target/raw-history-coverage-after-4907.json)保留相同输入哈希及水位，只补精确 Security 来源、Microsoft-Windows-Security-Auditing 提供程序和 4907：显示“对象访问审计规则已修改”，说明它影响哪些访问写入安全日志，不能当成文件内容或访问授权变化。最终已解释标题 61,365 条、未知 16,757 条；未修改原始事件、模型投影或对象关联。新增的是既有日志的语义子项，当前清单成为 **225 个定义、222 个控制条目、109 条日志分类规则**，来源仍为 133 个，不增加轮询。
