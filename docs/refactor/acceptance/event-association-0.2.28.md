# 日志关联与历史修复：0.2.28

2026-10-21。接续 [0.2.27 计划任务验收](task-association-0.2.27.md)。本批是总方案的通用机制及会话、账户部分，不能等同于全来源整改完成。

## 已实现

- 新事件的关联决定、机器/安装/启动范围、规则和身份校验值持久保存。展示读取这个决定；原始材料按保留策略清理后，不再因此丢失已经验证的对象链接。对象身份或来源绑定改变会使决定失效。
- 公用事件身份字段只接收可用文本和整数；空值、受保护内容、对象/数组/布尔值不转成对象名称，也不绕过显式无效值去读别名。缺关键身份的事件独立保存，停止继续建立共用 `?created_at` 等临时对象。
- 原生读取 Windows 启动 GUID；启动时间只限定时间范围，不作为身份。会话快照与事件统一使用启动范围，登录编号统一十进制/十六进制格式。不同启动、时间区间重叠、时间明显跳变、未知启动和导入日志均不硬绑。
- 旧的无启动范围会话快照保留历史，收到新范围快照后退出当前活动列表。新增、缺失记录读取其原快照中的启动信息，避免范围升级导致停止产生消失记录。
- 本地账户名称回查要求目标账户名、明确的本机名称、原生账户观察覆盖事件时间、唯一 SID，且没有已知改名冲突。不会使用操作者名称，也不会把域账户按本地同名账户处理。
- 服务名称回查纳入历史服务；多候选继续不绑定。历史显示名称的完整别名区间仍待下批补齐。
- 历史关联分批重验，保留动作编号、时间、原始记录。多材料冲突不移动关联，不因只读取前 8 份标签而忽略第 9 份之后的矛盾。无法完成的一条通过保存点回滚其候选变更，其他记录继续。
- 启动信息晚到后，只重试被新时间范围覆盖的等待记录。完成后的检查最多每 10 秒一次，仅查询等待索引；没有全库轮询、没有额外 PowerShell 进程。
- 主卡片去掉通用“日志未能对应到具体对象”；事件事实、分类和记录详情仍保留，有效关联才提供对象链接。
- 单对象详情计数直接走该对象的索引，不再先统计全库引用数量来选择路径。正式库只读基准中，三个任务对象详情 p50 为 22.41–31.98 ms，p95 为 25.68–41.96 ms；旧后台同样对象约 0.76–1.05 秒，首次曾超时。

## 数据修复与性能约束

首轮按固定动作水位扫描，每批最多 512 行、40 ms 工作预算。任务修复独立游标保持不变；后续关联修复另有游标和审计表。当前状态不由历史修复回写。

启动范围、等待队列和关联决定均是派生表。新的 Windows API 查询每次会话集合执行一次，不逐会话调用；启动元数据获取失败不会使整个状态快照失败。

本批展示上下文读取方式有变化，按现有展示规则版本机制执行一次后台分批重建。它不删除历史，但准备期间可能增加读写负载。随后每条关联更新仅使受影响动作缓存失效。正式查询性能须在准备中和准备完成后分别记录，不能将只读例程的结果冒充已部署 UI 的结果。

- contracts 279 项；storage 最终全套 224 项；service 32 项；UI 渲染契约检查。
- 专项覆盖：任务路径拆分、缺字段/保护值、事务回滚和续跑、启动时间微小抖动、跨启动编号复用、不同机器/安装范围、时钟跳变、材料清理、身份变化失效、名称/域/时间限定、操作者与目标区别、改名拒绝、延迟启动材料重试、十进制快照与十六进制事件对齐、第 10 份证据冲突、修复后重复投影。
- 原生普通权限实测连续三次读取同一启动 GUID，无系统设置改动。
- 一次并发全套测试与优化构建同时运行时，采集提交等待的 1 秒阈值测试失败；将负载分开并限制测试并行度后，完整存储套件通过。正式性能复测不与编译并发。

真实材料隔离回放：10,515 条事件（特殊权限 10,257、登录失败 207、进程启动 42、会话断开 9），6,952 条特殊权限事件在已知启动范围内恢复关联；其余独立保留。回放没有复制账户快照，所以没有将该回放中的 207 条未关联数作为账户回查效果的实库结论。动作数守恒，重复投影不增加记录。修复工作 8,277 ms，批次 p50 40.76 ms、p95 42.27 ms、最大 43.24 ms；是内存回放指标。

回放入口为 `target/release/examples/event-association-replay.exe <fixture.json> <boot-start> <observed-until>`，只写新建的内存库。正式部署结果追加在文末；未完成的步骤不得计作通过。

## 原生接口依据

按 [Microsoft 的 NtQuerySystemInformation 文档](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntquerysysteminformation) 在运行时解析接口，失败时保留明确的不可用结果。结构与信息类编号依据 [System Informer 的 phnt 头文件](https://github.com/winsiderss/phnt/blob/master/ntexapi.h)；只读取返回缓冲区首个 GUID，长度有界，不假定所有 Windows 版本都支持。
