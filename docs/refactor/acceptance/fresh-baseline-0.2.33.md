# 0.2.33 新采集基线

用户要求：旧数据库压缩备份、重新开始采集、全局周期 10 分钟，后续开发不引用旧数据。

## 实现

- `scripts/backup-offline-database.py`：停止程序后，将数据库、WAL、SHM 和启动记录打包为 ZIP64。Windows 文件共享锁拒绝并发写入；每个文件记录 SHA-256；完整解压并校验 CRC、字节数及 SHA-256 后才发布 `.zip`。空间不足或中断留下未完成状态，保留所有源文件。此校验保证备份与源文件一致，不宣称损坏的源数据库已被修复。
- `pcscope-cli init-baseline <新数据库路径> 600`：只允许新路径和空历史，事务保存固定采集起点、全局周期、运行时周期；不读取或迁移旧库。重新初始化已使用的库会被拒绝。
- 定时采集包括状态快照、事件日志、USN、进程模块、模块文件检查，均沿用 600 秒配置；后续单项调整仍按最后保存的值执行。启动时先读取当前状态，原生通知和人工立即采集仍可触发及时检查。
- 显式全局周期每轮依次检查全部日志通道，避免旧的次要通道轮转把 10 分钟扩大为数小时；保持串行和失败退避。未设置全局周期的旧实例仍保留短周期轮转兼容行为。
- Windows 日志只读采集起点之后的事件；断点恢复、日志清空或覆盖后的重新读取仍保留这一边界。显式 EVTX 导入保持原有行为，原先没有基线设置的实例也不被自动改变。
- 运行时监控摘要现在报告实际配置的周期。
- 正常入口与桌面 debug 入口继续使用固定构建目录，通过各自 `pcscope-launch.json` 连接新数据目录。

## 验证

- 备份自动测试：完整 DB/WAL/SHM 还原、拒绝覆盖备份、空间不足保留源文件、Windows 并发写入拒绝。
- 原生日志测试：原有查询、起点过滤、断点过滤、无效时间拒绝；直接读取 Windows Application 验证初次查询及断点失效重置均不会越过起点回读。
- 存储测试：初始化事务、周期范围、重复初始化拒绝、非空历史和已有周期配置拒绝。
- 调度测试：所有周期初始 600 秒，新采集项继承全局值，单项改动及重新应用全局值保持原来的优先级。
- 正式验收需在 ZIP 完整校验后进行：新库无旧记录、正常/debug 入口均指向新库、所有周期为 600 秒、重启保留起点、首轮状态及后续事件可见。
