# 完整批次接收原型

日期：2026-10-19。对应 W01、W02。状态：隔离原型，未接入正式采集，不改变现有数据库结构。

`collection-run-prototype` 使用独立 SQLite 表验证接收规则。执行代次由宿主生成；每个来源、范围和配置使用持久递增序号。原始分块按字节保存，全部分块、条目数、字节数、摘要和结束标记一致后，才更换已接收指针。接收完成与模型／展示发布是不同阶段。

已通过 13 项测试：缺分块或结束标记、乱序分块、重复提交、内容冲突、跨块重复标识、摘要不符、旧结果迟到、系统时钟回退、宿主代次替换、配置隔离与不可复用、序号溢出、形状和容量错误、写入事务中断、其他来源继续工作，以及同一可信宿主重新打开接收库后续传。部分测试同时覆盖多个断言；合计为 13 个测试函数。

命令：`cargo test -p pcscope-storage --example collection-run-prototype`。内存演示：`cargo run -p pcscope-storage --example collection-run-prototype`。不打开正式历史库，不启动采集器。

仍需完成，不能据此关闭 W01／W02：

- 接入全部采集、文件／模块监控和导入入口，并明确旧协议的完整性条件。
- 模型、字段贡献及展示代次的分批构建与原子发布；查询、计数和游标保持同一可见版本。
- 新宿主重启后的可信缓存接管；当前只允许同一宿主续传，新执行代次会拒绝旧票据。
- 全局暂存与磁盘配额、回收、空间不足恢复、迁移、备份和回退。
- 将隔离故障测试扩展到真实监督进程及正式数据库副本。

`received_items` 仅供小型隔离断言，汇总了全部分块。正式接入必须逐块消费，不能复用为大型采集的内存读取入口。
