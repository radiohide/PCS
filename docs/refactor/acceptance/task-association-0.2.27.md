# 计划任务关联修复 0.2.27

修复 TaskScheduler 结束事件漏读 `fields.TaskName` 的问题；原生结构与历史顶层 `task_name` 统一读取。路径缺失、空值或受保护时保留独立事件，不创建共用的 `?path` 临时任务。显式受保护字段不通过旧别名绕过。

后台在原有投影线程中分批修正任务历史，保留动作编号、时间、原始材料和当前对象状态；修复游标和操作记录持久化。每批最多扫描 512 行、预算 40 ms，每 250 ms 至多执行一批，完成后停止；失败退避重试。多份材料指向不同任务、没有历史环境或材料不可读时记录原因，不随意关联。任务来源绑定逐事件修正，重复投影不会增加动作。

本批不修改展示规则指纹，不触发全部展示缓存重建；通过已有动作更新触发器只重建受影响记录。共享临时对象没有被改成某一个任务，也没有删除原始证据。

## 验证

- contracts：278 项通过；storage：214 项通过，另新增回滚/重启测试后，关联专项 4 项全部通过；service：32 项通过。
- `node scripts/check-model-view.cjs` 通过。
- 正式历史只读提取 1,691 条任务结束事件，涉及 110 个路径，在内存数据库模拟旧共享对象并执行修复：1,691 条全部恢复关联，未解决 0 条，展示关联警告 0 条。
- 真实材料回放修复耗时 3,850 ms，93 个小批次，批次 p50 41.25 ms、p95 43.11 ms、最大 45.23 ms。该结果是内存隔离回放，不是正式大库运行速度。
- 修复后重复投影，动作数量不变；原始事件数量不变。错误提供程序、缺路径、受保护字段、不同任务路径冲突、事务失败和断点恢复均有回归覆盖。
- 优化后台与固定桌面 debug 入口已构建。正式后台替换与大库修复结果待部署复核后填写。

可复用回放命令：`target/release/examples/task-association-replay.exe <fixture.json>`。程序只在内存中新建数据库，不打开正式库。夹具为标准事件数组，机器材料保存在忽略目录 `target/task-association-replay.json`；指标见 `target/task-27-replay-result.json`。
