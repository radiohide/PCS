# 后台自动启动与恢复验收

日期：2026-10-14。开发包：`dist/backend-autostart`；模型版本继续为 1.2.6。

## 行为

打开桌面程序时自动连接所选数据目录的后台；后台不存在时自动启动同目录的原生程序。断线后再次连接或启动，窗口隐藏、最小化和暂停页面刷新时仍有原生守护。恢复成功后更新当前页面。

普通启动不触发 UAC，不更改保存的采集模式。后台进程变化后重新检查采集权限；保存增强模式但未取得管理员权限时，显示授权选择。不会自动反复申请管理员权限。

## 启动约束

- 原生端每 10 秒复用现有前台登记检查；界面继续每 3 秒检查连接。两者共享进程内启动锁，手动重连也使用同一入口。没有增加 PowerShell 循环或采集请求。
- 只有明确找不到所选后台管道时允许启动。忙碌、读取超时、拒绝访问和异常响应都不能当作后台不存在。后台保留原有第一管道实例保护，在打开数据库和启动采集前排除重复实例。
- 保留子进程句柄，慢启动不重复拉起。就绪等待整体限时 20 秒，之前的探测沿用 IPC 的 10 秒期限。
- 每个桌面进程的不稳定运行阶段最多自动尝试启动 3 次，重试至少间隔 10/30 秒；连接连续稳定 2 分钟后恢复重试额度。界面同样限制自动重试并保留手动按钮。自动启动暂停后仍可探测并连接外部恢复的后台。
- 管理员权限切换与普通启动共用锁；切换已发起后保留 180 秒交接保护，与后台等待旧进程退出的期限一致。交接期间不会由同一桌面另起普通后台。
- 本功能随桌面程序运行；未安装 Windows 开机服务或登录任务。
