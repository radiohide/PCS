# 进程历史与组成员关联：0.2.31

2026-10-22。接续 0.2.30；本批修复进程历史缺少原生创建时间时的关联，以及组成员事件漏读组标识。

## 规则与展示

- 原生运行清单仍使用 PID＋GetProcessTimes 创建时间；已有键不变。
- Sysmon 的 ProcessGuid 与 PID 使用单独身份命名空间，同一实例的启动和退出可以乱序到达；同 PID 的不同 GUID 不合并。
- Security 4688 v0/1/2 使用包含日志代际的完整事件地址建立历史启动实例。校验通道、提供程序、事件编号、版本、PID、时间和重复字段，不把父进程 PID 当新进程 PID。
- 日志时间单独保存为“日志记录的启动时间／退出时间”，不填写原生“创建时间”。历史主体不进入当前运行状态；详情显示“历史进程”，有 Sysmon 退出记录则显示“进程已退出”。时间线继续表达当时的启动／退出。
- 组成员变更使用 TargetSid＋MemberSid，支持 4728/4729、4732/4733、4756/4757 的 v0 模板；SubjectUserSid 只表示操作者。空 SID、受保护值、重复字段、未知版本不建立关联。
- 历史补齐只查这四个动作族的既有 `(action_id, action_row)` 索引，单独固定水位、分批事务、可续跑。保留 action_row、原始材料及已有 v1 修复账目；同批身份冲突回滚，不任意选择一个主体。

字段依据：[Microsoft 4688](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4688)、[4732](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4732)，Sysmon 沿用项目已核对的官方 manifest 模板。

## 验证

- 正式库原审查水位内 42 条进程启动事件均为 Security 4688 v2。最小材料导出到忽略目录，所有修复写入新建内存库：42 条全部关联到 42 个历史启动主体，修复 31.22 ms，最大批次 31.16 ms。重复执行不增动作，原生创建时间新增数为 0，当前运行对象新增数为 0。
- 存储完整回归 234 项、服务 32 项、contracts 原有 281 项通过；随后新增进程身份命名空间专项通过。进程专项扩展至 6 项并再次通过，包含时间线详情关联验证、PID 复用、日志代际、乱序退出、同 PID 不同 GUID、父进程与新进程区分、无效身份、受保护值、全部支持版本、未知模板、导入隔离及六种组成员事件。冲突修复在旧关联为空时同步更新身份保护字段，详情仍能读到明确冲突。
- UI 模型、103 类状态展示、更新／检测历史、进程历史、来源分类检查通过。首次新增的重放测试曾使用旧 batch_seq，被协议正确拒绝；改为合法批次重放后通过，没有修改协议的顺序校验。
- 回放入口：`target/release/examples/process-history-replay.exe <最小材料.json>`。这不是正式库已经修复的报告，也不是带持续采集负载的服务性能结果。

## 尚未交付的范围
