# 0.2.43：检查凭证、处理进度与分类占用

## 实施范围

1. **共享清单与每轮检查凭证**：保留 0.2.42 的正文共享；新快照通过 `observation_sets / observation_members` 复用成员清单，每轮在 `observation_runs` 保存来源、范围、时间和序号区间。每个历史检查点及其原始内容仍然可以读取。
2. **压缩完成队列**：快照用批次进度游标加失败项列表表示处理结果，一批处理只更新一次游标。已有完成队列按每次处理上限分批搬到 `completed_work`，保存整数证据序号、原队列号、尝试次数及完成时间。事实、动作、失败和进度在同一事务提交。
3. **共享元数据字典**：来源、范围、成员标识在 `storage_strings` 存一次，用整数引用；版本、类型和可推导地址在读取时还原。已有证据引用表保留，未尝试重写整个大库。
4. **分类占用**：采集健康显示总文件占用和按类别展开的来源明细。分类计数在入库事务中维护，健康页不扫描历史正文。共享内容归给首次保存它的来源，且只计一次。

## 历史与兼容性

- schema 11 → 12 只增加表、索引、视图、触发器，不重写原始快照、日志或对象历史，不调整采集周期和保留策略。
- `all_evidence / all_projection_queue` 提供逻辑读取接口；原表继续保存旧格式和非快照输入。诊断 SQL 需要读取逻辑视图才能包含新快照。
- 队列进度、错误、统计随事务一起回滚；中途重启从已提交的批次游标继续。重试游标之前的结论依靠已有证据身份去重。
- 按序号统一分配快照区间及日志序号，分页水位不混用两套顺序。来源筛选直接定位批次头，避免展开全部历史成员。事件读取继续使用事件原表的地址索引。
- 旧版后台拒绝 schema 12；新版只读入口在旧库尚未升级时提示启动新版后台，不自行写库。
- 分类统计从升级后开始。此前历史不补扫、不估填为零；分类合计只包含新保存的采集正文，不包含旧历史、索引、其他辅助结构和 WAL。总文件占用继续包含数据库、WAL、SHM。删除共享内容的最后一次引用才扣除共享正文。
- 历史保留不变。完成队列压缩腾出的数据库页可供后续写入复用，不承诺现有数据库文件立刻缩小；未执行生产库 VACUUM 或清理。

## 性能对比

同一基准程序分别针对 Git 基准 0.2.42 与新版本构建，标准 `target/release` 优化构建。每组 100 个服务、60 次检查，中间一次停止并恢复；3 次交替配对运行。数值为三轮结果的中位数，数据库大小在 checkpoint 后记录，包含索引。

| 指标 | 0.2.42 | 0.2.43 |
|---|---:|---:|
| 数据库 | 11.15 MB | 6.05 MB |
| 首轮之后每轮增量 | 159,605 B | 73,033 B |
| 入库 P50 / P95 | 33.459 / 95.824 ms | 25.326 / 90.443 ms |
| 处理 P50 / P95 | 54.450 / 69.442 ms | 48.273 / 62.792 ms |
| 时间线 P95 | 2.999 ms | 2.771 ms |
| 状态对比 P95 | 14.792 ms | 15.289 ms |
| 处理健康状态 P95 | 0.209 ms | 0.351 ms |

数据库减少 **45.8%**，后续每轮增量减少 **54.2%**。检查点、6,000 个输入、600 个当前事实及 200 条变化保持一致。状态对比差约 0.5 ms，健康查询增加约 0.14 ms；均未出现数量级回退。基准未包含 IPC 和渲染，不能将合成数据的节省比例直接换算成本机每日增长；真实增长需更新后台后由现有监控继续观察。

可复现入口：`crates/storage/examples/compact-storage-bench.rs`，`scripts/check-compact-storage.py`。脚本拒绝复用输出目录，生成独立测试库，并验证语义一致、升级保留与旧版本拒绝。完整数据见同目录 `storage-receipts-0.2.43.json`。
