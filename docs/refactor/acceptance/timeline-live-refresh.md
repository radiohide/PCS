# 时间线持续更新修复（0.2.12）

日期：2026-10-19。界面、原生维护工具及下次启动的程序已更新到固定正常/debug 目录；当前增强后台保持 0.2.11 进程和原权限，没有重启或再次 UAC。

## 原因与修复

界面原先仅在 `collecting: true → false` 时刷新时间线。长时间采集期间、采集结束之后的对象处理，以及用户暂停期间产生的新记录，都可能错过刷新。现在以已提交的展示变化为信号，保留采集完成触发；兼容旧后台的材料计数及处理进度。暂停后恢复会主动读取最新内容，手动刷新保持原开关状态。自动页面读取至少间隔 15 秒，不重叠执行，间隔内的变化保留待刷新标记；新后台标记不变时不重复查询，旧后台按处理进度保守刷新，也受相同间隔限制。刷新复用当前页面入口，保留筛选与整体折叠模式。

新后台状态增加只读 `read_model_revision`，依据行动序号、展示代次与发布状态提供变更标记；它不启动采集、不建立任务、不占用采集写锁。当前保持运行的旧后台通过兼容信号工作。

正式库还存在两处随历史增长的扫描：每次入库的积压检查扫描整个队列索引；恢复来源关联时，行动证据子查询按 `subject_kind` 扫描大量无关引用。新增两个小范围索引：

- `projection_queue_pending`：只包含待处理队列项，仍精确统计所有投影的积压。
- `evidence_refs_action_address`：按具体行动证据地址和主体查询，不扫描所有行动引用。

两个索引由原有写入路径自动维护，后台启动也会补齐。原生 CLI 的 `install-read-indexes` 支持对已标记、结构为 10 的现有应用库在线安装；拒绝未知库、不创建空数据库，不迁移或重置展示规则、游标及历史。索引安装放在同一事务，失败回滚。数据目录和启动配置保持原样。
