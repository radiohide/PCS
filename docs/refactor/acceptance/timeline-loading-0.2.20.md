# 0.2.20 时间线加载优化

## 交付行为

默认每次读取 2 个完整时间组；可选 2～6 组和既有分组间隔，继续记忆选择。分类数量、全选/反选、折叠、历史变化与当前对象详情的含义不变。

1. **读取与显示重叠**：显示当前批次时预读取下一批。仅一笔预读取；沿用同一水位与游标，不并发扫描历史。失败可续读，离开页面或改变筛选后停止接收旧结果。
2. **独立传输批量**：时间线请求 400 条轻量卡片；后端上限 800 条、数据数组 4 MiB。超出字节预算时在最后已返回记录处继续，不丢记录、不生成空游标循环。其他查询与完整记录接口仍限制 200 条。超大单条返回明确错误，不静默截断结论。
3. **按需详情**：初始响应保留卡片全部语义输入，去掉原始来源大字段及事实时间等详情元数据。展开“记录详情”时按 `detail_id` 读取完整记录；成功结果在页面内复用，失败可收起再展开重试。名称、前后值、历史时间和结论不被裁剪。
4. **长列表节点释放**：超过 1,000 条启用窗口化。保留轻量行锚点与分类统计，视口上下 1,500 像素之外的卡片转为 HTML 文本缓存，释放其 DOM；回滚时恢复。打开的详情和键盘焦点保持挂载。离开页面与刷新释放缓存、监听器和观察器。

每 50 条仍是独立构建单元；首批先让出一帧，其后按约 8 毫秒工作预算让出主线程，避免快速机器每 50 条都空等整帧。单个构建单元耗时不能硬性保证小于 8 毫秒。

不更改数据库结构、展示投影版本或采集调度，不重建已有历史展示数据。旧后台忽略轻量请求字段时仍可读取完整响应，新的按需详情仅用于提供 `detail_id` 的后台。

## 性能证据

### 正式历史库，只读同一 SQLite 快照

使用 `timeline-load-benchmark`，两个顺序轮次，记录查询加 JSON 序列化耗时；不是 IPC 或整个界面加载时间。运行中的增强采集不变。原始样本仅在忽略目录 `target` 中。

| 模式 | 返回条数 | 查询次数 | 响应总字节 | 两轮总耗时 |
| --- | ---: | ---: | ---: | ---: |
| 完整记录，200 条 | 10,000 | 50 | 24,529,791 | 2,114 / 1,951 ms |
| 轻量卡片，200 条 | 10,000 | 50 | 17,904,513 | 1,826 / 1,499 ms |
| 轻量卡片，400 条 | 10,000 | 25 | 17,897,863 | 864 / 875 ms |
| 轻量卡片，800 条 | 10,400 | 13 | 18,644,915 | 669 / 627 ms |

400 条的数据量较完整响应减少约 27%；800 条这一行多返回 400 条，不是完全等量比较。最后一项查询遍历从先收集整页改为逐行预算检查，以限制解析期间内存；上表采样在该遍历调整之前，后续另有最终查询回归。

### 同一历史样本，旧版与新版实际界面回放

`measure-timeline-replay.cjs` 使用相同 10,000 条样本、相同 60 ms 模拟桥接等待、1440×1000 Chrome。用于隔离前端及请求次数影响，**不代替正式 IPC 端到端实测**。每种设置首次加载后再滚动两次，所有返回条数与分组数量完全一致。

| 每次组数 | 阶段 / 新增条数 | 0.2.19 | 0.2.20，400 条 |
| --- | --- | ---: | ---: |
| 2 | 首批 / 573 | 482 ms | 233 ms |
| 2 | 滚动 / 637 | 632 ms | 332 ms |
| 2 | 滚动 / 860 | 650 ms | 266 ms |
| 6 | 首批 / 2,070 | 1,418 ms | 531 ms |
| 6 | 滚动 / 2,564 | 2,001 ms | 633 ms |
| 6 | 滚动 / 2,674 | 2,620 ms | 799 ms |

加载到 7,308 条时，结果区 DOM 节点由 111,657 降为 8,671，减少约 92.2%；挂载卡片由 7,308 降至 18。记录、分类统计和时间组并未删除。此处测的是节点数量，不冒充精确内存字节。

另测 800 条：2 组首批 249 ms，后续 299 / 232 ms；6 组首批 515 ms，后续 782 / 866 ms。小样本有波动，800 条没有稳定的界面优势，默认采用 400 条以减少首批等待和缓冲。

## 边界与上线

- 仍保留每条记录的轻量锚点和文本缓存，内存并非恒定；打开的详情也会保留节点。优化的是大列表的渲染与 DOM 占用。
- 离屏卡片恢复依赖 IntersectionObserver；支持现有 WebView2/Chrome。不支持该 API 时正常显示全量节点。
- 正常与 debug 构建目录保持不变，启动配置与正式历史保留。
- 0.2.20 新增后端读取接口，需要启动新版增强后台才全部生效；已有 0.2.16 的一次性 Windows UAC 授权不用于启动新的管理员进程。
- 正式后台替换及完整 IPC/WebView2 复测记录将在获准完成后补充。本轮不宣称解决既有后台写入等待，也不关闭先前尚未完成的长时间压力验收项。
