# SIHost 运行时模块文件跟踪：首段实施验收

日期：2026-10-12。状态：基础链路已通过隔离验收，整个 SIHost P0 与产品里程碑仍未完成。

## 已实现的行为

从当前账户、当前会话的精确进程名称发现实例，原生读取 PID、建立时间、实际程序路径和模块清单。按进程独立提交；不把发现失败当退出、不把空目标当健康。模块枚举不执行 DLL，也不等待文件验签。SIHost 预设可关闭或修改。

成功模块清单建立独立的自动文件集合，保留进程/模块关系、观察时间、初始磁盘基线与后续有效检查。自动集合不改写手动文件名单。相同路径被两个进程加载时只安排一份文件检查；目标退出后继续跟踪已经观察的文件，停用目标则停止监听。

后台直接使用非递归原生目录通知，只匹配已知文件，排除最后访问时间变化；通知合并、失败退避、固定补查和监督进程超时限制工作量。文件变化不触发全量模块重采、其他文件复核或诊断；页面刷新只查询证据。监听及安全撤销按 [ReadDirectoryChangesW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw) 和 [CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex) 的生命周期要求实现。

复核磁盘存在性、卷/文件 ID、大小、写入时间、属性、Owner/DACL、版本、SHA256、嵌入/本地 Catalog 签名及基础 PE 结构。改名通知只有核对原文件身份后才增加新路径关系；同路径替换保留新旧身份和初始基线。结构检查仅覆盖 [PE 基础头部及节区文件范围](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)，不是完整加载器验证。

原始检查及模块关系通过同一数据库的 `source_readings` 查询；稳定且存在的文件复用 `file.watched_file` 的卷/文件 ID 身份。原始条目身份包含实际文件身份，防止同路径新文件复用旧对象的来源绑定。ACL 正文保存在主文件字段和原始记录；此来源暂不展开独立 ACL 子对象。未读取、写入中、超时或路径缺失不冒充物理文件已删除。

新增桌面“SIHost 监控”页，展示监控配置、最近目标观察、覆盖及待复核情况、模块关联文件变化、发布者类别、签名、PE 检查及完整前后材料。第三方候选/归属未知优先安排检查；微软签名不等于产品归属或功能健康。

## 运行隔离

- IPC 以实际数据目录的文件系统身份和当前用户 SID 派生；路径别名不能绕过重复实例保护。
- 桌面默认新目录为应用本地数据目录的 `native-v1` 子目录；显式 `PCSCOPE_DATA_DIR` 选择目标实例。桌面请求、后台启动、权限替换使用同一固定端点，探针必须明确指定目录。
- 后台与写入类 CLI 使用新程序入口；已有未标记数据库在写入/升级前拒绝。重解析文件和多硬链接数据库被拒绝，避免不同目录共享一个写入库。新库的自身标识、设置及状态可以重启回读。
- 本轮使用新建隔离库。没有启动正式后台、没有操作正式库、没有弹出 UAC、没有修改系统审计或日志配置；测试只对可控宿主和夹具 DLL 制造变化。

## 实机夹具与证据

测试入口：[文件监控验收](../../../scripts/test-sihost-file-monitor.ps1)、[实际后台隔离验收](../../../crates/service/examples/daemon-isolation.rs)。汇总材料：[验收指标](SIHost-runtime-metrics.json)。原始测试库、后台 stderr 和结果保存在指标内对应的 `target` 目录。

| 验收场景 | 结果 |
| --- | --- |
| 两个可控宿主真实加载同一原生 DLL | 模块正向采集并投影；两个进程关联保留，文件集合去重 |
| 原文件改名，原路径放入新版 DLL | 改名文件身份与初始基线一致；替换文件获得不同对象别名；宿主继续运行 |
| 将原路径的新 DLL 写成损坏夹具 | SHA256/签名/基础 PE 异常进入证据；不报宿主退出或模块已卸载 |
| 删除原路径文件 | 路径缺失可查；保留旧基线，不伪造内存损坏或物理文件删除结论 |
| 50 次无关文件写入 | 两秒观察窗没有新增文件检查记录；不触发模块全量循环 |
| 宿主退出、后台关闭，再恢复文件并重启后台 | 无目标进程时仍检查历史已知文件；初始基线及两个关联保留 |
| 手动名单与自动名单共存 | 手动配置与修订保持一致 |
| 两个实际后台、重复启动、同账户替换、关闭其中一个 | 不串连接、不串设置、不影响另一实例；重启设置回读通过 |
| 误传未标记旧库夹具 | 拒绝写入，主文件字节前后一致；自身新库重开及硬链接拒绝通过 |
| 持久退避、1000 次重复通知、原生通知撤销 | 重启仍尊重退避；单文件只有一个待办；原生监听读写与清理测试通过 |

完整工作区回归 368 项通过，之后最终变更的针对性回归及旧库保护测试通过；22 个 Node 检查、无 Git 环境的等价文件归属检查通过。桌面构建通过，仍有既有 MinGW manifest 合并警告。Strict Clippy 的既有 14 条问题仍未关闭。

## 当前实现预算

| 工作 | 当前策略 |
| --- | --- |
| 模块观察 | 独立后台线程，每 60 秒；单次监督 20 秒；不复用整个状态域周期 |
| 自动范围 | 最多 4096 文件、128 父目录、每文件 64 个历史进程关联；未确认改名候选另限 64 项 |
| 文件检查 | 每个监督进程检查一文件，5 秒超时；调度批次最多 4 文件或 2 秒，单调用可超出批次预算 |
| 变化合并 | 同文件静默 1 秒后复核，持续通知最多等 5 秒；不监听最后访问时间 |
| 补查 | 元数据 300 秒；内容/签名 3600 秒或相关变化后复核；启动复查元数据，旧校验到期或身份变化再完整复核 |
| 权限/读取失败 | 文件退避 60、120、240、480、900 秒并持久保存；不自动 UAC 或回退 PowerShell |
| 检查材料 | 每次实际文件检查保存完整原始材料；尚未启用依赖引用的精简摘要优化 |

空闲 CPU 数字来自单次 15 秒窗口、20 个逻辑处理器、夹具已建立基线后的后台主进程，具体值见指标。它不包含初始化校验全部子进程的总成本，也不代替 24 小时、多目标、大范围和多机器性能验收。
