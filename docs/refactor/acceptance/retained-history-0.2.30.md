# 更新、检测历史与退出取消：0.2.30

2026-10-22。继续实施日志与对象关联方案；本批覆盖更新历史、Defender 检测，以及本次替换后台暴露的退出等待。正式运行状态与离线结果分开记录。

## 功能

- Windows 更新以 UpdateID＋Revision 建立 `software.update_history_subject`。安装、卸载、失败、取消和多次尝试分别保留；已有 action_row、时间、原始材料不改号、不删除。当前已安装组件仍由 QFE 清单独立维护。
- Defender 检测不再直接 Skipped。DetectionID＋ThreatID 标识检测历史；首次检测与有明确时间的后续处理分别生成动作。同一条检测重复采集不重复记录，清单不再列出也不生成清除动作。缺身份的材料保留独立动作，默认 false 的 ActionSuccess 不会制造处理失败。
- 两类主体详情显示“历史记录”。时间线使用“安装失败”“卸载成功”“威胁已隔离”等具体结果，不附带泛化影响说明。内部标识留在详情。
- 历史补齐沿既有后台维护线程执行，按来源的证据索引取材料，独立固定水位、游标可续跑；每批最多 128 条、目标 40 ms。新采集与回放复用同一条动作入口，已有更新动作会原位补关联。真正修改关联时保存原值、新值与证据地址。

字段含义按 Microsoft 的 [IUpdateHistoryEntry 属性](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/aa386472%28v%3Dvs.85%29) 与 [MSFT_MpThreatDetection](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/defender/msft-mpthreatdetection) 核对。未知状态码保持一般处理记录，不推断成功或失败。

## 退出与后台整理

收到关闭请求后，先通知派生数据线程停止，再等待采集写入结束。SQLite 取消回调只安装在该线程持有存储锁的维护操作期间；退出该操作时移除，不把取消信号带到后续采集写入。未提交的派生事务回滚，游标保留，下一次启动续跑。

历史采集范围整理的事件分支改从单条证据的引用查对象，再按完整绑定键确认。旧查询先取同来源、同动作类别的全部绑定，数量随历史增长。新增 20,000 条同类别干扰绑定的 SQL 步数回归；精确查询通过。沿用原有独立范围整理游标，未增加全库索引，也不重置它。

正式库只读、同一已关联特殊权限事件，精确查找 30 次：p50 0.060 ms、p95 0.154 ms、最大 5.174 ms，每次返回同一个对象。查询计划使用证据地址索引、对象主键和完整绑定唯一索引。这是单项读取基准，不是后台或界面整体性能结果。
