# 总览查询拥堵与来源统计验收

日期：2026-10-14。开发包 `dist/overview-fixed`，debug 桌面 SHA256 `AAF31ECE3BF0C832240CD7AF149AA3770E3769C2AF008E1CBDDFAD6299E5E6D2`，后台 SHA256 `985F57369D64F76DF511C733017B23333E19D462261333D8340E571A89194DCF`。

## 原因与修复

总览用 Promise.all 同时发出四个模型查询，服务仅提供两个读槽。新增窗口内串行队列并共享相同在途请求；连接检查和配置操作不进入历史查询队列。总览计数需要的对象查询采用最近观察排序，避免无意义的全局名称排序。增加渲染代次校验，旧的总览响应不覆盖新页面；查询失败提供“重新读取”，不再引导重启后台。

来源采集报告每次将 evidence 与 projection_queue 全量关联分组，实机两表各约 361 万行，已有覆盖索引也无法在 6 秒内完成。新增派生汇总 coverage_projection_counts，首次由写端在一个事务中建立，之后通过两表触发器与原始变动同步提交。查询只读取小汇总；回滚、重放、两种清理顺序、证据地址变化及多个处理队列保持与原 INNER JOIN 完全一致。旧数据库尚未建立汇总时沿用原查询，不制造零失败或零待处理。原始数据、采集设置和两查询槽限制保留。

首次建立需要扫描历史，后续启动无需重复建立。此表为可派生统计，不改变原始证据或对象合同。升级期间不能将尚未提交的汇总当作已经就绪。
