## 2. 两条贯穿全组的约束

- **不靠破坏真实机器制造样例。** 每一个故障都注入到本模块自己创建的库里（临时目录或内存）。计划禁止「通过实际清空用户系统日志制造样例」，这条禁令背后是一种更广的习惯：**需要主机处于特定状态的测试，是没人能重复的测试**。
- **用「什么幸存下来」判断故障。** 失败的事务由没出现的行来判定，中断的进程由下一次运行看到什么来判定，重试由它没有重复什么来判定。

## 3. 遗留问题

1. **「字段结构变化」未覆盖。** 协议里有 `structure_version`，但**没有声明结构变化的机制**：采集端不会说「这个来源的结构变了」，证据行也恒为 `v1`。因此「结构变化时会发生什么」无法检验——不是测失败，是**被测能力不存在**。要让来源能声明结构版本并在解析层响应，属协议扩展，不在本步。
2. **中断是「事务不提交」，不是真的杀进程。** 真实强制退出还涉及 WAL 恢复、未刷盘的页与操作系统层面的锁；这些在临时文件库上只被间接覆盖。**真正的强制退出属 S31 实机验证**。
3. **并发只测了「一读一写」。** 计划提到的「投影并发」还包括多个投影彼此、以及投影与清理之间的并发。当前架构下投影是单写入方（服务持有一个写连接），因此多投影并发不是当前设计的一部分；**投影与保留清理的并发**（清理在投影读取队列时发生）未测，属 S31。
4. **本步未产生缺陷修复记录。** 七项故障注入**全部通过、未发现新缺陷**——这与前几步不同，值得说明：这些路径大多在 S05–S08 已被测试覆盖，本步把它们集中到同一处并按计划的场景逐条对照。**没有发现缺陷不代表已验证充分**，见第 2、3 项的范围限制。
