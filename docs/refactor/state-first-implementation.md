# 状态展示整改：第一批实现与验证

日期：2026-10-13。目录版本：1.2.2。完整范围仍以 [整改方案](state-first-remediation-plan.md) 和 [224 项清单](state-first-items.md) 为准。

本批已修改源码、构建匹配包并更新正在运行的预览程序，目标是让已采到的状态直接显示出来，同时修正会造成错误归属和状态倒退的基础问题。**开发包为 `dist/state-first`，这次交付不代表 SP01–SP09 全部完成。**

## 已实施的内容

| 范围 | 改动 | 实际边界 |
| --- | --- | --- |
| 101 类对象 | `model/presentation.json` 声明类型名称、主要属性、状态与值解释；后端摘要和界面读取同份配置 | 有展示规则不等于该类所有原始字段都已承接；缺失字段不伪造 |
| 列表、详情、时间线与比较 | 共用按类型的格式器；主要位置显示业务状态，技术名称与原始值保留在折叠详情 | 未识别枚举、受保护值与读取失败有明确短提示 |
| 电源计划 | “平衡”是计划名称，“正在使用”是状态；预设 GUID 与名称同时匹配才用中文别名 | 自定义名称保留；未选中不等于禁用 |
| Windows 防护 | 策略写入配置字段 `real_time_configured`；运行来源写入 `real_time` | 旧策略记录按明确来源解释；不把启用设置说成正在防护 |
| 身份绑定 | 限定类型、机器、安装和作用域；计划任务使用完整任务路径；10 个复合来源按子对象身份绑定 | 既有错误历史保留，新观察建立正确关系；未进行整库强制重放 |
| 字段时序 | 迟到记录不替换较新名称/状态；缺少字段的后续采集不抹掉已有有效值；历史区间保持时间顺序 | 读取失败的影响仍需结合来源健康显示 |
| 事件身份 | 事件记录号包含日志代际；严格匹配对象键；事件归属与对象重新出现分开处理 | 旧删除/重复删除不创建或复活当前对象；离线导入默认只保留历史事件 |
| 明确事件更新 | 原始事件保留在时间线，并更新它明确给出的字段，不额外生成一条重复的快照变化 | 精确规则见下表；不是全部 108 条分类都能更新状态 |

10 个按子对象绑定的来源：账户组、账户权限、文件元数据与权限、网络访问配置、系统策略、浏览器策略、环境变量、防护策略、登录启动配置、.NET 运行环境。完整列表的“未再发现”判断仍只对已有完整性规则的组成员/账户权限启用；不能由某条原始记录少一个子项就推断删除。

## 本批日志规则

所有规则必须同时符合通道、提供程序、事件 ID、Windows 事件版本 0、字段结构和有效发生时间。未知版本保留事件，不写当前字段。

| 日志 | 输出 | 当前状态写入条件 |
| --- | --- | --- |
| Security 4722 / 4725 | 账户启用 / 停用 | 合法 TargetSid 对应账户；写入 enabled |
| TaskScheduler 100 | 任务开始执行 | 完整 TaskName 与有效运行实例标识；只更新 last_run，不改变任务 enabled，也不宣称成功 |
| System / Service Control Manager 7036 | 服务运行 / 停止 | 显示名称在同一机器、安装和范围内唯一匹配已知服务；只接受明确状态词，写入 state |
| TerminalServices-LocalSessionManager 24 / 25 | 会话断开 / 重连 | 已实现语义与字段意图；当前投影没有事件所属启动周期，故暂只显示事件，不更新当前会话 |

任务结束、单个动作结果、其他提供程序和未知版本未在本批扩展为状态转换。服务无法唯一对应时仍保留明确服务活动；不会新建一个以显示名冒充系统名称的服务。

## 验证记录

- 已有 8 类实机保存样本用于前端回归：电源计划、防火墙配置集、服务、网络连接配置、防护状态、系统版本、安全启动、可选功能。样本回归不冒充本批实时采集验收。
- 目录与来源处理入口对账、既有事件语义、查询消费及 16 项相关 Node 检查通过。101 类型规则、保护值和未知值、预设名称、防护来源隔离、时间线/比较检查通过。真实浏览器 23/23 场景通过，无页面错误和采集调用。
- 契约 265 项通过。存储共覆盖 143 项：全量首轮 141 项通过、2 项失败；修复后复跑 141 项（避开刚通过的两项未改历史清理压力用例），140 项通过、1 项失败；修复冲突的有效时间后，最终受影响的投影模块 23/23 全过。失败经过保留，不写成一次全量绿灯。桌面 2/2 测试通过。
- 最终回归覆盖身份边界、完整任务路径、多子项绑定、迟到状态/名称、互补快照、事件更新、同秒冲突的保持与恢复、日志代际、重复删除和导入隔离。服务日志只呈现明确结果状态，不捏造前值；普通快照的前后值要求保持不变。
- 自动审批服务的模型容量问题曾阻止两次编译请求；随后通过相同权限正常重试，未绕过审批。最终后台/采集程序、探针、桌面构建成功。原有 MinGW 多 manifest 链接警告仍归 RW13，不当作本批新增已解决事项。
- 新包 29 个文件的 SHA256 已核对，见 [包清单](acceptance/state-first-artifacts.json)。通过同账户 UAC 更新原增强后台，旧后台正常退出；没有强制结束进程，没有重写原始材料或更改系统审计。
- **实机 19 次只读 IPC 请求通过**：新后台 PID 18884、增强权限、原开发数据目录；默认列表 1553 ms，8 类列表/详情 42–264 ms，8 类均有主要信息。新捕获再次通过前端状态语义检查。新桌面 PID 5020，窗口标题 PCScope、响应正常；启动器已指向新包。
