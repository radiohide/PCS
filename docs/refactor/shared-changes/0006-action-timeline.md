# 0006 查询契约新增跨对象时间线

| 字段 | 内容 |
| --- | --- |
| 共享入口 | 公共契约（`crates/contracts/src/query.rs`） |
| 整合责任人 | 基础数据线 |
| 提出工作线 | 查询与界面线（S23 实施时间线页时发现） |
| 变更类型 | **兼容性新增**（新增一个请求变体与其筛选结构；既有七个请求不变） |
| 影响的工作线 | 查询与界面线（新增一个查询可调用）、迁移验证线（固定响应集与检查） |

## 问题

R05 定义了七类请求，其中与动作有关的是 `instance_actions`——**按实例**取动作。而计划第 8 节要求时间线「按真实对象与动作展示」，来源与插件作为独立筛选。

两者对不上：问到「这个对象发生了什么」有答案，问到「**发生了什么**」没有。时间线页因此无法只靠契约实现——要么把全库实例逐个查询再合并（不成立，且拿不到未归属动作），要么前端自己拼一套响应（正是 R07 禁止的「前端自定一套 DTO」）。

## 旧结构 / 新结构

| | 旧 | 新 |
| --- | --- | --- |
| 跨对象时间线 | 无 | `QueryRequest::ActionTimeline(ActionFilter)` |
| 未归属动作 | 只能在按实例查询里看到（而它们不属于任何实例，因此看不到） | 默认**包含**，由 `include_unassigned` 控制 |

`ActionFilter` 的字段：`action_id`、`category`、`type_id`、`source`、`instance`、`include_unassigned`（默认真）、`since`、`cursor`、`limit`。

## 兼容性

纯新增：既有七个请求与其响应结构未变，`response_shape().queries` 增加一个名称。固定响应集由 `query-contract.rs` 重新生成，新增内容仅为该名称（一行）。

**默认包含未归属动作**是刻意的：一条无法归属的事件仍然是发生过的事，默认隐藏会让时间线看起来完整而实际不是。需要只看已归属动作的调用方显式关闭。

## 样例变化

| 位置 | 变化 |
| --- | --- |
| `model/query-samples.json` | 重新生成；新增 `action_timeline` 样本（3 条动作、1 条未归属、带下一页），`shape.queries` 增加该名称 |
| `crates/storage/src/query.rs` 测试 | 新增 4 项：排序、未归属默认包含与显式排除、筛选与分页（含跨查询游标被拒）、`since` 下界 |
| `docs/refactor/query-contract.md` | 请求表补一行 |
| `apps/desktop/ui/model-view.js` | `page.next_cursor` 由可选路径升为必需路径 |

**新样本同时补上了固定响应集原有的一处空白**：此前 12 个样本里**没有任何一个带下一页游标**，因此 `page.next_cursor` 被登记为「契约定义但样本未覆盖」。现在它被真实覆盖，该条从可选清单移回必需清单——这让声明更严，而不是更松。
