# PCScope 采集鲁棒性与可读性实施方案

日期：2026-10-19。方案版本：第二版。代码基线：产品 0.2.13、模型 1.2.6、数据库结构 10。状态：实施中，首批进展见[0.2.14 实现记录](acceptance/robustness-readability-first-batch.md)，性能整改见[0.2.15 验收记录](acceptance/performance-0.2.15.md)。

目标是让采集在失败、中断、重试和数据积压时仍保持正确状态，并让用户直接看懂对象、变化和影响。沿用原生采集、原始材料留存、后台解析和预计算展示的架构，分阶段增强事务、身份、规则与查询契约。

产品输出以简洁、明确、可行动为标准。有效证据支持什么就直接写什么：运行中、未加载、已停用、安装失败。复杂性留在后台规则和测试中，不能转成每张卡片的解释负担。默认每条记录突出一个对象、一项变化或状态；必要上下文和时间辅助说明，影响说明仅在有具体价值时增加。

本方案与[测试方案](robustness-readability-test-plan.md)配套。完成条件是每项任务通过对应验收，不能以文档完成、源码覆盖或测试总数代替功能完成。各批实际代码、测试和部署范围在实现记录中单独登记。

## 产品标准

以下标准优先约束后续状态规则、页面文案和验收：

- 有有效结果，就直接写“运行中”“未加载”“已停用”，检查时间放旁边。
- 后台短暂延迟不打扰用户；确实影响判断时，才提示哪项信息停止更新。
- 证据足够就明确给结论；检查失败就说明失败范围和恢复办法。
- 不让每张卡片反复解释“不代表什么”“不能确认什么”。

验收要检查用户能否一眼看懂对象发生了什么，而不只是技术上措辞无误。默认页面回答“哪个对象、发生了什么或现在怎样、是否需要处理”；解释依据供展开查看。

实际变化和采集问题分别表达：服务正常停止显示“已停止”；只有更新链路出问题才提示“服务状态更新失败”。后台已有稳定结果时不因一次重试改写成“未知”，没有证据支持的成功或故障也不强行下结论。

## 采集和发布契约

### 一轮采集的边界

完整性单位为“来源＋逻辑范围＋配置版本”的一次采集，不要求全机所有来源同时完成。逻辑范围保留机器、安装实例、用户、安全上下文及具体提供程序；分片编号是传输信息，不能代替业务范围。CNG 某提供程序失败只影响该范围；其他提供程序可独立发布。

采集调度器在持久事务中分配 `run_id`、`run_seq` 和执行代次，并把捕获的配置版本传给采集器。来源、范围、序号绑定到监督程序启动的执行实例，不能仅信任消息自报身份。每个逻辑范围的序号递增；传输重试沿用原身份并重发不可变缓存块，重新读取系统状态必须取得新序号。计数器溢出应拒绝启动并报告维护错误，不能回绕。恢复旧备份时更换采集执行代次，阻止遗留进程写入。

范围版本包含选择项、监控名单、用户及权限能力变化。普通权限、增强权限或监控范围改变后建立独立基线，并明确退役旧范围；范围退役不是对象删除。对象层依然通过稳定身份合并各有效来源，避免升级权限造成大量重复对象。

### 原始材料与完整发布

新增能力协商，支持带清单的分块快照：清单声明来源、逻辑范围、配置版本、序号、预期分块、条目数、总字节数与摘要。分块可重复发送；内容一致时幂等，身份相同而内容不同则拒绝本轮。终止标记、分块和摘要全部核对后才允许发布。

建议增加以下逻辑结构，具体表名在实现时统一到存储命名规则：

| 结构 | 主要内容 | 约束 |
| --- | --- | --- |
| `collection_runs` | 来源范围、执行代次、序号、配置版本、清单摘要、开始结束时间、状态 | 同范围同代次同序号唯一，完成身份不可复用为其他内容 |
| `collection_parts` | 分块编号、原始材料地址、摘要、条目数、长度 | 分块唯一；总量受单轮预算限制 |
| `collection_scope_heads` | 最近接收完成轮次、模型发布轮次、展示发布轮次 | 发布指针与完成标记同事务更新，只能前进 |
| 派生版本记录 | 对象、字段、行动、绑定和摘要所属代次 | 未发布代次不进入普通查询 |
| `evidence_payloads` | 大正文分块、保护方式、长度和完整性摘要 | 全部可靠保存后才能作为已接收证据 |
| `replay_jobs` | 来源、证据范围、旧新规则版本、游标、重试状态 | 同修复任务幂等，重启不从头开始 |

分块和大批次派生结果分批写入未发布版本，短事务释放写锁；最终用短事务切换完成指针。不能把整个大来源放进一个无限增长的写事务，也不能只保证原始材料完整、随后让逐条模型修改直接暴露半轮结果。模型和展示查询应各自读取完整发布代次，同一个响应固定其代次；跨来源按各自有效轮次汇总，不宣称全机瞬时一致。

同一对象可能由多个来源提供字段，需保留按来源／绑定版本化的贡献。查询在一个读取快照中固定各来源的已发布版本；汇总缓存记录所依赖的版本集合，发布前检查依赖是否改变，变化则重新合并受影响字段。A 来源的旧构建不能覆盖 B 来源刚发布的新结果，对象摘要和计数使用同一组依赖版本。

每个来源的投影保持轮次顺序，分块可并行读取，发布序号只能前进。轮次具有超时、撤销和废弃终态：N 失效后，N+1 可按最近有效发布轮次比较，不永久等待 N；N 后来返回只保留历史材料。该规则用于快照，事件检查点仍不能越过未保存原文。失败轮次不阻挡无关来源。配置版本改变、执行代次过期、材料超预算或摘要不符时，本轮不发布，保留上轮已发布结果与具体错误。

接收 ACK 仅表示原始材料和接收位置可靠提交，不表示解析和展示已完成，后两项使用独立进度。监督程序从整轮内存缓冲改为有界流式接收；分块建议从 256 KiB 起验证，单行保持 1 MiB 上限，单轮初始沿用现有 64 MiB 总输出预算，更大来源另做预算验收。计算总预算时包含暂存、WAL、大正文、派生版本和备份。旧派生版本按活跃读者、游标期限及保留策略回收，不能无限积累，也不能删除仍用于读取或恢复的代次。

快照缺席只能由已经完整接收且完整解析的适用范围得出。某个子集合解析失败时，保留该集合旧结果，标记该集合未更新；禁止把它解释为一个空集合。健康子范围可以按事先声明的独立范围发布，不能在遇错后临时缩小范围却仍宣称原范围完整。

### 旧协议和时间

保持现有 v1 读取能力。已知原生 16 分片来源由监督程序按声明收齐后封装成本轮；真正单消息来源为单分块轮次；未知分片布局不猜测完整性。新分块能力通过明确协商启用，旧后台不得忽略未知类型后继续报告成功。旧前后端组合先做能力检查，安全降级显示旧结果或提示版本不兼容。

旧分片范围到逻辑范围建立可审计映射，原证据地址保持不变。只有能够证明属于同一完整旧轮次的材料才接管为新基线；不能拼接各分片不同时间的最新记录。无法恢复完整旧轮次时，用首次新完整轮次建立基线并保留旧历史。接管时显式退役旧活动绑定，不制造批量新增或删除，也不让旧分片绑定永久阻止之后的真实缺席。

顺序由可信调度器分配的序号和执行代次决定，时间用于解释发生区间。统一校验时间格式并转换为 UTC，保留原始文本和精度。晚到旧轮次只进历史材料，不替换当前基线；同一序号冲突不能靠“后到覆盖”解决。系统校时或时钟倒退时仍按采集序号处理；不能生成结束早于开始的区间，此时显示检查时间并在详情保留时间异常。

跨来源日志没有共同序号时，依据可靠事件时间、启动周期、对象身份和明确状态规则合并。缺少可比顺序时记录冲突或保留现有有效状态，不能用入库先后强行决胜。

### 大记录与坏材料

小消息继续使用受限 JSON 信封。大正文按有界块传送并保存在应用数据目录内的证据存储，优先与 SQLite 事务统一管理；前端只读摘要和按需详情，不自动展开全文。路径、大小、分块数和总量由后台校验，不接受采集器提供任意外部文件路径。

处理顺序为“正文完整持久保存 → 事件元信息和证据引用入库 → 检查点提交”。解析失败不妨碍已经可靠保存的原始事件推进接收断点；失败项进入隔离队列，其他事件继续解析。若磁盘满、权限不足或超过证据总预算而无法保存原文，则保留断点、停止该通道并退避，不能为了继续读取而丢掉这一条。

分块摘要验证实际传输和保存的字节；事件重读去重另按可信来源、epoch、记录身份和原文语义核对。相同 XML 再次独立加密后的密文可不同，不能据此判原文冲突。语义比较在本机保护边界内完成，必要的稳定指纹使用本机密钥保护，不向 UI 暴露敏感明文摘要；相同事件身份而真实原文不同仍拒绝冲突。快照差异继续使用现有受保护值语义比较。

隔离材料不自动变成正常事件；错误、重试次数和待修复原因可查。只有未引用且超过保留期的未完成分块可回收；完成证据沿既有保留策略处理。加密、敏感值遮蔽、当前账户保护和 UI 展开权限不因新格式放宽。

## 对象身份和完整变化过程

W03 复用现有身份策略，增加“绑定存在状态”和完整观察代次，不用显示名称作主键。变化比较使用类型化的语义值；集合按成员身份比较，数字、时间、路径及大小写按具体字段协议规范化，密文随机性不产生变化。

| 场景 | 实施规则 | 对用户的结果 |
| --- | --- | --- |
| 首次基线 | 建当前状态，不制造安装或创建记录 | 可在采集历史查看首次基线 |
| 后续首次出现 | 从有效空集合到有对象，形成出现行动 | 首次记录到此对象或相应运行／登记状态 |
| 离开后再现 | 同一稳定身份保持对象历史，形成独立再现行动 | 再次检测到此设备、再次记录到此项 |
| 确认终结后身份复用 | 按类型的代际规则建新实例；PID 必须包含创建时间 | 旧进程结束，新进程独立显示 |
| 父记录内成员变化 | 对已确认完整的子集合单独做差分 | 成员加入／移出，不把父对象反复新增 |
| 驱动版本替换 | 设备身份不变；旧绑定离开，新绑定加入；版本可并存时不强配替换 | 设备驱动版本变化，保留包与绑定各自状态 |
| 多来源或多个角色 | 各绑定独立有效；一处离开不删除其他有效绑定 | 只显示实际移除的登记或角色 |
| 监控范围变化 | 更新覆盖范围，保留对象最后结果 | 已暂停监控，不写文件已删除 |
| 短生命周期对象 | 快照保留所见，日志补充启退；无日志能力时保留范围限制 | 不为两次检查之间未观察到的过程补造事件 |

行动使用稳定发生身份，包含证据地址、转换类型和对应绑定／代际；同材料重放不能增加重复行动。多个来源描述同一次操作，只在可靠操作 ID、对象身份及阶段匹配时合并证据，不能按同名或相隔 30 秒认作一次操作。

## 日志解析与状态更新

W04 为事件规则声明提供程序、通道、事件编号、版本、必要字段、对象身份、动作、结果和可更新字段。原生采集器负责保留结构化字段和 XML，后端按规则决定动作；前端不补做事件归属。

首批修复 Sysmon 1/5、6/7、3、11/23/26 的生产路径，分别检查进程、驱动／模块、连接和文件事件。使用 ProcessGuid 等可靠身份时，需先落实它与本地进程实例的绑定规则；不只凭 PID 合并。文件事件继续受监控名单约束。缺少身份的动作仍可作为未关联历史显示，不能凭空补当前对象。

明确的服务启停、会话结束等事件在身份和顺序有效时可以直接更新相应字段，不强制额外轮询。操作开始、阶段结束、成功、失败、取消、回滚分别处理；“结束”不能自动成为“成功”。没有结束证据的操作保留已知阶段，不设超时自动成功规则。

驱动安装过程单列实现：增加 SetupAPI 安装记录的增量读取和解析能力，处理轮转、编码、区段未结束、设备／包标识、重启要求与回滚；这是新增功能，当前不能算已实现。新增来源、开关或分类时同步更新目录、归属和覆盖分母，不强行维持基线的 133／225 数字。Windows Update、MSI、任务等用各自操作标识关联阶段。缺少可靠操作身份时保留独立事件，不能强凑开始／结果对。

23 个通道和 109 条分类逐项标记为“已解析动作”“仅原始日志”“不适用于对象动作”或“缺少环境”。仅原始日志必须写出原因、所缺字段和后续任务，不把读取成功记作动作解析完成。

## 当前状态和展示语义

### 状态时效

新鲜度按字段或状态组判断，不能用对象名称、资源读数或其他字段刚更新的时间替代运行状态的检查时间。查询返回 `effective_at`、`last_success_at`、来源范围、发布轮次、当前更新情况和原因；这些属于兼容扩展字段，旧前端可忽略，旧后端缺失时新前端保留已有检查时间并避免虚构时效。内部可细分状态，默认界面只在信息时效确实影响判断时提醒；一次读取失败但上次结果仍在有效期内，不把对象统一降级成“未确认”。

为每个状态来源声明检查策略。周期来源的建议初始过期门槛为 `2 × 实际配置周期 + 本轮允许耗时`；事件驱动来源使用订阅健康和最近有效复核时间；仅历史日志的来源不套用周期阈值。具体值写入来源策略并由性能阶段校准，不能所有对象统一“五分钟过期”。

多来源字段声明权威来源和允许的替代关系，不能任意取最新一条。时效在查询时轻量计算，返回 `server_time`、`valid_until` 或 `next_refresh_at`，不每秒改写全部摘要。前端用单一有界计时器和现有请求队列在时效边界重查；即使没有新材料且 `read_model_revision` 不变，已打开的对象列表和详情也必须从当前状态转为上次状态。补齐总览、时间线中的状态入口、系统对象列表及展开详情的更新，保留筛选与展开位置。暂停刷新、隐藏窗口、休眠和重连分别处理，恢复时先核对连接和状态，不瞬间生成全局故障。

| 情况 | 主状态 | 辅助信息 |
| --- | --- | --- |
| 有及时有效结果 | 当前状态：运行中／已加载／已启用 | 最后检查时间 |
| 一次失败或短暂处理延迟，上次结果仍有效 | 保持状态值及检查时间 | 默认不增加卡片警告；后台重试，失败详情可查 |
| 持续失败或已经超过该状态的有效期 | 上次状态：运行中 | 上次成功时间；在相关范围集中提示更新失败和恢复操作 |
| 用户暂停该范围 | 保留状态值及最后检查时间 | 已暂停检查；不标成对象异常 |
| 只有历史日志且不能形成当前结论 | 历史事件照常给出明确动作 | 进入当前详情时简短显示“暂无当前状态”，不重复添加到历史卡片 |
| 原始数据新但解析或展示明显落后，影响当前信息 | 保留已经发布的状态 | 状态栏集中显示“正在更新，已更新至……”；仅历史回补不触发当前状态告警 |
| 多来源有一条新鲜的有效依据 | 使用该依据得出的状态 | 失败来源问题放到相关详情或状态栏 |

采集、模型和展示分别记录“已处理的采集轮次／接收序号”与其采集时间；历史事件的发生时间不充当处理进度。长时间没有变化且检查成功时仍然是新鲜状态，不要求必须产生新时间线。

### 名称和信息层级

默认卡片保留名称、对象类型、动作或状态、必要上下文和时间。模块显示所属进程，如 `pdh.dll · sihost`；不同目录存在同名文件时补最短区分路径；同名进程多实例需要区分时再显示创建时间。内部标识、完整路径和原始字段默认折叠，但在详情和复制操作中可得。

名称优先级为可靠系统显示名、来源提供的文件／产品说明、精确匹配字典、文件名或对象类型加必要上下文。字典记录匹配键、适用范围、来源和版本，不凭路径片段猜产品。受保护字段不得通过别名或历史值重新泄露。

历史卡片描述当时变化；打开“查看当前状态”读取最新已发布详情。模块文件变化与加载状态分别显示，文件哈希变化、第三方发布者或签名未检查都不能直接认定损坏。依赖当前时效才能成立的影响，需要对应当前证据；过去故障不能自动成为现在故障。

### 统一规则与影响说明

扩展 `model/presentation.json` 和模型规则，集中定义字段类型、名称、必要上下文、历史动作、当前状态、例行分类、影响条件和规则版本。生成后端规则及前端数据，构建检查生成物一致性。后台产出结构化展示语义和依据，前端只负责本地时间、颜色、布局及展开交互，不存 HTML。

例行记录不删除，主时间线的分类筛选在分页前执行；“包括例行更新”的入口和对象历史仍可查看。模块地址变化按用户要求保持可见。30 秒分组不参与事件去重、对象身份和操作归并，分类数统计实际可见行动，不混入证据份数。

影响文案只从明确配置含义、可靠依赖关系或故障记录产生。普通服务停止只写“服务已停止”；没有证据时不自动追加“依赖功能可能无法使用”。将技术错误变成简明可操作提示，具体错误和来源放到详情；正常项目不增加免责声明。有明确退出、删除、安装或失败依据时直接使用这些动作，不降格成笼统“有记录”或“可能发生变化”。

可恢复问题提供匹配的后台重试、重新检查、重新连接或申请权限入口。多个对象受同一来源失败影响时只集中提示一次，详情保留各自最后状态和时间。没有恢复动作的旧历史缺口留在诊断信息中，不作为长期全局警告；不添加“不能说明什么”“不代表什么”等通用自我辩护段落。

## 历史修复和版本迁移

W06 为每种规则声明影响来源、类型、字段和行动，安排定向重放。失败原因区分暂时性、规则不支持、格式错误、材料缺失和保护字段不可读；规则变更只重新处理适用项，暂时性错误有界退避，永久错误保留隔离。

重放从不可变原始材料生成新派生代次，保存旧新规则、修复范围、游标、成功／失败数量与差异统计。规则修复导致旧行动被撤销或拆分时，保留修复关系和旧证据，查询仅显示当前有效派生版本，不能靠追加另一条矛盾行动“修复”。重复回放结果一致；证据已清理的历史列为无法重算，不编造字段。

数据库从结构 10 做增量迁移，新增表、索引和代次字段，原始 `records`、`snapshots` 的内容不因重算修改。所有派生入口和关联查询一并检查代次过滤，防止详情正确而总览或计数读到旧版本。页游标包含展示代次；代次不可继续读取时返回明确刷新结果，不能跨代拼接造成遗漏或重复。

迁移前确认空间预算、数据目录和运行中的程序版本。使用 SQLite 在线备份 API，或正常停止后台后做一致性备份；不能只复制活跃数据库主文件而遗漏 WAL。历史大库不预设有双倍可用空间，空间不足先保留当前版本，提供明确需求。

回滚优先使用当前结构支持的旧派生发布代次或功能关闭开关。旧二进制不能直接打开新结构；需要二进制回退时配套恢复一致性备份，并冻结完整新版恢复包，包含原始材料、大正文、来源 epoch／检查点、范围对应、规则与保护格式。选定恢复路径为：重新升级后由兼容的新工具前向导入，按原始身份去重并核对检查点连续性；不要求旧结构直接承载新正文格式。回退期间该段历史保存在恢复包中，明确标为待恢复；未有经过验收的导入工具不得宣布数据库回退方案完成。恢复失败时保留现场，禁止删除数据库重新开始。

| Hyper-V 四项兼容来源 | 完成契约、离线样本和无环境行为；暂不启用系统功能 | 实机和原生迁移继续待验收，不能标为完成 |
| Sysmon 未安装或相关日志未启用 | 记录实际能力，原生状态采集继续工作 | 不自动安装 Sysmon、不自行修改系统审计；环境具备后验收真实事件 |
| 驱动安装／卸载及安全配置变更 | 在可恢复虚拟机测试；日常机器只做已有材料和只读接口验收 | 缺虚拟机时过程实机验收保留，不能用合成样本替代 |
| 普通账户无法读的来源 | 权限拒绝隔离，保持旧状态；在同账户增强模式只读复核 | 不把无权限等同不存在；Codex 无需整体提权 |
| 旧原始材料缺失或从未采到 | 标明不能重算的数量与范围 | 不补造历史，也不向所有正常卡片反复提示 |
| 快照间的短活动 | 有可用日志时补充，其他来源保留能力范围 | 不保证捕获每次短连接、瞬时进程或每次文件写入 |

## 验收与交付

详细输入、断言、环境和性能目标见[测试方案](robustness-readability-test-plan.md)。最终交付包含实现代码、规则版本、数据库迁移与恢复工具、全量覆盖登记、测试结果、性能报告、固定目录构建及剩余缺口清单。

任何会生成错误当前状态、误报删除、丢失已接收原文、重复生成行动或泄露受保护字段的失败均阻止相关阶段发布。性能指标为拟定验收目标，S0 固定硬件、权限、数据量和采集配置后执行；指标不达标需要说明原因并调整实现，不能事后只调大阈值宣布通过。
