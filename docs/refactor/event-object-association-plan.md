本次完成来源、身份声明、共用解析链路和实库已生成动作审查；没有在本机人为触发全部事件。各事件编号的真实样本回放、未配环境验收属于下述实施测试。附录分别标出“有通道业务材料”“只有状态材料”“没有记录”，不把通道有数据当作每条子规则已验证。

## 这句话何时出现

1. **已存关联在展示时被否定。** `query_views::action_context` 再次运行事件适配器，要求类型、范围、完整身份、确认状态和来源绑定全部一致；任何一项不满足都归为 mismatch。随后展示对象链接被清空。当前 1,733 条都是这条路径，并非存储里完全没有对象。
2. **原始事件无法重新读取。** 事件引用存在，但材料已清理或无法解析时，可停留在 unverified。已有有效关联也可能因此失去展示链接。
3. **多份证据处理不一致。** 当前只取最早 8 份事件材料，且一份 mismatch 会持续影响结论；正确材料在截断范围外也无法参与。需要区分真正矛盾、缺字段、版本不支持和材料不可读。
4. **规则或上下文改变。** 展示重验使用对象上的机器与安装信息；无对象时这些信息为空，启动周期始终为空。相同事件在投影与展示阶段可能得到不同结果。
5. **有些失败不会出现这句话。** unassigned 不在该提示的触发集合内；尚未识别的分类使用另一句提示；直接跳过的原始日志甚至没有动作卡片。应一起统计，避免只修可见部分。

权限不足、字段加密或截断也可能造成缺失，但本次任务路径缺失与启动周期缺失已有明确代码原因，增加管理员权限不能修好。

## 统一规则

解析动作、识别主体、关联对象、更新当前状态分开处理。事件能证明什么，就写什么；关联对象只决定是否提供“查看对象”。一条历史动作可以关联已结束或已删除的对象，不要求对象现在仍存在。只有符合该事件状态规则和时间顺序的事实才能更新当前状态。

后端持久化每条动作的关联决定，包含结果、原因码、对象 ID、证据地址、机器/安装/启动范围、适用时间、规则版本。内部区分已关联、等待补充、独立事件、身份冲突、解析失败；不把这些内部状态逐个输出到主卡片。展示读取已准备好的决定，不再缺少上下文地重跑适配器。

统一字段读取支持原生 fields、历史顶层别名、UserData 路径和指定事件版本；按通道、提供程序、事件编号、版本选规则。显式受保护值不通过别名绕过，结构损坏不能变成合法字符串。不同事件的字段语义分别声明，不能用任意同名字段充当对象身份。

身份缺关键字段时，不再以 `?path`、`?created_at` 等公共占位键聚合多个主体。保留每次事件的独立地址与已知名称，后续有证据再归并。名称字典用于可读显示，不能代替 SID、GUID、文件编号或启动范围。

## 展示改法

| 情况 | 卡片主文案 | 操作与详情 |
|---|---|---|
| 有完整任务结束事件 | `任务已结束`，下一行任务可读名称 | 有对象链接；运行结果仅在事件明确提供时显示 |
| 进程开始事件 | `程序已启动`，程序名称，时间 | 可查看进程历史主体；当前是否运行在对象详情显示 |
| 登录失败、有目标名称 | `登录失败 · radiohide`，失败原因 | 已匹配账户才显示查看账户，否则提供记录详情 |
| 更新操作失败 | `更新安装失败`，更新名称，失败原因 | 历史更新详情；不把失败动作当作当前安装状态 |
| 事件本来没有具体管理对象 | 已识别的行为名称及结果 | 默认不显示关联警告，保留记录详情 |
| 信息确实矛盾 | 仍显示可确定的事件事实 | 详情标明冲突字段；同一来源的持续解析问题汇总到状态栏 |
| 单项检查持续失败并影响判断 | 对象保留最后有效状态与检查时间 | 状态栏说明例如“登录会话信息停止更新”，附具体恢复办法 |

去掉主卡片通用的“日志未能对应到具体对象”。关联原因保留在技术详情和维护统计中。对象历史只展示关联成立的动作；待处理记录在维护详情可查。分类、搜索、时间分组与自动加载均不能依赖是否有对象链接。

## 历史修复与性能

1. 新规则先阻止继续产生错误，按版本保存关联结果；再修历史。先固定审查水位，后续新记录使用新规则，修复任务保存游标并可续跑。
2. 首批按每条原始 TaskName 拆分 1,691 条任务动作。保留 action_row、发生时间、原始材料与证据地址；逐条更新关联及来源绑定。不得直接把共享临时对象改名或整体合并到任意一个任务。
3. 进程、会话、账户、更新分别生成候选清单，只提交证据满足的关联。原有已确认关联也检查启动范围和身份复用。导入日志保留独立机器/安装范围，不能默认绑定本机当前对象。
4. 修复日志记录旧值、新值、理由、规则版本及批次；保留可撤销的派生变更。清理无引用临时对象前检查事实、关联与证据引用，不删原始记录。多证据合并保留完整证据集合，缺材料不是否决证据，真正冲突不能被最后一条覆盖。
5. 后台分批处理，起始每批 100–500 条、目标写事务不超过 100 ms，按实时查询和采集积压自适应退让；这些是验收目标，需实测调整。新建索引也分阶段评估，避免在正式大库上直接全量重建。
6. 按类型/机器/安装、SID/GUID/路径、有效时间索引匹配。只在新材料、候选对象或规则改变时重试；对同一缺失原因退避，禁止每次刷新或轮询扫描全库。只使受影响动作展示缓存失效，不重建所有时间线。
7. 补齐优先使用已存原始材料和快照，必要时合并原生只读查询。无逐事件 PowerShell 启动、无自身日志触发递归采集、无身份验证式探测。保持全局和单项采集周期语义。

## 测试与验收方案

| 层次 | 必测内容 | 判定 |
|---|---|---|
| 字段解析 | 当前原生 fields 与历史平铺格式；UserData、重复字段、大小写、空值、截断、受保护值、未知版本、错误 provider 的相同 ID | 支持格式得相同主体；无效值不产生假身份；错误 provider 不误分类 |
| 身份 | 任务 110 路径；任务同路径重建/并发；PID/登录号/会话号/打印号复用；同名不同 SID；文件路径复用；同名服务；证书跨存储；CNG 跨提供程序；容器跨宿主 | 不误并、不把操作者当目标；无完整键不共用占位对象 |

| 多证据 | 8 份以上证据、旧版缺字段＋新版有效证据、真实冲突、材料清理、重复输入、日志清空后编号复用 | 不被 LIMIT 8 或 sticky mismatch 错误否定；同源代际正确；持久决定仍可解释 |
| 数据修复 | 使用脱敏最小夹具模拟共享临时对象；重跑、断电续跑、并发采集、重复证据、回滚 | 不重复动作、不删原始历史、来源绑定不串对象；游标与事务一致 |
| 全项覆盖 | 附录 225 个定义、133 个来源逐项登记：真实样本/脱敏回放/合成样本/待环境；109 事件规则下展开已支持 provider/ID/version | 不能仅以入口注册或通道有数据判为通过；健康读数不计业务样本 |

核心质量指标分别报告：正确关联数、可补齐但待处理数、正常独立事件数、真实冲突数、解析失败数、未投影数。正确关联率以“应有可识别对象的事件”为分母并公布分类依据；同时保留上述总量口径供前后比较。不以删除记录、隐藏分类或取消链接凑完成率。

现有 1,691 条已验证都提供唯一 TaskName，因此全部应完成任务主体修正；具体任务代际若缺材料，建立历史主体，不强行绑定当前同路径对象。其余 42 条进程与 10,622 条未关联事件的可自动补齐比例，要在时间范围及候选唯一性检查后报告，不提前承诺 100%。

## 明确保留的测试缺口

- Hyper-V 暂无测试环境，沿用用户已说明的限制；合成样本可验证解析和身份，实机行为验收仍待环境。
- 当前 Sysmon、AppLocker 两通道、DriverFrameworks、PrintService、远程连接管理通道只见状态材料，没有本次业务事件样本；Windows Backup 通道无记录。不能标作实机通过。
- 本次 USN 动态卷来源没有实际文件变化材料，需要专用临时文件回放创建、改名、删除和日志代际测试。
- Defender 检测来源本次无实际记录；修复 Skipped 后用脱敏样本回放，不在正式机制造恶意样本。
- 225 项全字段、全部 Windows 版本/提供程序模板尚未逐一做真实环境验收。附录是完整静态范围和测试账目入口，不是全部通过报告。
