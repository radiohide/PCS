## 3. 准入前置任务

### R01：确认共同基线

**实施：** 先探测执行目录、Git 命令及实际仓库根，选择以下一条恢复路径，再核对 S01–S04 验收状态：

- 有可用 Git：记录基线提交、目录版本和摘要、schema、样例版本及未提交改动归属。
- 无 Git：决定安装/建立仓库，或明确使用“文件快照 + 串行整合”。本方案不自动安装、不自动建仓；选择无 Git 路径不阻止文档和隔离模块准备。
- 文件快照路径：记录快照 ID、文件清单、相对路径和 SHA-256；把工作文件复制到独立恢复位置并做还原演练。单独的哈希清单不是备份。排除运行库、凭据和大产物，数据库如需备份走一致性备份流程；集成在单一写入者下进行。

工具链单独作为外部依赖登记：Cargo/Rustup 根、cargo/rustc、目标平台、链接器、Node、PowerShell、原生 C# 编译器的实际路径与版本。要求构建入口接受显式路径配置或可靠解析环境变量，不再无条件覆盖为不存在的项目内 `.tools`。这是准入需要实施的构建修复，不是本文已经修好。

**交付：** `parallel-baseline.md`，列出已通过项、缺口及可供各工作线使用的基线。

**验收：** 从选定基线能复现目录生成和已有检查；在新终端、无历史 PATH 补丁时构建预检能定位外部依赖，缺失时指出准确路径；完成一次选定方式的恢复演练；S04 的新库/旧库升级、幂等启动及事务失败恢复通过。不能用“已写迁移文件”代替 S04 验收。

### R02：冻结标准适配器契约

适配器应接收已持久化的来源材料，输出候选事实；它不直接分配最终对象 ID、不自行写数据库、不另行调用 Windows 补采。

| 契约 | 必须明确的内容 |
| --- | --- |
| EvidenceInput | 来源、采集项、结构版本、来源作用域、证据引用、原生记录身份、源/观察/入库时间、解码可用性 |
| AdapterContext | 目录与规则版本、可用的机器/安装/启动上下文、采集范围与完整性 |
| IdentityCandidate | 类型 ID、身份字段及各字段来源、业务作用域、缺失与歧义信息 |
| ObservationCandidate | 身份候选、字段 ID/值/状态、观察时间、证据引用、范围和完整性 |
| ActionCandidate | 目标身份候选或未归属原因、动作类型、阶段/结果、时间精度、前后值、证据引用 |
| AdapterResult | 零到多个候选、非对象用途、解析问题、可重试性和明确的处理结论 |

**交付：** 共享 Rust 类型或等价可校验 schema、序列化格式、适配器函数签名及示例。

**验收：** 至少两种结构不同的来源使用同一接口；未知字段保留在原始证据，缺字段不填猜测值；重复输入得到等价候选；失败有明确结果；候选不可包含未登记类型或字段。

### R03：冻结身份解析接口

| 输入/输出 | 要求 |
| --- | --- |
| 输入 | IdentityCandidate、证据时间上下文、生命周期线索、类型策略版本 |
| 已确认结果 | 内部实例 ID、匹配策略和支持依据 |
| 暂定结果 | 暂定实例 ID、身份不足原因、未来可补充的键 |
| 歧义/未解析结果 | 候选或原因，禁止任意选择一个匹配 |
| 生命周期结果 | 首次观察、未发现、明确结束/删除、重建代际及依据 |

**实施：** 明确业务范围和采集范围的边界。采集分片、请求 ID 和插件名不参与跨来源身份；用户 SID、注册表视图是否参与由类型决定。暂定身份以后确认时必须能迁移引用或通过稳定别名解析，不能静默让旧详情链接失效。

**交付：** 身份接口、规范化规则、实例 ID 生命周期说明。

**验收：** 用户改名、任务不同路径、PID 复用、文件路径复用、同实例多来源五类样例有固定预期；没有最终 ID 的适配器输出可被处理；缺少安装/启动标识时明确降级，不伪造历史上下文。

### R04：冻结事实、动作、时间和清理语义

**必须决定：**

- 时间统一编码、时区、精度；精确、区间和仅观察时间如何表示；每种排序使用哪个锚点。
- 字段不存在、读取失败、不适用、冲突与显示遮罩的区别。持久事实和显示脱敏不是同一个状态转换，不能把遮罩字符串当真实值参与身份匹配或变化比较。
- 当前值选择策略、来源优先级的适用范围；旧事件晚到与冲突处理。
- 动作去重依据、阶段区分、多证据支持规则；不得仅凭时间接近归并。
- 证据被清理时引用返回什么；实例历史与当前最小事实如何保留。
- 完整快照的完整范围：何时可以判定“未发现”，停用项和范围变化如何排除。

**交付：** 语义决策表及预期输出样例；未决定项必须列为阻塞项。

**验收：** API 最新快照 + 较早日志、同字段冲突、停用采集、证据被清理、任务下次运行时间变化都有唯一预期处理方式；各工作线不自行定义枚举或缺失值含义。

### R05：冻结查询契约与模拟服务

先固定类型目录、实例列表、实例详情、实例动作、证据详情、来源覆盖、投影进度的请求/响应结构，不要求真实后端全部实现。

**实施：**

1. 明确筛选字段、默认顺序、稳定游标、查询水位和页大小上限。
2. 区分总对象数、来源记录数和动作数；定义暂定及历史对象的默认可见性。
3. 定义加载、空结果、未支持、权限不足、部分成功、证据已清理、版本不兼容等响应。
4. 用同一 schema 验证模拟响应与实际响应。模拟模式显式标记，仅用于开发，不写用户数据库、不触发采集。

**交付：** 查询契约、固定响应集、模拟服务/适配层。

**验收：** 前端无需猜测后台字段即可展示完整任务详情；模拟数据覆盖上述状态；身份暂定、动作区间、多证据、遮罩均可展示；正式构建不会误连模拟服务。

### R06：建立共享样例与契约检查

**实施：** 基于已有 `fixtures/` 补齐输入与标准候选、身份结果、查询响应的对应样例。预期结果必须写明证据依据，不能直接由待测实现生成后当成正确答案。

**最小样例集：**

1. 一个计划任务，两个配置来源和一份运行日志。
2. 同名不同路径任务，以及确认删除后重建。
3. 同 PID 不同创建时间，只有 PID 的不完整事件。
4. 新快照先入库、旧日志后补采；同字段无法消解的冲突。
5. 一项来源停用、一个字段不可读、一份证据已清理。
6. 带敏感字段的证据，验证遮罩和复制路径。
7. 无法归属对象的日志与一个纯采集缺口记录。

**交付：** 样例说明、共享加载工具、独立的契约检查和集成测试命令。

**验收：** 所有样例通过 schema 校验；错误类型 ID、错误枚举、缺证据引用、错误时间区间等故意破坏能够被拒绝；日志样例不包含真实秘密；Rust 和前端侧对同一数据含义一致。

### R07：划分代码与目录所有权

**实施：** 为各工作线写清可独立修改的文件边界及共享改动流程。所有权指改动整合责任，不限制必要的跨模块修复。

| 工作线 | 主责范围 | 不应自行修改 |
| --- | --- | --- |
| 基础数据线 | schema、证据入库、队列、身份、投影与预算 | 前端展示规则及其他类型专属解析 |
| 类型适配线 | 独立来源适配模块、专属样例和映射增量 | schema 编号、最终对象 ID 算法、公共枚举 |
| 查询与界面线 | 查询实现、IPC 展示 DTO、页面与交互 | 原始证据语义、适配器私有格式 |
| 迁移验证线 | 回放工具、对账、故障/性能验证 | 运行库数据、用户配置及未协调的保留规则 |

中立目录、公共契约、schema 和 IPC 注册入口各设一个整合责任。共享入口尽量通过模块注册表汇总，避免所有工作线同时追加同一大文件。

**现存两套目录的权威与切换是阻塞项：**

1. 新对象类别、类型、身份策略、字段、动作的权威为 `model/` 编写文件；`model/catalog.json` 仅为生成产物。
2. 旧采集目录在过渡期继续作为旧运行路径的采集项分类输入。它不能定义新对象身份，新前端不得把两套目录的同名字段直接拼接。
3. 来源/采集项 ID 沿用现有注册与控制定义，由显式映射连接到新对象类型。不得用改对象分类的方式重命名单项开关或丢失配置。
4. R07 要完成消费者清单，列出 Rust `include_str!`、前端 fetch、生成脚本、开关清单及解释模板分别读哪一套、属于旧还是新路径。
5. 并行开工前至少接通新 Rust 消费者与新前端契约/模拟消费者，并校验同一目录版本及内容摘要；零消费者时“版本检查通过”不能算接线通过。
6. S22/S26 完成真实查询和页面切换验证，S32 统一默认切换，S33 才清理无消费者的旧对象分类。来源说明与控制元数据可以继续存在，但不能与对象目录争夺同一语义权威。

类型边界表从 `model/catalog.json` 自动生成，双向列出“类型→来源”和“来源→类型”，去重统计多来源类型和多类型来源。生成事实不等于分工决定：实施责任、重叠边界处理和待决项另行登记；不能把未指定责任的生成表当作 R07 完成。

已提供生成工具 `scripts/build-parallel-boundaries.cjs` 和 [当前生成边界表](parallel-boundaries.md)。在项目根执行 `node scripts/build-parallel-boundaries.cjs` 更新，附加 `--check` 校验是否过期。当前生成结果为 35 个多来源类型、13 个多类型来源；后续以生成表和输入摘要为准。

**交付：** 文件责任表、类型边界表、共享改动登记格式。

**验收：** 自动边界表可重复生成且与目录摘要一致；所有重叠类型有明确主实现；两套目录的消费者与切换表完成并通过接线检查；无人自行分配迁移号；生成目录不手工修改。任何工作线仍把旧采集分类当作新对象类型权威时不得准入。

### R08：固定工作区与集成策略

**实施：** 按 R01 选择的恢复能力安排工作环境，不默认存在 Git。Git 模式使用从共同基线创建的独立分支和工作目录；无 Git 模式使用带快照清单的隔离副本，提交变更文件清单与差异，由单一整合者核对基线后串行合入。只有共享目录时禁止并发修改同一文件，共享修改完全串行。各工作线只使用隔离测试数据库。

**规则：**

- 各开发线使用自己的测试数据库路径；不得并行迁移、清理或重建本机正式库。
- Git 模式下，共享索引的目录不并发 commit、切分支或 reset；无 Git 模式下，整合前验证待覆盖文件哈希是否仍等于基线，变化则先处理冲突，禁止整目录覆盖。
- 公共契约变动先整合到共同基线，再由消费者更新；不用各线私有兼容分支无限维持差异。
- 临时产物、基准数据库和日志不进入源码提交。

**交付：** 基线与分支或快照/副本对应表、独立测试目录约定、相应模式的集成与恢复流程。

**验收：** 两条开发线同时执行测试无端口、文件、数据库冲突；能定位每条结果所用契约版本；没有对当前运行库的写入。

### R09：先完成最小贯通演练

**实施：** 用已有样例走通“证据输入 → 适配候选 → 身份结果 → 模拟或最小投影 → 查询响应 → 前端详情”。底层可有明确标记的替身，不宣称已经完成 S05–S08。

**交付：** 可重复演练入口和一份结果报告。

**验收：** 同一任务来自两种来源时在样例详情中只有一个实例，字段能指向各自证据；未归属事件保留；未知、冲突和证据清理状态贯通；各模块之间不再依赖口头约定或未文档化字段。

## 4. 准入判定

不以“这些文档已经写完”为准入依据，应记录实际运行结果。

| 准入等级 | 必须满足 | 允许的工作 |
| --- | --- | --- |
| 准备 | 无 | 盘点、样例补齐、设计和边界澄清 |
| 独立开发 | R01–R08 对该工作线所需契约全部通过；S04 已验收 | 在隔离分支或受快照管理的副本中开发，按所选模式整合 |
| 全工作线并行 | R01–R09 全部通过 | 多工作线按固定契约推进和定期集成 |
| 实际步骤验收 | 满足主计划对应 Sxx 的真实依赖 | 可以将 Sxx 标记通过 |

局部准入只能放行不依赖未决事项的工作。例如查询错误模型尚未定时，可以做来源解析样例，但不能同时宣称前端查询契约已冻结。

建议新增 `acceptance/parallel-readiness.md`，逐项记录 R01–R09 的状态、文件或提交、验证命令、实际结果、未决项、允许进入的工作线。此报告与本文不同：本文是方案，报告是实际执行证据。

## 5. 接口变更与冻结边界

冻结意味着契约版本与变更记录受控，不意味着一定已有 Git，也不意味着永远禁止修改。Git 模式用提交追踪；文件快照模式用快照 ID、摘要、变更清单和恢复副本追踪。

每个共享接口变更记录：问题、旧/新结构、兼容性、受影响工作线、样例变化、数据迁移需求和检查结果。

- 只增加兼容的可选字段：更新版本和样例，验证旧消费者的真实处理能力，不能假定其忽略未知字段。
- 删除字段、改枚举、改变身份或时间语义：作为破坏性变更统一整合；相关工作线先停止依赖旧语义的集成，再一起升级。
- 身份策略变化：必须说明旧实例 ID、来源绑定和事实引用怎样重建/迁移，不能只更新目录版本。
- schema 变化：由整合责任分配编号并验证新库与升级库；各类型适配器通过声明提出需求。
- 生成文件：修改编写源后统一生成、校验和提交，不互相覆盖生成结果。

一个工作线发现接口缺项时应提交最小变更提案和失败样例；其不相关任务可以继续，不需要把所有开发全部暂停。

## 6. 并行期间的集成顺序

1. 基础数据线先提供证据与身份接口的实际实现，替换样例替身。
2. 每个适配模块以小批次接入，跑其专属样例及共享语义样例。
3. 查询接实际投影，验证响应与模拟契约一致。
4. 前端切实际查询，验证同一份样例在模拟与真实链路表现一致。
5. 迁移与质量线持续验证重复回放、晚到数据、清理和性能，不等全部页面完成才开始。
6. 全来源覆盖由 S21 收口，全前端由 S26 收口，完整质量门禁仍按 S29–S31 执行。

接口变动或一个可独立交付的模块完成时执行集成检查。不要等各线大量代码完成后才第一次合并。

## 7. 并行前必须阻止的情况

- 同一个词在不同模块有不同含义，例如把 source scope 直接当业务身份 scope。
- 前端自定一套 DTO，后端自定另一套，再靠临时字段重命名拼接。
- 适配器直接写 objects 或自己生成最终实例 ID。
- 类型线私自增加公共枚举、迁移号、动作合并规则。
- 用真实用户数据库作为多条工作线共同的迁移测试库。
- 模拟测试通过就标记真实来源或 Sxx 集成验收通过。
- 公共契约持续变化但不更新版本、样例和消费者。

## 8. 最小可执行准备顺序

`R01 基线确认 → R02/R03/R04 契约 → R05 查询模拟 → R06 契约检查 → R07/R08 协作边界 → R09 贯通演练 → 准入记录`

责任和隔离环境可以提前准备，但不会替代契约和贯通检查。完成这些条件后再投入多条开发线，可以把并行用于真正独立的实现，而不是同时修改尚未稳定的公共基础。
