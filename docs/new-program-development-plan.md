# 新程序独立运行与功能完整性开发计划

日期：2026-09-12。状态：待实施；本文件的写入不代表其中任务已经完成。

## 1. 目标与适用范围

新程序从独立的新数据库运行，不兼容、不迁移旧版本数据；完整实现既定采集、原始信息保存、规则解释、对象与动作查询、界面展示和系统配置，并通过从源码构建到真实前后台运行的端到端验收。

本计划承接 `full-object-refactor-plan.md` 的功能范围，但替代其中 §19 的后续实施路线，以及“旧数据留在升级后的同一库中”的运行方案。旧版本只供参考，不是新程序的运行依赖。历史验收记录保留原文，后续追加新的适用范围说明，不改写历史事实。

- 不做：旧库回放、旧表对账、旧接口兼容、旧数据库原地升级验收。S27/S28/F4 继续作废，不标通过。
- 必须做：新产生数据的完整性、持续采集、断点恢复、明确失败与缺口、可读解释、查询展示和配置闭环。
- 不兼容旧数据不等于重写所有代码：复用仍服务新功能的实现；仅删除确认无用的兼容路径。
- 本计划不授权删除旧库、归档或演练副本，也不授权自动提交、推送或替换正在运行的正式程序。
- 系统本身不提供、已清除或权限禁止取得的信息，不能承诺获取。必须记录原因、范围和状态，不能伪造完整性；已经取得的信息不得静默截断或丢弃。

## 3. 完整性的验收定义

1. **来源完整**：按来源清单和采集子项逐项追踪，不以类型总数或对象总数代替覆盖证明。权限不足、环境不适用、未配置、未实现分别表示。
2. **信息完整**：已取得的原始正文、结构化字段、来源身份、时间与错误信息有保存路径；超大输入、解析失败、未知字段不静默丢弃。主动采集字段的排除也必须审计，不能只保证“解析器收到以后不丢”。
3. **解释完整**：常见来源有确定性规则解释；未知情况仍可读，展示已知事实、缺失原因与原始依据，不能靠事件编号编造原因。
4. **链路完整**：每个实际采集来源均能追踪到证据、处理状态及正确的业务去向。非对象来源进入覆盖或采样视图，不硬造对象，也不在失败队列永久堆积。
5. **运行完整**：首次启动、定时与手动采集、停用恢复、重启、异常退出、并发查询和正常关闭均可验证。重复处理不重复制造动作，未处理材料可恢复。
6. **显示完整**：列表、详情、搜索、历史、差异、覆盖健康、原始信息与导出一致；分页说明未显示数量，不能把截断列表说成全部。
7. **敏感信息**：默认遮罩，系统配置允许用户明确选择明文；保存、界面、复制和导出分别约定。默认日志及错误报告不得泄漏明文；不能通过丢弃原始字段实现遮罩。

## 4. 实施阶段与顺序

主线：N01 基线与构建 → N02 新库隔离 → N03 完整度语义 → N04 来源闭环 → N05 解释与界面 → N06 运行验收 → N07 旧代码清理 → N08 最终复验。

### N01：锁定工作树与打通构建（优先级 P0）

- 盘点当前暂存、未暂存、新增文件，记录基线版本与变更范围；不得 reset 或覆盖既有修改。
- 为当前平台记录 Rust/MSVC、Node、PowerShell、WebView2 和原生事件采集器依赖。
- 解决 `build.ps1` 工具链定位：现有入口支持 ToolsRoot / PCSCOPE_TOOLS，但要求特定目录结构。明确支持的安装布局；不得偷偷回退后声称可复现。
- 审查 PowerShell 构建和 staging 的失败传播：每次原生命令失败都须终止，禁止接着使用旧二进制得到假成功。
- 打通工作区、examples、桌面工程和原生事件采集器的构建与打包；记录本次产物路径、哈希、版本和对应源码状态。

验收：从明确输入构建所有必需产物；故意使一次构建失败时，冒烟与打包必须停止。已有 exe 的时间戳或输出字符串不作为完整产物溯源证明。

### N02：新库与旧环境隔离（P0）

- 确定独立新数据目录，统一桌面、CLI、服务、脚本的路径与启动参数；不复用旧正式库、不扫描导入旧库。
- 首次启动直接建立当前版本所需结构；删除旧 schema 阶梯前先识别新库仍依赖的初始化代码。
- 保留新程序自己的版本标识和拒绝未知高版本库的保护；“不兼容旧库”不等于可破坏任何库。
- 误指定旧库时应在写入前明确拒绝并引导新建目录，不得自动升级。默认配置不继承旧敏感明文开关。
- 隔离后台发现、IPC 端点和单实例机制，防止测试新 UI 误连旧后台。
- 审核数据库、WAL/SHM、运行日志等自身产物的采集排除策略，避免递归自采集。

验收：空目录冷启动成功；所有组件连接同一新实例；旧库夹具误传后字节不变；旧正式目录不被本轮测试写入；并存时不会串连。

### N03：修复历史完整度与失败语义（P0）

- 将“本轮采集成功”“日志已读到末尾”“投影队列追平”“已知历史缺口”拆开判定。
- 修复 coverage.rs 仅凭 ok 写入 caught_up；日志类依据游标、世代、has_more 和读取范围，快照类不得冒称全历史完整。
- 来源恢复不自动消除已知丢失区间；重置、清除、禁用、权限错误、保留裁剪均保留可追溯原因。
- 审核覆盖范围和来源聚合，不能以一个来源或一个范围的成功覆盖其他范围的失败。
- 更新契约、存储、服务与前端；已有词表检查保留，增加状态转换测试。

验收夹具至少包括：首次成功但尚未追平、has_more、已到日志末尾、日志世代变化、停用再启用、失败后恢复但缺口仍在、解析失败但采集成功、状态未知。界面不得把这些混为“已追平”。

### N04：全来源保存与业务去向闭环（P0）

建立逐来源矩阵：来源/子项 → 原始载荷与字段 → 保存位置 → 处理器 → 对象/动作/覆盖/采样去向 → 查询 → 页面 → 自动测试 → 实机证据。以当前清单为基线，不冻结数量，也不删清单来提高通过率。

| 当前例外或缺口 | 必须完成的工作 |
| --- | --- |
| apps.dotnet-runtimes / software.runtime | 基于真实子键结构实现家族、版本复合身份，验证重复与不同家族同版本 |
| system.update-history | 明确对象或动作模型并闭环；失败更新、重复记录与时间信息不可丢 |
| collector.scoped-configuration | 原始证据保留，投递覆盖范围视图，不作为对象适配失败 |
| collector.event-channel-coverage | 将补采游标与范围接入覆盖状态，区分进度和完整性 |
| usn.watch-list | 接入配置/覆盖视图；空名单表示未配置，不代表对象消失 |
| execution.resources | 进入采样路径，保留时间与原始值，提供可查询和可读展示 |
| usn.changes | 验证其仅为虚拟前缀，逐盘实际来源仍须闭环 |
| file.watched_directory | 接通目录监控类型及来源，覆盖配置和实际变更 |
| security.key_metadata | 实现已声明的元数据采集，明确权限和采集边界；不扩展为绕过保护提取密钥 |
| hardware.driver_package | 实现驱动包来源、身份、字段和详情 |

- 审查所有 PS1、原生采集器和适配器的字段白名单、长度限制、Select-Object/分页、异常吞掉及字符串编码路径。
- Windows 事件首次采集自动取得可用正文和原始结构，不要求用户手动补采；正文资源缺失等情况保留原始依据与具体失败原因。
- 自动补取需要超时、重试和持久状态，不阻塞整个采集循环，不丢掉已成功取得的材料。

验收：所有真实来源有经验证的去向；“未实现/待决”不能作为完成例外。环境不适用须有探测证据及夹具测试。校验原始内容及字段，而不只比行数；长文本、未知嵌套字段、空/null、特殊字符、敏感值和异常载荷均有回归。

### N05：可读解释与用户功能闭环（P0）

- 从固定规则生成事实摘要、影响/限制和来源依据，严格区分事实与推测；原始信息始终可访问。
- 核对对象、动作时间线、搜索过滤、详情、前后差异、覆盖健康、采集开关、系统配置、复制与导出。
- 保留并验证活配置接口，包括 Retention/SetRetention；默认不自动丢弃。用户主动选择裁剪时需明确提示、记录边界，不能继续宣称完整历史。
- 完成敏感信息默认遮罩及明确明文选择；跨重启、错误状态、复制导出均测试，使用人工假秘密测试，避免真实凭据进入日志或仓库。
- 对截断结果显示总量/还有更多及获取方式，包括 reconcile 的抽样上限；此工具仍服务新库，缺陷不能随旧迁移作废一起忽略。

验收：真实 WebView2 操作验证，形成页面检查记录；固定规则输出不编造；空结果能区分“无记录、未采集、失败、未配置”；长原始内容和分页结果可完整取得。

### N06：新程序运行验收（新的 S32，P0）

- 只用全新隔离库及新采集/生成数据，不以旧迁移副本的成功或失败替代证明。
- 真实多采集器运行，验证首次采集、周期采集、手动采集、增量变化、重启及正常关闭。
- 注入强制退出、事务错误、损坏载荷、权限不足、日志重置、磁盘空间不足、队列积压和并发查询。
- 验证容量背压和恢复：未提交输入不得提前推进游标；可重试错误与确定性解析失败区分；失败证据可定位。
- 采用小型确定性夹具验证正确性，并用独立新生成的大规模数据验证积压与性能。开始前记录规模、硬件及时间/内存/查询预算，不以迁移演练数字充当性能承诺。
- 核对证据、处理状态、投影、水位与引用关系，验证恢复后不漏不重；只读审计必须具有实际断言和非零失败退出码。

验收：每种故障均有恢复证据；后台/界面/CLI 指向同一测试实例；队列状态准确；不存在无解释的数据遗漏或假完整。所有测试后台完成后正常停止，未自动替换正式运行环境。

### N07：旧路径清理（新的 S33，P1）

- 旧 schema 兼容、迁移专用示例与文档入口按用途处理；本地旧数据库和大型副本仅列清单，不自动删除。

验收：静态引用检查、全测试、查询契约和真实前后台复验通过；测试数量变化逐项解释，不能只给一个总数。独立死代码可提前清理，但不得因此提前宣布 S33 完成。
