# 插件内采集项开关

位置：采集插件 → 插件“详细” → 采集来源明细 → “采集开关”。默认全部开启，点击立即保存。配置保存在当前后台数据库 `settings.item_settings`，带递增版本号，后台重启后仍生效。每次实际修改记录 `collector.item_configured`。

当前提供 216 个采集项开关，包括事件日志的 108 个细分项。ID、名称及归类来自统一采集目录，开关清单由 `build-collection-catalog.cjs` 同步生成。USN 的“日志身份与断点”和“采集库文件自身排除”是文件变更采集的必要机制，不是可单独停用的数据项；对应行明确标注，不提供会破坏采集正确性的开关。

- 插件总开关控制自动调度；项开关同时约束自动和手动采集。手动执行一个已停用的插件仍只运行其启用的采集项。
- 状态项关闭后，不再调用其独立查询；不发送空快照代替关闭状态。共享接口可能仍为其他启用项读取，但关闭项不进入持久化结果。
- Shell COM 信息依赖从扩展登记发现 CLSID；开启 COM 项时可能仍需读取这些登记以解析引用。
- 已有历史及系统对象保留，关闭项的最近采集时间保持不变。共享来源部分关闭时保留对应对象，避免误报“对象消失”。重新启用时与最后一次真实采集状态比较。
- 设置变化会使进行中的旧配置结果停止后续入库，下一轮使用新配置。
- 事件日志按细分项跳过关闭项，原生读取器和 PowerShell 读取器都在格式化正文前筛选。共享通道继续推进断点，因此已跳过的事件不会在重新启用后自动回补。
- 当整个来源关闭时跳过该来源读取、保留断点；重新启用后可从断点读取 Windows 仍保留的日志，能否追上取决于源日志保留情况。USN 文件变更关闭时也保留断点。
- 文件列表、插件采集周期、现有权限和磁盘保留策略均沿用当前配置。

验证覆盖：设置持久化及幂等更新、插件与采集项归属校验、共享快照的对象与时间保留、恢复采集比较、日志断点推进、分类器一致性、PowerShell 关闭查询不执行、原生日志关闭项不输出正文，以及 UI 开关状态。
