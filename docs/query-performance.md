# 查询性能与超时

## 当前系统对象列表（2026-10-13）

当前对象模型的默认列表包含精确的对象、动作、绑定和证据计数。大量完整快照会让同一证据地址被许多对象重复引用，原 `COUNT(DISTINCT)` 去重统计因此成为瓶颈。

新增仅用于加速的观察引用覆盖索引。筛选结果仅计算一次，四项统计共用；接近全部对象的列表逐个跳到不同的证据地址，其余通过最多 25 万条引用的有界探测选择按对象统计或按地址统计。探测上限随总引用规模变化，只影响路线选择，最终仍精确计数。空选择立即返回零；旧只读库没有新索引时自动使用原统计路线，不进行无用探测或升级数据库。

计数仍包含已清理或缺少材料元数据的引用，跨材料类型的同地址只计一次，游标页的计数范围保持不变。筛选集合只暂存对象数字身份与其短文本形式，不把全部证据地址复制到 Rust 集合中。

写入程序启动时原子补建索引，随后由 SQLite 随引用写入维护。数据含约 158 万条观察引用的隔离副本中，首次建立约 9.21 秒，增加约 339 MiB；不会每次查询重新建立。版本仍为 9，这是兼容旧程序的附加索引，不改变历史格式。索引失败不产生半个索引，原始材料保留。

最终完整原生开发构建在同一副本上，默认列表首两页为 1860 / 2162 ms；五种排序各两页均成功，范围 1735–2397 ms。12 类筛选全部成功，其中运行程序 927 ms、网络 1060 ms、最慢的资源管理器扩展 3612 ms。默认精确证据地址计数为 62,356；请求的 SQLite 预算仍为 6 秒。状态及轻量设置另用 2 秒预算的独立只读连接，避免等待采集写锁。实际运行验收和边界见 [本轮验收](refactor/acceptance/object-query-recovery.md)。重复快照长期增长尚待单独处理。

## 此前历史记录查询与测量（2026-09-11）

以下描述此前历史记录表的优化和当时数据集，不代表当前对象模型的实际响应时间。

时间线分类在写入时保存到 `record_search`，按采集项、分类、变化类型和序号建立索引。筛选菜单只扫描分类覆盖索引，不再解析全部历史证据或重复展开分类 CASE。索引随插入、分类字段修改及历史清理同步维护。

数据库版本 5 首次打开会在事务中补建旧记录的分类索引；失败时回滚，历史证据不变。目录定义更新后会重建索引。首次建立期间后台尚未就绪，耗时取决于数据量和磁盘速度。

历史查询使用独立的只读 WAL 连接，在阻塞工作线程执行。最多同时处理两个查询；SQLite 查询预算为 6 秒，超时会中断 SQL，不会继续占用后台采集的数据库锁。IPC 等待时限仍为 10 秒。繁忙和超时均返回中文提示。

关键词仍是对原始存储文本的字面子串检索，未引入全文索引；大范围无匹配查询可能较慢。可通过采集项、分类或变化类型缩小范围。加密字段不能按明文检索。

## 验证记录

2026-09-11，在本机历史库的 SQLite 一致性副本上测试，258,641 条记录、16,958 个当前对象，开发构建：

| 查询 | 耗时 |
| --- | --- |
| 旧版仅生成时间线筛选菜单 | 超过 8 秒，测试主动中断 |
| 首次补建分类索引 | 50.3 秒 |
| 默认时间线 100 条 | 206 毫秒 |
| 指定采集项 | 244 毫秒 |
| 指定变化类型 | 211 毫秒 |
| MapsUpdateTask 关键词 | 4.81 秒 |
| 无匹配关键词 | 4.81 秒 |
| 当前对象列表 | 641 毫秒 |
| 当前对象关键词 | 940 毫秒 |

以上为该数据集的一轮测量，不是任意数据量下的性能保证。复现命令：`cargo run --offline --locked -p pcscope-storage --example query-benchmark -- <现有数据库> <不存在的副本路径>`。工具只读打开来源，使用 SQLite Backup API 创建副本，仅在副本上迁移和测量。

自动测试覆盖历史索引补建、更新和删除同步、查询执行计划使用采集项索引、只读 WAL 快照与后台写入并行、超时中断后写入仍可继续。

升级后的实际 IPC 默认时间线查询为 273 毫秒。补充并发测试发现状态计数也需要独立读取；修复后，在后台采集与全库关键词检索同时进行时，状态请求为 41 毫秒。该轮无匹配关键词在 6 秒预算处被中断并返回中文提示，因此不能宣称所有关键词查询均已达到秒开。可用 `cargo run --offline --locked -p pcscope-ipc --example probe -- query-performance` 对正在运行的后台复测（只读，不触发采集）。
