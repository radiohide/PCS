# PCScope 对象监控模型设计

版本：设计稿 v1 · 2026-09-11

本文定义 PCScope 下一阶段的对象组织与展示模型。它是目标设计，不代表当前程序已经完成对象归一、多来源合并或历史迁移。现有采集能力应以采集目录和实际读取结果为准。

## 1. 目标与范围

以电脑中实际存在、参与或影响电脑行为的对象为中心，回答：

1. 它是什么，属于哪一类？
2. 最近观察到的属性和状态是什么？
3. 它发生过哪些动作和变化？
4. 每个结论根据什么信息得到？
5. 哪些信息仍在采集，哪些存在缺口？

第一阶段包括对象分类、身份识别、属性和状态、动作历史、证据和来源、采集状态，以及同一对象的多来源信息汇总。

对象之间的关系图谱、软件归属推断、依赖分析、影响范围分析留到下一阶段。例如“软件安装了哪些服务”和“服务启动了哪个进程”不在本阶段实现范围内。第一阶段可以保留来源中的文件路径、账户 SID、进程 ID 等字段，但不据此自动建立对象关系或推断归属。

## 2. 三层对象结构

固定层级为：**对象类别 → 对象类型 → 对象实例**。

| 层级 | 定义 | 示例 | 是否为电脑里的实际对象 |
| --- | --- | --- | --- |
| 对象类别 | 面向用户的功能大类 | 自动执行入口 | 否，是导航分类 |
| 对象类型 | 有共同身份规则、属性和动作的对象种类 | 计划任务 | 否，是类型定义 |
| 对象实例 | 在某台电脑及明确作用域内被识别的具体对象 | `\Microsoft\Windows\Maps\MapsUpdateTask` | 是 |

```text
自动执行入口
├─ 服务
├─ 计划任务
│  ├─ \Microsoft\Windows\Maps\MapsUpdateTask
│  └─ \Microsoft\Windows\Maps\MapsToastTask
├─ 登录启动项
└─ WMI 永久订阅
```

实例内部的信息分区为：**属性和状态、动作历史、证据和来源、采集状态**。这些是信息维度，不是第四级分类。

允许增加可选的浏览分组，例如任务文件夹、文件目录、证书存储区、用户作用域。这些分组不改变对象类型和身份，不强制所有类型具有相同的目录深度。

## 3. 对象分类目录

下面是目标分类骨架。具体类型可以继续扩展；列入设计不意味着已完整采集。一个类型只设一个主类别，避免同一对象在不同分类下重复计数。辅助搜索标签可以跨类别。

| 对象类别 | 对象类型 | 对电脑行为的影响 |
| --- | --- | --- |
| 账户与身份 | 用户、用户组、组成员登记、用户配置文件、账户权限分配 | 谁能登录、使用什么身份、获得什么权限 |
| 软件与组件 | 软件安装登记、AppX 包、预配包、Windows 可选组件、运行时、便携程序登记、系统更新组件 | 系统具备哪些功能和执行能力 |
| 运行实例 | 进程、模块加载实例、登录会话、终端会话 | 当前执行什么、使用什么身份、加载什么代码 |
| 自动执行入口 | 服务、计划任务、登录启动项、登录初始化配置、WMI 永久订阅登记、IFEO/AppInit/AppCert 配置 | 什么条件下自动执行什么代码 |
| 系统扩展与关联 | 右键菜单登记、预览处理程序、图标覆盖处理程序、COM 注册、文件关联、命名空间扩展、浏览器扩展 | 用户或程序操作系统功能时调用什么组件 |
| 文件与访问控制 | 监控文件、监控目录、文件系统权限登记、备用数据流 | 实际代码与数据是什么，谁能读取、修改或执行 |
| 策略与配置 | 环境变量、UAC 策略、软件限制策略、应用策略、时间同步配置、电源计划、操作系统配置 | 系统和应用按照什么规则运行 |
| 网络与远程访问 | 网络适配器、IP 地址配置、路由、DNS 配置与缓存项、代理配置、VPN 配置、防火墙规则、IPsec 规则、网络连接与监听端点、SMB 共享及映射、远程访问配置 | 流量走哪里、哪些连接被允许、资源如何对外开放 |
| 安全与信任 | 证书登记、密钥元数据对象、防护策略、排除项、安全产品登记、BitLocker 配置、SSH 公钥登记 | 信任谁、保护什么、哪些检查被豁免 |
| 硬件与驱动 | 设备、驱动包、设备驱动绑定、驱动服务、磁盘、分区、卷、固件、TPM | 设备如何工作，哪些组件参与系统底层执行 |
| 虚拟环境 | 虚拟机、虚拟交换机、虚拟磁盘连接、检查点、WSL 发行版、容器、镜像、容器网络与卷 | 电脑中有哪些隔离环境及其资源配置 |
| 桌面与应用集成 | 打印机、打印端口、打印作业、输入法、快捷方式、编辑器扩展、同步账户、桌面配置 | 用户操作如何被处理，应用如何接入桌面 |

### 3.1 分类边界

- 驱动服务主归“硬件与驱动”，普通服务主归“自动执行入口”。服务枚举与驱动枚举发现同一个登记时，应按类型规则归一，不能仅因插件不同重复展示。
- 文件关联主归“系统扩展与关联”，即使当前由环境配置采集项提供，也不改变对象类别。
- 浏览器扩展主归“系统扩展与关联”；浏览器策略主归“策略与配置”。
- 监听端点主归“网络与远程访问”，进程主归“运行实例”。端点中的进程标识暂作为字段保留。
- ACL 通常作为文件或目录的属性和历史变化展示；只有需要独立识别、检索某项权限登记时才建立独立类型，避免为每个属性制造一个对象。
- 组成员登记等关系性质的数据，在第一阶段可以作为独立配置登记或组属性保留；它与下一阶段的通用对象关系图谱不是同一功能。
- 注册表是很多对象的存储来源，不应把每个注册表键都自动视作独立业务对象。指定监控的原始键可以另定义为“注册表配置项”类型。
- 密钥操作日志证明发生过密钥操作，不代表已经枚举出全部密钥。密钥对象设计仅要求身份与元数据，不要求读取私钥内容。

### 3.2 哪些信息不是对象

| 信息 | 归属 |
| --- | --- |
| 某次 CPU 使用率 | 进程或机器的采样状态 |
| 下次任务执行时间 | 任务的状态字段 |
| 一条 Windows 事件 | 证据，可支撑一个或多个动作或状态事实 |
| Windows Update 历史记录 | 更新动作的证据，不直接等同于当前仍安装的组件 |
| 某次 Defender 检测记录 | 检测动作与结果的证据 |
| 日志通道不可读 | 采集状态 |
| “采集插件已关闭” | 监控配置变化，不等于被监控对象关闭或删除 |

## 4. 对象身份与生命周期

### 4.1 身份字段

| 字段 | 用途 |
| --- | --- |
| `object_id` | PCScope 内部不变标识，不使用显示名称代替 |
| `machine_id` | 机器身份；系统重装或数据库迁移时需有明确的沿用规则 |
| `installation_id` | 区分系统安装实例，不能仅凭相同机器名称跨安装合并 |
| `type_id` | 稳定的对象类型 ID，例如 `startup.scheduled_task` |
| `scope` | 机器、用户 SID、证书存储区、注册表视图等身份相关作用域 |
| `native_key` | 来源系统提供的标识或类型规定的组合标识 |
| `incarnation` | 同一原生标识在删除后重建或被复用时的实例区分 |
| `display_name` | 用户可读名称，可以变化，不参与通用合并判断 |
| `identity_status` | 已确定、暂定、存在歧义 |

每个类型自行定义规范化规则。只有明确符合 Windows 对应标识规则的字段才进行大小写、路径分隔符等规范化，不对所有字符串统一小写或随意裁剪。

### 4.2 类型身份示例

| 类型 | 身份依据 | 注意事项 |
| --- | --- | --- |
| 用户 | 安装作用域与账户 SID | 同名不同 SID 不合并；改名不应变成新用户 |
| 计划任务 | 安装作用域与完整任务路径，再结合生命周期证据 | 路径相同不保证删除重建前后是同一实例 |
| 服务 | 安装作用域与服务名称，再结合生命周期证据 | 显示名称可能变化或重复 |
| 进程 | 安装/启动作用域、PID、进程创建时间 | 只有 PID 不足以唯一识别 |
| 文件 | 可用时使用卷身份与文件 ID，并处理身份复用 | 路径可变；仅有路径时标记身份能力受限 |
| 证书登记 | 存储区作用域与证书指纹 | 同一证书在不同存储区的登记可分别存在 |
| COM 注册 | 用户/机器作用域、32/64 位视图与 CLSID | 同一 CLSID 的不同注册位置不能无条件合并 |
| 软件安装登记 | 登记作用域、注册表视图与原生登记键 | 同名软件不一定是同一个安装登记 |

### 4.3 生命周期规则

- `first_observed_at` 是 PCScope 首次观察时间，不是对象创建时间。
- `created_at` 只有来源明确提供或有创建证据时填写，否则为空。
- `last_observed_at` 表示最后一次真实观察，停用采集后不继续更新。
- 单次未返回对象不自动解释为删除：必须检查采集是否成功、范围是否完整、过滤是否改变。
- 完整且可比较的快照中缺失，可标记“本次未发现”；只有类型定义的可靠证据才升级为“确认删除”或“确认结束”。
- 删除后重建且证据充分时生成新实例；证据不足时保留“生命周期不确定”，不编造创建时间。
- 旧日志回补可以补充历史，但不能直接把较早状态覆盖为当前状态。

## 5. 属性和状态

属性描述对象的身份、结构和配置；状态描述对象某次观察时的运行情况。两者统一保留历史事实，但在界面分组显示。

以任务为例，执行命令、运行账户、触发条件属于配置属性；是否正在运行、下次运行时间、最近执行结果属于状态。是否启用属于配置开关，可以在状态摘要中突出显示。

每个字段至少支持：

| 字段 | 含义 |
| --- | --- |
| `field_id` / `label` | 稳定字段 ID 与中文名称 |
| `value` / `value_type` | 值及类型，保留数字、布尔、时间、列表等语义 |
| `value_status` | 已知、来源未提供、无法读取、不适用、存在冲突 |
| `source_time` | 来源明确提供的状态时间，可为空 |
| `observed_at` | 实际采集观察时间 |
| `evidence_ids` | 支撑这一字段值的证据引用 |
| `derivation` | 来源直接提供、解码解释、快照比较、其他明确规则 |

“最近状态”采用类型及字段规则选择。优先考虑事实时间、来源能力与采集范围，不能简单使用最后入库的一条记录。

同一字段有无法消解的不同值时，显示冲突标记及各来源时间，保留原始候选值。来源较旧导致的正常差异应展示为历史版本，不误报冲突。

敏感字段延续现有加密保存与显示遮罩策略。人类解释、原始数据和复制功能都遵守当前显示设置，不通过摘要绕过遮罩。

## 6. 发生的动作

动作是对象发生的具体操作或变化，不是所有字段差异的通用别名。

| 动作性质 | 示例 | 展示规则 |
| --- | --- | --- |
| 来源明确记录的动作 | 创建任务、删除密钥、进程启动 | 使用相应事件语义，引用证据 |
| 快照观察到的配置变化 | 任务执行命令从 A 变为 B | 写“观察到执行命令变化”，时间为观察区间 |
| 运行状态变化 | 任务下次运行时间更新、服务由停止变为运行 | 写具体状态变化，不自动推断人工修改 |
| 结果记录 | 任务执行成功、应用包部署失败 | 区分开始、结束和结果，不把开始事件当作成功 |

动作记录包含 `action_id`、`object_id`、稳定动作类型、标题、结果、变化前后值、发生时间或时间区间、观察时间、执行身份和程序字段（来源存在时）、证据引用。

执行身份与程序只展示证据支持的信息：来源写入进程不能自动当作操作发起进程；账户身份不等于本人手动操作。缺失字段显示“来源未提供”，解释重点仍是实际动作、目标和结果，避免重复无助于理解的通用声明。

### 6.1 动作归并与去重

- 相同源记录重复读取：按来源记录身份幂等处理。
- Windows 日志证据身份需考虑机器、通道、日志代际与记录 ID；不能仅依赖可能在清空后复用的记录 ID。
- 不同来源记录同一次动作：只有对象身份与来源关联标识或明确规则足够时才归并，并保留全部证据。
- 仅凭时间接近、标题相同或同一 PID，不合并动作。
- 无法确定时保留独立记录，允许以后补充归并依据。
- 事件包含多个不同阶段时，保留阶段语义；可以在未来组合展示，不能误去重成一条成功事件。

## 7. 证据和来源

### 7.1 两者的区别

**来源**描述信息从哪里来、如何读取，例如任务 API、Security 日志、某个注册表位置。

**证据**是某次具体取得的材料，例如某次任务 API 返回、某条审计事件、某次注册表读取结果、两次快照的引用。

一个对象可以有多个来源；一个来源可以产生多份证据；同一证据可以支持多个字段或动作。证据可以先保存，再等待确认其对应对象。

### 7.2 来源元数据

来源保存 `source_id`、插件与采集项 ID、来源类型（API/CIM/COM、日志、注册表、文件、命令接口等）、接口或渠道名称、作用域、读取方式、权限要求和覆盖限制。

对象类型与来源是独立维度：一个插件能采多个类型，一个类型也能由多个插件补充。展示分类不继续依赖插件名称。

### 7.3 证据元数据

证据保存 `evidence_id`、来源引用、原生记录标识、采集批次、源时间、观察时间、入库时间、原始结构及可用的摘要校验值、解析版本、读取问题和保留情况。

摘要校验值用于核对保留内容，不单独证明来源绝对真实或整个历史没有缺失。

解释与原始数据分开保存或生成。解释规则升级不修改原始证据；重新解析需记录规则版本。

### 7.4 多来源汇总示例

| 来源与证据 | 支持的结论 | 不能单独证明的内容 |
| --- | --- | --- |
| 任务 API，10:00 读取 | 当时任务命令是 A，任务已启用 | 谁在什么时候设置了 A |
| 任务修改审计，10:03 发生 | 来源记录了一次修改及其中提供的身份、任务内容 | 操作者是否亲自点击界面 |
| 任务 API，10:05 读取 | 当时任务命令是 B | 没有审计时，不能把变化精确定位到 10:03 |
| 任务运行日志，10:10 发生 | 来源记录了任务执行及其阶段或结果 | 任务全部配置是否在该时刻都未变化 |

如果审计缺失，A → B 显示“10:00 至 10:05 之间观察到变化”。如果可靠审计可定位具体修改，则将对应证据归入该动作，同时保留前后观察。

## 8. 采集状态

采集状态描述 **PCScope 对对象的观察能力**，必须与对象本身的运行状态分开。

| 维度 | 示例 |
| --- | --- |
| 监控配置 | 已启用、插件关闭、采集项关闭、不在监控范围 |
| 最近读取结果 | 成功、部分成功、权限不足、来源不存在、读取失败、从未尝试 |
| 新鲜度 | 最近成功观察时间、当前距该时间多久、按采集计划是否过期 |
| 历史覆盖 | 正在补采、已追到现存日志末尾、源日志缺失、PCScope 历史已清理 |

以上维度分别记录，不压缩成一个容易误导的“正常/异常”。事件驱动来源没有新事件不等于失去采集能力，应参考订阅或读取状态。

采集状态首先记录在来源、采集项和作用域上，再汇总到对象；不能因为某个日志通道失败，就断言该对象所有属性都不可用。

示例：

> 任务状态：已启用。最近配置观察：14:30。
>
> 采集状态：配置读取正常；任务运行日志可读；修改审计不可读。可以查看最近配置和已采执行记录，修改发起者信息可能缺失。

停用采集后保留最后状态并标注“已暂停监控”，不产生对象删除动作。恢复采集产生跨越缺口的变化时，要保留观察区间，不能填补不存在的历史。

状态未变化时不反复插入采集缺口记录；状态首次异常、性质改变及恢复时记录转换，延续现有采集缺口去重原则。

## 9. 完整对象示例

以下内容为说明模型而构造的示例，不是本机 MapsUpdateTask 的真实配置或历史。

```text
类别：自动执行入口
类型：计划任务
对象：MapsUpdateTask
路径：\Microsoft\Windows\Maps\MapsUpdateTask
身份：当前机器安装实例 + 完整任务路径 + 生命周期实例

属性和状态
  执行命令：示例程序 B
  运行账户：示例账户
  是否启用：是
  下次运行时间：18:00
  最近观察时间：10:05

动作历史
  10:00–10:05  观察到执行命令变化：示例程序 A → 示例程序 B
                证据：两次完整任务配置读取
  10:10         任务开始执行
                证据：任务运行日志中的开始记录
  10:11         任务执行结束，来源报告成功
                证据：任务运行日志中的结束记录

证据和来源
  任务配置接口：10:00、10:05 两份读取证据
  任务运行日志：10:10、10:11 两条事件证据

采集状态
  配置：已启用，最近读取成功
  运行日志：已启用，已追到现存日志末尾
  修改审计：不可读
```

如果以后补采到可确认的修改审计，可以补充动作的发生时间及执行身份，并保留原来的两份快照证据。不得为了补充解释而修改原始快照。

## 10. 界面组织

### 10.1 系统对象列表

筛选顺序为类别、类型、对象搜索，再提供作用域、对象状态、采集状态筛选。默认展示当前仍被观察到的对象；历史对象和未确认消失对象可通过明确筛选查看。

列表建议显示：对象名称、对象类型、关键状态摘要、作用域、最近观察时间、采集状态。摘要字段由类型模板定义，不把全部原始字段铺进列表。

类别和类型计数按归一后的对象实例统计；证据条数和事件条数另外展示，不能混为对象数量。

### 10.2 当前行展开详情

保持当前行展开的交互。一级页签沿用“易读说明 / 原始数据”，原始数据保留复制按钮。

易读说明内组织为四个分区：

1. 属性和状态：先展示关键字段，再展开全部字段。
2. 动作历史：围绕当前对象过滤，前后值左右并排，差异高亮。
3. 证据和来源：列出支持当前内容的具体材料，可跳转原始证据。
4. 采集状态：显示各来源最近结果、时间、缺口与暂停情况。

字段旁的来源入口可以直接定位到支撑该值的证据。原始数据区必须标明当前显示的是对象归一结果还是某份源证据，不能把归一结果称作未经处理的来源原文。

### 10.3 全局时间线

时间线动作与系统对象使用同一类别、类型和实例名称。插件、采集项与日志渠道保留为来源筛选，不再充当对象分类。

不能定位到对象的事件仍可展示：标记“对象尚未确定”，保留动作解释与来源。不要使用 `通道/提供者/事件ID` 这类事件类型键冒充真实对象实例。

采集缺口与后台维护等记录作为采集活动显示，不强行归入真实系统对象类型。自身活动过滤继续适用。

## 11. 建议的数据组织

以下为逻辑实体，不要求直接按同名表实现；应结合现有 SQLite 结构与查询性能迁移。

| 逻辑实体 | 责任 |
| --- | --- |
| 类别与类型目录 | 稳定 ID、中文名称、身份规则、关键字段、动作模板 |
| 对象实例 | 机器、作用域、原生身份、生命周期、首次与最后观察 |
| 来源目录 | 插件、采集项、接口、渠道、能力与范围 |
| 证据 | 原始材料、源记录身份、时间、解析版本与读取问题 |
| 对象事实/观察版本 | 字段值、状态、时间和支撑证据 |
| 对象动作 | 动作语义、结果、前后变化及时间精度 |
| 事实/动作证据引用 | 支持一对多、多对多，不把原始大字段复制到每个对象 |
| 采集覆盖状态 | 来源与作用域的可用性、新鲜度和覆盖区间 |
| 当前展示投影 | 可重建的对象列表摘要、最新字段与搜索索引 |

对象归一规则与采集插件解耦，由类型适配规则将来源记录映射到对象候选身份、字段和动作。无法识别时保留原始证据及未归属状态，不丢弃记录。

“同一对象的多份证据引用”属于本阶段；“两个不同对象之间的语义关系”属于下一阶段。

## 12. 保留策略与现有开关兼容

- 默认总历史容量沿用 5 GB，滚动删除最旧数据；用户可以选择无限增长。
- 证据引用必须能区分“来源从未提供”“因权限未采到”“曾经采到但已按保留策略清理”。
- 证据清理后，不保留无法解释的悬空引用。当前状态如果仍被保留，应有最小来源与观察元数据，并明确完整历史证据已清理。
- 当前对象摘要、证据元数据和新索引也计入存储预算，不能以“当前状态”名义无限增长。
- 单项开关、文件空白默认名单、隐私显示和自身活动过滤均沿用现有用户配置。
- 关闭事件子项期间跳过的数据，是否能回补继续遵循现有断点规则；界面不能宣称恢复开关就恢复了完整历史。
- 对象投影重建不得触发新的“系统发生变化”事件；解析版本升级与真实对象变化分开记录。

## 13. 实施顺序

1. 建立类别与类型目录，把现有采集项映射为对象类型、字段来源、动作证据或采集状态；标出未映射项。
2. 首先打通计划任务：配置来源、运行日志、修改审计统一到实例，验证时间与身份规则。
3. 扩展到用户、服务、进程和指定文件，覆盖改名、删除重建、PID 复用、暂停采集等边界。
4. 改造系统对象与时间线筛选和详情，保留旧记录兼容入口及来源检索。
5. 分批重建保留历史的对象投影，记录规则版本与进度，验证计数、性能和保留策略。
6. 再扩展其他对象类型；类型支持程度明确显示，不把泛化兜底当成已完成的对象语义。

## 14. 验收标准

- 一个任务被多个来源观察时只显示一个可确认实例，各来源证据均可追溯。
- 同名不同作用域对象不误合并；进程 PID 复用不会把两次进程生命周期拼接。
- 首次观察不冒充创建，未观察到不冒充删除，日志开始不冒充成功。
- 快照变化显示正确时间区间；旧日志回补不会覆盖较新的当前状态。
- 每项关键字段和动作可以定位其证据；缺失、冲突和历史清理有明确标识。
- 任务下次运行时间变化不会直接被解释为人工修改任务。
- 停用单项采集保留旧状态并显示暂停，不制造对象删除或虚假最新时间。
- 目录、列表、详情和时间线使用一致的类别与类型名称；来源仍能单独检索。
- 对象未确定的事件保留可读解释和原始材料，不创建虚假的系统对象。
- 黑白主题、直角风格、当前行展开、原始数据复制和差异并排阅读继续可用。
